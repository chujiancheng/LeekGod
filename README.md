# 股神请就位 · 韭菜进化论

> 一个能单机跑起来的 A 股模拟交易游戏。内部代号「我是股神」（目录名、存档名、测试用例里的 `gushen` 都不改）。

免密登录 → 开户（起昵称 + 选券商）→ 在 **10 只股票**上做多/做空，和 **3160 个 NPC** 共用同一本订单簿；行情由服务端做市引擎驱动，有消息、有内幕、有涨跌停、有集合竞价、有收盘结算和隔夜跳空。一天 620 秒，收盘后给你算账，顺便发彩蛋。

- **纯 H5 前端**（无构建、无框架）+ **Node.js 原生 http 服务**（REST 写操作 + SSE 推送）
- **SQLite 存档**：停服重启接着上一局玩，账号 / 持仓 / 挂单 / 流水 / 行情断点都在
- **零外部依赖**：不需要数据库、Redis、WebSocket 服务；Node 依赖只有 `log4js` + `better-sqlite3`

## 快速开始

**环境要求**：Node.js 22+（`better-sqlite3` 13 的 engines 要求）、Python 3.8+（仅用于进程管理）

```bash
cd Server
npm install          # 首次运行必装，否则会报模块找不到
python server.py start
```

打开 <http://127.0.0.1:3000>，输入任意合规账号（3~16 位、字母开头）即可开始。

```bash
python server.py status     # 看是否在跑
python server.py stop       # 停服
python server.py restart    # 重启（改配置后必须执行）
python server.py halt       # 全市场停牌 5 分钟
python server.py resume     # 复牌
```

换端口：`PORT=3100 python server.py start`（PowerShell：`$env:PORT=3100; python server.py start`）。

> 配置在进程启动时只读一次，**改完必须重启**。

### 交易规则（默认值，全在 `Server/src/config.js`）

| 规则 | 默认 |
|---|---|
| 初始资金 | 100 万元（加钱入口目前关闭） |
| 手续费 | 万分之一 |
| 下单冷却 | 同账号 2 秒，跨股票共享 |
| 买入锁仓 | T+10 秒（改成按分钟也很容易） |
| 做空 | 冻结市值 50%，维持率 30% 爆仓；必须从该股融券池借券，不允许裸空 |
| 同股多空互斥 | 同一账户在同一只股票上只能持一个方向 |
| 涨跌停 | ±30%（相对昨收） |
| 一手 | 100 股 |
| 停牌 | 全市场一起停，默认 5 分钟，上限 120 分钟 |

### 有「天」

一天 **620 秒**（10 分 20 秒），切 6 段，段与段之间规则完全不同：

| 游戏内时刻 | 阶段 | 时长 | 能做什么 |
|---|---|---|---|
| 09:15 | 开盘集合竞价 | 30s | 只入簿不成交；最后 10 秒锁死撤单 |
| 09:30 | 上午连续竞价 | 230s | 正常撮合 |
| 11:30 | 午间休市 | 40s | 价格冻结、不能下单，消息照跑 |
| 13:00 | 下午连续竞价 | 260s | 正常撮合 |
| 14:57 | 收盘集合竞价 | 20s | 最大成交量原则集中撮合，最后 10 秒锁死 |
| 15:00 | 夜间结算 | 40s | 收盘价结算、委托作废、算彩蛋 |

收盘会滚昨收、定格日线、清当日量额、撤销当日委托；下一个交易日开盘价可能**跳空**——休市期间公允价值继续迁移，这是隔夜跳空的全部来源。停服跨过的收盘日会在下次启动后补结算。

### 券商（出生门派）

开户时从六家里选一家，它把你的交易参数改成 per-broker：佣金、冷却、锁仓、做空保证金、融资额度、券源、策略条数、消息提前量、强平缓冲、禁买名单……没有更优的通用解，只有风格差异。

**钟信证券 / 滑泰证券 / 招伤证券 / 天疯证券 / 嗨通证券 / 东风财富**

- **声誉星级**：按本券商累计成交额 + 累计盈利 + 有无爆仓记录评级；1★ 到 5★ 逐级解锁"比基准更好"的特权，而"比基准更差"的代价一开始就全量生效。
- **每周之星**：按交易日号轮转，当周一家享受佣金减半 + 融资额度加成。
- **转户**：首日免费，之后有冷却与费用，两家进度都清零。
- **东风人气**：东风客户的成交额会推高该股热度，放大散户 NPC 的跟风系数。

### 消息是有层级的

一条消息的"诞生"不等于"公开"：中间是泄露期，按接收者等级给提前量——**L0 内幕 6 秒 / L1 机构 4 秒 / L2 情报玩家 3 秒 / L3 公众 0 秒**。券商星级决定你能拿到多少提前量；未满 4★ 时只看得到"哪只股票有消息"，看不到方向。泄露期的消息绝不会出现在公众行情和成交流水里。

### 其他

- **自动化策略**：止盈止损（TPS）、网格、均线（MA）、定投（DCA），按股票绑定，服务端逐 tick 执行。
- **融资融券**：融资自备 50%（最高 2 倍）；融券池每股一套，出借人是不做空的被动持有者，日息 0.1%~0.4%。
- **彩蛋（里程碑）**：收盘结算时按权益水位、回撤、风险度、首次爆仓判定，发称号与横幅；三档文案基调（吐槽 / 温和 / 冷面），权益跌破 10 万自动切温和。
- **排行榜 / 股东榜 / 资金流向 / 日线周线月线 K 线 / MACD**，涨红跌绿。
- **股娘图鉴**：每只股票一份拟人档案（`Client/lore.js`），纯前端数据，服务端不感知。

## 开放平台（用代码交易）

游戏内提供一套独立的**量化交易接口**，和网页会话令牌完全隔离：

1. 登录游戏 → 主页「开放接口」→ `/portal.html` 自助生成 API Key（明文只显示一次，库里只存 sha256）。
2. 阅读文档：`/docs.html?doc=player`（入门）、`/docs.html?doc=api`（完整手册）。
3. 跑示例：`Server/examples/quant_ma.py`（双均线）、`quant_template.py`（带对账/风控的长期运行骨架）、`quant_rotation.py`（多股票动量轮动）。

运维代管（锁 IP、帮查、被盗撤销）：

```bash
cd Server
python openkey.py issue <账号> --label 备注 --ip 127.0.0.1
python openkey.py list [账号]
python openkey.py revoke <KeyID>
```

接口规格与逐字段说明见 [`Doc/开放平台API.md`](Doc/开放平台API.md)。

## 开发与测试

服务端测试是自研轻量断言，不依赖 jest/node:test：

```bash
cd Server
npm test                          # 撮合 / 整局 / 存档 / 多股票 / 流向 / 券商 / 彩蛋 / LLM / 开放接口 / 门户
node test/auto.test.js            # 自动化策略（不在 npm test 里）
node test/day.test.js             # 交易日机制（用真实配置：涨跌停开着、竞价真实毫秒）
node ../Client/test/client-day.test.js   # 前端自检（把 app.js 真跑一遍）
```

当前回归基线约 **1900** 条断言（前端自检 500+ 条），改撮合 / 行情 / 持久化后请全跑一遍。

改行情参数、交易日节奏、券商数值前，先跑对应探针（纯内存，不碰正式存档）：

```bash
node test/npc-probe.js      # NPC 行为：意图/力量天平/买盘空档率/强平次数
node test/day-probe.js      # 日收益分布/贴板占比/跳空/日内量能形状
node test/broker-probe.js   # 券商支配性/等价换算/爆仓概率
node test/diag-bid-depth.js # 买盘深度与空段诊断
```

## 存档与日志

| 路径 | 说明 |
|---|---|
| `Server/data/game.db` | 正式存档（SQLite + WAL，不入库） |
| `Server/data/admin.token` | 运维口令，首次启动自动生成 |
| `Server/log/server.YYYY-MM-DD.log` | 业务日志，按天切割，保留 30 天 |
| `Server/log/server-console.log` | 仅承接 logger 初始化前的崩溃输出 |

**开新一局**：停服 → 删掉 `Server/data/game.db`（连同 `-wal` / `-shm`）→ 启动。

**验收 / 调试不要污染正式存档**，用临时库：

```bash
# PowerShell
$env:PERSIST_FILE="$env:TEMP\gushen-verify.db"; python server.py start
# bash
PERSIST_FILE=/tmp/gushen-verify.db python server.py start
```

要点：服务运行中直接改 `game.db` 没用（内存会写回）；登录按账号建号，验收账号会在浏览器 `localStorage` 留下 `gushen_name` / token，清理时要连本地存储一起清。
