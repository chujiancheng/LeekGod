## 1. 项目概述

单机可玩的**炒股模拟游戏**（「我是股神」）：玩家免密登录后，在一只模拟股上做多/做空，与 NPC 共用订单簿撮合；行情由服务端 NPC 做市引擎驱动（趋势阶段 + 消息 + 动量），支持融资/融券、爆仓强平、自动化策略、排行榜。

- **技术形态**：纯 H5 前端（无构建）+ Node.js 原生 http 服务端，REST 写操作 + SSE 推送，SQLite 存档。
- **无外部数据库 / 无 WebSocket / 无前端框架**。依赖仅 `log4js` + `better-sqlite3`。
- 默认监听 `0.0.0.0:3000`（`PORT` 环境变量覆盖）。

```
浏览器 Client（H5）
   │  POST /api/*（Bearer token）        GET /api/events（SSE，每 700ms 一帧 state）
   ▼
Server/index.js ── createServer(game) → src/http.js
   │                      │ 静态托管 Client/{index.html,app.js,style.css}
   │                      └ SSE Hub：每 tick 广播完整 state（市场共享段 + 按 token 拼账户段）
   └─ Game（src/game.js）主循环 700ms/tick
         ├ news.maybeEmit   随机利多/利空（20~60s 一条）
         ├ npc.step          公允价值/趋势 → 报价 + 主动吃单  ← 价格在这里产生
         ├ market 撮合       订单簿成交、结算、强平扫描
         ├ auto.step         玩家自动化策略（止盈止损/网格/均线/定投）
         ├ 融券/融资利息按 tick 计提
         ├ SSE broadcast
         └ persist.commit    每 tick 一个 SQLite 事务
```

**价格从哪来**：`npc.js` 维护共享公允价值 `fairValue`（趋势段随机推力 + 消息推力 + 噪声 + 向最新价/重心回归）→ NPC 据此挂双边限价单并主动吃单 → `market.js` 撮合，**成交价 = 被动方挂单价**，更新 `lastPrice`。market 不生成价格，只做撮合与风控。

**权益公式**（做空口径，非期货模型）：`equity = 现金 + 挂单冻结 + 空头保证金 + 多头市值 − 空头市值`（±挂借/融资负债利息挂账）。爆仓条件 `equity < maintenance × 空头市值`（多头融资侧镜像）。

**NPC 五类**（`npc.types`，holdRatio 合计=1，开服按比例瓜分全部流通盘+现金）：

| 类 | 数量 | 持仓占比 | 现金 | 特性 |
|---|---|---|---|---|
| 机构 inst | 10 | 32% | 2.2 亿 | **聪明钱**：公开消息对倒（利好出货/利空吸筹）、定价锚以基本面 `fund` 为主（`fundWeight: 0.7`）、过热/超跌回归、库存软目标；可做空、固定多空阵营、分歧度两态 |
| 游资 hot | 6 | 8% | 4500 万 | 动量 ×1.6、主动率 0.35、轻度过热回避 |
| 大户 big | 20 | 18% | 4500 万 | 动量 ×1.15，不做空，轻度过热回避 |
| 中户 mid | 60 | 25% | 3000 万 | 动量 ×1.2 |
| 散户 small | 220 | 17% | 1500 万 | 动量 ×1.25、跟消息追涨杀跌 |

**行情模型（趋势阶段，2026-10 起）**：大级别由「趋势阶段」驱动——时长指数分布（均值 260 tick，无记忆）、方向每次 50/50 抽签、幅度三档混合（温和 62% / 强 30% / 极端 8%，极端段可数倍或腰斩）。公允价值对数空间推进，安全边界 0.05×~20× 只是保险丝、不做触轨反转偏置。报价中枢 = `quoteLastWeight`×最新价 + (1−w)×定价锚，硬夹最新价 ±3%（保证盘口始终可成交）；挂单深度随情绪倾斜（`quoteTilt`）。**`fairValue`/`fund`/`regime` 绝不能下发客户端。**

**消息**：20~60s 一条，作用 60s；scope 分 机构/散户/全体；**文案按 scope 分池**（`news.js` 的 `TEMPLATES`：全体 = 政策/宏观/大盘、机构 = 研报/调研/大宗/席位、散户 = 股吧/小道/情绪，每池 12 条利好 + 12 条利空，共 72 条）。抽取顺序是「先定 scope，再从该池按方向取文案」，所以盘面不会出现「机构」scope 却播宏观政策这类错配；池内**最近 12 条消息用过的文案不重复抽取**（`REPEAT_GUARD`，全用完才退回纯随机）。文案不影响 `power`/`until`/情绪权重——仍是随机 0.3~0.8、60s 衰减。双通道作用——情绪（偏移报价中枢、触发吃单、挂单量倾斜）+ 直接乘性推公允价值（`fvDriftCoef: 0.0015`）；方向随牛熊阶段 70/30 偏置（`regimeBias: 0.2`）。**群体反应不对称**：散户/游资/大户跟消息同向追涨杀跌；机构 `sentimentByScope` 看见公开消息（全体+散户盘）后**对倒**——公开利好出货、公开利空吸筹，机构专属消息仍小幅同向（`publicNewsFade` / `instNewsFollow`）。

**自动化策略（auto.js）**：玩家自设、服务端每 tick 代执行（下线也跑），走 `market.place` 正常下单无后门。四类：止盈止损 / 网格（间距 0.3%~20%、≤50 格）/ 双均线 / 定投（间隔 ≥5s）。单账户 ≤20 个（含已完成）。

## 4. 服务端模块（`Server/src/`）

| 文件 | 职责 | 关键导出 |
|---|---|---|
| `config.js` | 全局配置单例，环境变量：`PORT`/`LOG_LEVEL`/`PERSIST`/`PERSIST_FILE`/`ADMIN_TOKEN_FILE` | `module.exports` |
| `logger.js` | log4js **仅 stdout** appender；落盘/轮转归 server.py。禁止 console.*（test/ 除外） | `logger`, `getLogger` |
| `db.js` | SQLite 连接（WAL + synchronous=NORMAL）、DDL、旧档补列迁移、`SCHEMA_VERSION` 校验 | `openDatabase` |
| `store.js` | 内存账户模型：现金/冻结/保证金/多空批次 lots（FIFO）、权益计算 | `Account`, `Store` |
| `orderbook.js` | 限价簿，价格优先时间优先，五档聚合 | `OrderBook` |
| `market.js` | **撮合与风控**：place 校验（停牌/整手/冷却/偏离/笼子）、match/execute/结算、融券池与融资利息、强平（含 SYSTEM 兜底）、停牌 | `Market`, `ACTIONS` |
| `npc.js` | **做市引擎**：公允价值/趋势/机构分歧度/动量情绪、机构聪明钱（消息对倒/过热/库存）、重报价、主动吃单、流动性回收（地板 4200 万） | `NpcManager` |
| `news.js` | 随机消息系统；按 scope 分池的文案库（各 12+12 条，池内近 12 条去重）；`sentiment` / `sentimentByScope` / `fvDrift` | `NewsSystem` |
| `auto.js` | 玩家自动化策略 | `AutoManager` |
| `game.js` | **门面 + 主循环**：tick 编排、login/order/cancel/lend/auto/deposit/halt 玩家 API、stateFor 快照、排行榜、前十大股东与股东操作快照 | `Game` |
| `persist.js` | 落盘：脏标记 → 每 tick 一个事务 commit；300 tick 全量 sweep 兜底；NPC 报价单不落盘 | `Persister` |
| `http.js` | 原生 http：静态托管、CSP、限流、guardWrite（同源+JSON）、SSE Hub、全部路由 | `createServer` |
| `admin.js` | 运维口令：env→`data/admin.token`→生成；timingSafeEqual 校验 | `loadToken`, `authorized` |

**tick 顺序**（`game.js tick()`）：停牌过期 → news → npc.step → 全账户 maybeLiquidate → auto.step → 融券/融资利息（摊息的同时累加展示用的 `lendInterestPaid` / `financeInterestAccrued`）→ 空头 5min 采样 → 分时入列 → refreshStats → SSE 广播 → persist.commit。

**股东快照不在 tick 里**：它跟着玩家写操作走（`login`/`order`/`cancel`/`lend`/`unlend` 成功后各记一份），所以「较上次操作」的基线只随玩家动手而移动，不会被每 700ms 的 tick 冲掉。

**持久化要点**（改资金/持仓路径必读）：
- 任何改钱/持仓的路径必须 `journal.touch(account)` / `orderChanged(order)` 落脏标，漏标只能靠 300 tick sweep 兜底。
- NPC 报价单**不落盘**（写 NPC 账户时退回冻结、reserved 归零），重启由 `npc.step()` 重报；落盘会产生撤不掉的幽灵单。
- 恢复走 `game.applySnapshot()`；**绝不能调 `npc.init()`**（那是新局建仓）。`fairValue`/`fund`/机构情绪态不落盘，重启重锚。
- 强平前必须撤该账户全部平仓挂单；结算按**实际成交量**入账（账实一致不变量，详见 MEMORY）。
- Windows 下 `server.py stop` 是 `taskkill /F`，**SIGTERM 钩子不会执行**——退出时不做落盘，全靠按 tick 增量写。

## 5. HTTP API（`http.js`）

写接口要求 `Content-Type: application/json` + 同源 Origin + IP 限流；身份只认 **token**（`Authorization: Bearer`，SSE 用 `?token=`）。请求体里的 `name` 不是身份来源。

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/login` | `{name}` 按名字建号/登录（同名复用、不独占），返回 token |
| GET | `/api/state` | 完整快照（含 priceHistory） |
| GET | `/api/holders/history` | 本账户最近若干次操作时的前十大股东快照（查「较上次操作」变动与占比走势，仅内存） |
| POST | `/api/order` | `{action, qty, price, finance}`；action ∈ buy_open / sell_close / sell_open / buy_close |
| POST | `/api/cancel` | `{orderId}` |
| POST | `/api/auto` | `{op: create/update/remove, ...}` 策略 |
| POST | `/api/lend` | `{op: lend/unlend, qty}` 融券挂借/撤借 |
| POST | `/api/deposit` | `{amount}` 加钱（受终身上限；`deposit.enabled=false` 时返回"加钱功能未开放"） |
| GET | `/api/events` | SSE，`event: state` 每 tick 一帧；15s 心跳；token 失效客户端自动重登 |
| POST | `/api/admin/halt` | `{minutes, reason}` 停牌，头 `X-Admin-Token` |
| POST | `/api/admin/resume` | 复牌 |
| GET | `/` `/index.html` `/app.js` `/style.css` | 静态客户端 |

每账户最多保留 5 个会话令牌（`MAX_SESSIONS_PER_ACCOUNT`）。

## 6. 数据库表（DDL 全在 `db.js`）

`meta(key,value)` · `accounts(name PK, is_npc, role, cash, order_frozen, short_margin, realized_pnl, initial_long, last_order_at, created_at, deposited, lend_offered, lend_interest_earned, lend_interest_debt, lend_interest_paid, finance_interest_accrued)` · `lots(account,stock_id,side,seq,qty,price,ts,reserved,margin,debt,principal)` · `orders(id PK, account, ..., status)` · `trades(...)` · `sessions(token PK, account)` · `market_state(stock_id PK, last_price, prev_close, ..., short_interest, ...)` · `prices(t PK, price, vol)` · `auto_strategies(...)`。

`lots.principal` = 融资批次借入的本金（含开仓手续费），开仓时写入一次、**只随平仓按比例减少**（`consumeLong` 里与 `debt` 同比例扣）；`debt − principal` 就是这批已计但未还的利息。`debt` 参与权益计算，`principal` 纯展示。

`accounts` 里四个利息字段分工：`lend_interest_debt`（做空欠息）**参与权益计算**（是负债）；`lend_interest_earned` / `lend_interest_paid`（出借累计收入 / 做空累计已付）与 `finance_interest_accrued`（融资累计已计利息）都**只做展示**——钱早已在逐 tick 的现金流/负债里走完账，三者不重复扣减权益。恒等关系：做空累计产生额 = `lend_interest_paid` + `lend_interest_debt`。

schema 版本存 `meta.schema_version`，不匹配直接拒绝启动。后加的列走 `openDatabase` 里的纯增量 `ALTER TABLE` 迁移（`deposited`、`lend_*`、`lend_interest_paid`、`finance_interest_accrued`、`lots.principal`），不加 `schema_version`，旧局可直接续跑。其中 `lots.principal` 补列后要跑一次 `backfillLotPrincipal()`：旧档没记批次本金，只能按「利息按批次负债占比摊入」这一事实反推 —— 用 `debt × (1 − 账户累计已计息 / 账户融资总负债)` 近似，一律记 0 会让旧持仓显示成「本金 0、全是利息」。

**股东操作快照不落库**：`_holderSnapshots`（账号名 → 快照数组）纯内存环形缓冲，每账户留最近 `HOLDER_SNAPSHOT_LIMIT=30` 次操作快照，每份记当时持股前 `HOLDER_SNAPSHOT_ROWS=30` 名（含占比），重启清空——所以表结构没变，也不需要迁移。

## 7. 客户端（`Client/`）

- **通信**：无轮询。首屏 `GET /api/state` → `EventSource('/api/events')` 每 700ms 全量重渲染；另 200ms UI 定时器只做倒计时/时钟等本地展示。localStorage 仅 `gushen_name`、`gushen_token`。
- **视图**：主页（行情列表迷你走势/资产/持仓/排行/消息）+ 交易终端（分时三带图：价格+均价/成交量/MACD(12,26,9)、五档、逐笔、下单面板、8 个标签页）。
- **交易操作**：四方向按钮（买开/卖平/卖开/买平）+ 融资勾选 + 撤单 + 挂借/撤借 + 加钱 + 自动化 CRUD。无可借券源时开空按钮禁用。「加钱」按钮跟随 `rules.deposit.enabled` 显隐，当前开关关闭 → 按钮不出现，弹窗入口一并失效。
- **杠杆利息展示**：下单面板分三处——①「杠杆利息」块**常显两行**（做多·融资 / 做空·融券，各显示 `x%/分` + 折算 `≈y%/日`，`minuteRate × 1440`），当前这笔真会借钱/借券时对应行高亮（买入开多且**勾了融资**、或卖出开空），裸空模式显示「裸空不计息」；②「预计利息」行按当前委托数量估算这次开杠杆的成本（`¥/分` + `≈¥/日`），融资按借入口径（`市值×(1−ratio) + 手续费`）、融券按借券市值，都乘当前分钟息——**与服务端逐 tick 摊息的基数同一口径**，不计息时整行隐藏；③融资勾选行的 tag 只留杠杆口径（`自备 50% · 最高2倍`），利率交给杠杆利息块，避免重复数字把标签挤换行。
- **持仓利息（资产区）**：`融资负债`（`financeDebt`，本金+未还利息）拆成 `融资本金`（`financePrincipal`）与 `融资已计息`（`负债 − 本金`）两行，两者之和恒等于融资负债；`融资已计息` 的 tooltip 里给出**累计**口径 `financeInterest`（含平仓时已随批次还掉的）。空头侧是 `做空欠息`（挂账未付，参与权益计算）+ `做空已付息`（累计实付）。再加一行 `持仓利息 x/分` = `融资负债 × 融资分钟息 + 空头市值 × 融券分钟息`。「融券」tab 的我的融券视角同步显示「做空已付息」。
- **股东 tab**：表格两列变动——「较开服变动」相对开服建仓、「较上次操作」相对本账户最近一次操作快照（服务端 `holderSnapshot` 给出时间与次数），都按「占比百分点 + 股数」两行显示；算不出时显示 `--`（还没操作过）或 `新进`（当时未进快照前 30 名）。点任意一行弹窗看该股东的占比走势折线（缺失点断线，不做连续臆测）+ 最近若干次操作流水；弹窗开着时若服务端又记了新快照会自动重拉。
- **安全约定**：CSP 无 `unsafe-inline`——**app.js 严禁内联 `style=` 属性**，样式写 style.css 用 class；服务端字符串插 HTML 前必须过 `esc()`。
- **视觉**：深色终端 `#0b0e14`，涨红跌绿（A 股配色），等宽数字，≤860px 移动端适配。
- **布局坑**：`.main` 必须 `grid-template-rows: minmax(0,1fr)` + overflow hidden，否则画布把行撑爆导致分时图溢出。
