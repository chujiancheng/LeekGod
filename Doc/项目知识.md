## 1. 项目概述

单机可玩的**炒股模拟游戏**（「我是股神」）：玩家免密登录后（**首次登录必须选一家券商**，见 §3.2），在 **10 只股票**上做多/做空，与 NPC 共用订单簿撮合；行情由服务端 NPC 做市引擎驱动（趋势阶段 + 消息 + 动量），另有**大盘指数**（10 只股票按流通市值加权合成，纯展示不可交易），支持融资/融券、爆仓强平、自动化策略、排行榜。**有「天」**——一天 620 秒切 6 段（开盘集合竞价 / 上午 / 午休 / 下午 / 收盘集合竞价 / 夜间结算），有昨收、有收盘价、有隔夜跳空、有涨跌停。

- **技术形态**：纯 H5 前端（无构建）+ Node.js 原生 http 服务端，REST 写操作 + SSE 推送，SQLite 存档。
- **多股票形态**：每只股票一套**完全独立**的做市池（自己的 Market + NpcManager + 316 个 NPC 账户 + 融券池 + 做市资金），彼此行情独立；玩家**一份现金**跨股票共享、持仓按股票分账，风控按**组合口径**（权益与敞口都跨股票汇总）。
- **无外部数据库 / 无 WebSocket / 无前端框架**。依赖仅 `log4js` + `better-sqlite3`。
- 默认监听 `0.0.0.0:3000`（`PORT` 环境变量覆盖）。

```
浏览器 Client（H5）
   │  POST /api/*（Bearer token；下单/融券/策略带 stockId）
   │  GET /api/state（全市场快照）、/api/history?stock=（分时）、/api/holders?stock=（股东）
   │  GET /api/events（SSE，每 700ms 一帧：markets[] + index + 账户段）
   ▼
Server/index.js ── createServer(game) → src/http.js
   │                      │ 静态托管 Client/{index.html,app.js,style.css}
   │                      └ SSE Hub：每 tick 广播完整 state（10 股行情 + 指数 + 按 token 拼账户段）
   └─ Game（src/game.js）主循环 700ms/tick
         ├ 交易日时钟定位（daycycle.js）→ 阶段切换：竞价结束集中撮合 / 收盘结算
         ├ news.maybeEmit   随机消息（大盘 + 个股；节奏按阶段分段：盘前/盘后密集、盘中 20~60s、收盘竞价不发；休市期照发，盘后消息作用到次日竞价结束）
         ├ 逐只股票：npcs.get(id).step  公允价值/趋势 → 报价 + 主动吃单  ← 价格在这里产生
         │                                （休市期只跑 stepFairValue：价格冻结、公允价值继续迁移）
         ├ 逐只股票：market 风控扫描（只扫持有该股敞口的账户；竞价与休市冻结强平）
         ├ 逐只股票：融券/融资利息按股票计提
         ├ auto.step         玩家自动化策略（按策略绑定的股票执行；休市跳过）
         ├ index.update      用各股最新价合成大盘点位
         ├ SSE broadcast
         └ persist.commit    每 tick 一个 SQLite 事务（11 个标的的行情 + 分时）
```

**价格从哪来**：每只股票的 `npc.js` 各自维护 `fairValue`（趋势段随机推力 + 消息推力 + 噪声 + 向最新价/重心回归）→ 该股 NPC 据此挂双边限价单并主动吃单 → `market.js` 撮合，**成交价 = 被动方挂单价**，更新该股 `lastPrice`。market 不生成价格，只做撮合与风控。**时间维度由 `src/daycycle.js` 提供**——一天 620 秒切 6 段，段与段之间发生的事完全不同（见 §3.1）。

**权益公式（组合口径）**：`equity = 现金 + 挂单冻结 + 空头保证金 + Σ各股多头市值 − Σ各股空头市值 − Σ各股融资负债 − Σ各股做空欠息`。
多股票下必须按**整个账户**汇总——现金只有一份，若按单只股票算，每只股票的开仓预检都会各自看到全额现金，敞口会被放大到 10 倍。爆仓条件 `equity < maintenance × 账户总空头市值`（多头融资侧镜像），触发后由持有该敞口的市场强平自己那部分。

**同股多空互斥（港交所口径，2026-10 起）**：同一账户在同一只股票上只能持有一个方向。`Market.place` 在开仓前调 `Account.sideLock(stockId)`，占用判定 = **已成持仓 + 在途开仓委托**：持多头（或有 `buy_open` 在途）拒 `sell_open`，持空头（或有 `sell_open` 在途）拒 `buy_open`；`sell_close`/`buy_close` 与同向加仓照常。**旧档残留的多空并存只许平、不许再开**，平到一侧归零即自然收敛。强平走 `forceSellLong`/`forceCoverShort`，不经 `place`，不受该规则限制。

- **NPC 因此改为「阵营切换」模型**（`NpcManager.updateSide`）：机构/游资在情绪跌破 `openShortSentiment` 时切到**空头阵营**——不再挂买开、把库存往外派发，库存清零后转净空（卖开补卖盘、买盘只回补）；情绪回到阈值以上切回多头阵营。`wantShort` 带 0.08 滞回，避免阈值抖动导致买卖盘反复翻面。不做空的类型永远是多头阵营。
- 没有阵营切换就永远开不出空：只要还押着库存就进不了开空分支，而没有任何力量把库存推到 0（实测 600 tick 空头存量恒为 0）。同理，派发期间**连主动吃单的开多也要压住**（`tryAggressive` 里 `!wantShort`），否则自己的价值抄底会把库存买回三成。
- 做空类**不挂借**（`npc.js init` 里 `lendRatio = 0`，旧档残留由 `syncLend` 逐步撤回）：挂借中的券卖不掉（`freeSellableLong` 扣掉 `lendOffered`），留着就永远翻不了空。融券池的基础券源改由不做空的被动持有者承担（60% 流通盘 × 30% ≈ 18%）。
- 代价（实测对照改动前）：熊段买盘档数会明显变薄——机构是唯一现金充裕的做市方，它转空头阵营时就不再挂买盘，而中户/散户常已把现金买光。600 tick × 10 股的采样里买盘深度均值 110→83~150 档、"买盘空档"时刻 0%→0.4%~4.7%；空头存量峰值仍在同量级（原 340 万/1550 万/679 万 → 现 150 万/1400 万/130 万）。

**行情模型（趋势阶段，2026-10 起；2026-10-16 按「天」重标定幅度）**：大级别由「趋势阶段」驱动——时长指数分布（均值 260 tick，无记忆）、方向每次 50/50 抽签、幅度三档混合（温和 62% / 强 30% / 极端 8%）。公允价值对数空间推进，安全边界 0.05×~20× 只是保险丝、不做触轨反转偏置。报价中枢 = `quoteLastWeight`×最新价 + (1−w)×定价锚，硬夹最新价 ±3%（保证盘口始终可成交）；挂单深度随情绪倾斜（`quoteTilt`）。**`fairValue`/`fund`/`regime` 绝不能下发客户端。**
**`trend.bands` 是「每 tick」的对数漂移**，所以一天的涨跌幅 = 一天的 tick 数 × 它。引入「天」之后一天只有 620 秒 = 886 tick（≈3.4 个趋势段），沿用为「连续无边时间轴」标定的旧幅度会让**日收益中位数就有 ±38%**——涨跌停 ±10% 于是从"熔断器"变成"日内主约束"。幅度标定分两步：2026-10-16 先整体 ÷11（`[0.00003,0.00014]` / `[0.00014,0.0004]` / `[0.0004,0.0008]`，日收益中位 ~3.3% / p90 ~9.2%），同日对照真实行情后发现**仍高出真实一倍**，再 ÷1.7 收口到 **`[0.0000145,0.000068]` / `[0.000068,0.000195]` / `[0.000195,0.00039]`**（三档仍首尾相接，各档单阶段涨幅约 ±0.4~1.8% / ±1.8~5.1% / ±5~10%）。

**真实口径**（2026-10-16 采集：十只原型港股 2024-10-02~2026-10-16 各 503 个交易日，东方财富日线，见文末变更记录里的逐只表）：|日收益| 中位 **1.67%** / p75 3.01% / p90 **4.65%** / p99 10.40% / 最大 29.31%，日收益 **std 3.10%**，**超过 ±10% 的交易日占 1.2%**；年化波动 33.2%（腾讯）~65.7%（中芯）。本轮把日波动标到真实的 **约 1.4~1.7 倍**（`day-probe` 实测日收益中位 2.78% / p90 8.04% / std 4.38%、贴板采样 4.7%）——按用户确认的口径「轻微收敛到真实的约 1.5 倍」，完全对齐真实会让连板几乎不再出现。**再动幅度参数必须先跑 `node test/day-probe.js`**（见 §9）。

**多空力量对比（力量天平，2026-10 起）**：`npc.js updateForce` 把盘面上"真正拿得出来打的"东西合成一个慢变量 `force ∈ [-1,1]`（−1 空头占优 / 0 势均力敌 / +1 多头占优），**算出来的、不是随机贴标签**：情绪合力（机构一致情绪 + 散户情绪）、动量（90 tick 窗口）、弹药（全池现金 / 流通市值）、浮盈亏结构（获利盘是卖压、深套盘是"卖无可卖"的潜在买盘）各自投票，加权归一再以 0.02/tick 平滑成慢波。**空头存量与券源紧张度刻意不进天平**——它们恒为正，算进去会让天平结构性偏多、永远出不来"空头占优"（它们只是逼空的燃料，只在挤兑条件里用）。三处用途：① 情绪同向偏置（`force.bias` 0.2，实测 0.35 会把趋势放大过头、买盘被扫穿的时段翻倍）；② 调制机构分歧度——势均力敌更容易打成放量对攻、一边倒更容易全体一致（`polarBase` 0.35 + `polarBalance` 0.45×(1−|force|)）；③ 三种战术意图的成立前提。实测分布（6 局 × 3000 tick × 10 股）：多头占优 ~18~23% / 多空均衡 ~69~73% / 空头占优 ~8~11%。**与 regime/fairValue 同级敏感，不下发客户端。**

**NPC 战术意图（`npc.js` 意图层，2026-10 起）**：情绪是每 tick 从零重算的反射，意图层是**唯一有记忆的一层**——manager 级、三种模式互斥、状态不落盘（与 `fairValue`/`fund`/`regime` 同寿命，重启重新观察）。触发带**随机门 + 随机时长 + 随机力度 + 冷却**：条件满足只抬高每 tick 的触发概率，不构成"看到信号就必然发生"的确定性映射（顶底仍不可押注）。只有能做空的聪明钱（机构/游资）执行，且**空头阵营的账户一律不参与**（它们正往空侧走，让它们反手做多会毁掉"卖光库存翻净空"那条路径）。

| 意图 | 触发条件（`config.npc.intent`） | 行为 |
|---|---|---|
| **挤兑空头** squeeze | 空头存量 ≥ 5% 流通盘 + 券源被借走 ≥ 45% + `force ≥ 0.1` + 非下跌段（卖盘越薄触发概率越高） | 参与者情绪 +1.1×力度、吃单量 ×2、买盘 ×1.8，**停挂卖单 + 暂停过热派发**（一边往上打一边挂卖单是给自己拆台） |
| **压盘吸筹** accumulate | 大级别位置 ≤ −25%（`fund/initPrice − 1`）+ `force ≤ 0.3` | 前 25% 时长**诱空砸盘**（主动卖把价格打下去），随后承接吸筹：报价中枢额外下压 0.5%、买盘 ×2、卖单 ×1.6，**不主动扫单**（吸筹靠承接不靠追），并临时解除"做空类只惩罚超配"→ 允许低配收集 |
| **抬价派发** distribute | 大级别位置 ≥ +25% + 追涨动量为正 + `force ≥ −0.2` | 前 20% 时长**诱多拉抬**（做出突破的样子），随后派发：卖单 ×1.8、**一律不开多**（含不抄底，别接自己的货） |

- **"高位/低位"必须用大级别位置（`fund / initPrice − 1`），不能用"价格相对重心"的短端偏离**：短端偏离被 `fvAnchor`（几十 tick 时间常数）钉在 0 附近，实测"偏离 15%"的命中率是 **0.00%**——拿它当门槛等于这条战术永不触发。退出条件与入场同口径（`exitAboveLevel`/`exitBelowLevel`），否则"入场看大级别、退出看短端"会让意图刚开就立刻满足退出条件。
- **每条意图都必须能自己退出**：涨幅保险丝（挤兑 40% / 吸筹 15% / 派发 50%）、目的达成（空头被挤掉 75%、大级别回到发行价附近）、判断失效（吸筹中又跌 30%）、时长到点。收手后进入 1200~3000 tick 冷却。
- 实测（4~6 局 × 3000 tick × 10 股，对照开关关闭的基线）：挤兑 4 次、均涨 **+32%**、胜率 100%；压盘吸筹 31 次、铺垫段 −4.4%（砸得下去）、期间**机构库存 +2.9%**（吸到货）；抬价派发 37 次、铺垫段 +9.8%（拉得起来）、期间**机构库存 −2.3%**（派得出去）。意图状态占全部股票 tick 的 0.8%~7%。

**被动持有者的浮盈亏行为（`npc.pnlFeel`）**：大户/中户/散户不再是"永不卖出的背景板"——他们按**自己的持仓成本**（NPC 批次每 tick 合并成一条，均值即成本）算浮盈亏：浮亏 ≥ 25% 恐慌割肉（`panicBias` 0.3、上限 ×2）、浮盈 ≥ 30% 获利了结（0.25）。机构的吸筹/派发要有对手盘，一群人死拿到底的话战术就空转了。**成本口径绝不能用发行价**：那样这批人要一路扛到最后才动，盘面没有换手。

**盘口微结构感知（`npc.intent.depthAware`）**：① 主动单量按对手最优档承接力约束（`aggroDepthMult` 3）——主动单成交价钉在"对手价 ∓1 分"，超出的量会变成留在盘口的残单，那不是做市；② **主动卖单不下手于比 `thinBookFloor`（3000 股 × qtyScale）更薄的买盘**——砸掉最后一档承接力之后盘面就变成"没有买盘"，连想跑的人都跑不掉。实测这条把**买盘空档率从 7.4% 压到 1.0~1.7%**（顺带消除了 `game.test.js` [1]「盘口存在买盘」的偶发红），代价是极端下跌里砸盘的最后一档不再被踩穿。

> ⚠️ **这个 1.0~1.7% 是「没有天」时代的数**。引入「天」之后夜间有日终结算把委托全部作废、两段竞价只累积不连续撮合，这些 tick 的簿天然是空的，`npc-probe.js` 原先逐 tick 采样会把这个比例抬到 **15%**（改动前后一样高，纯口径污染）。2026-10-16 已把采样限定在**连续竞价时段**：卖盘空 0.2~0.35%（正确），买盘空 **11.5%**。

**买盘空档的根因与修法（2026-10-16）**：**不是池子没钱，是钱的位置不对**。实测（24010 个连续竞价采样）买盘空档那一刻全池现金仍占流通市值 **18.75%**，与有买盘的时刻（18.92%）几乎一样；但**拿得出一个手数现金的账户只剩 19.9/316**（有买盘时 111.7），且"有资格挂买盘、手上却没有活买单"的账户**全部卡在重报价随机门上**（自己那张买单被吃光后手上还剩一张卖单，`ownResting` 非空 → 要等 25%/tick 的门，平均 4~5 tick 才补回买盘）。钱的位置为什么不对：一天下来散户/中户把现金都换成了股票（初始 340M 股票 vs 15M 现金），钱集中在机构手里，买盘侧的实际承接力只剩十几个聪明钱账户，它们一转空头阵营买盘就整侧空掉。两处修法：

- **`shouldRequote`：买盘侧空了 + 自己有现金 + 手上没有活买单 → 立刻重报**，不等随机门。买单刚被吃光本来就该马上补上，这是"买盘空档"里占比最大的一类（竞价那句"只在簿空时补一次"之外的唯一例外）。
- **`recycleLiquidity` 第二条判据（判据是**症状**，不是"人头够不够"）**：**买盘侧真的空了**时才给最穷的几个账户补到 `liquidityTopUpLots`（8 手），每次只补 `liquidityTopUpHeads`（2）个人头、补完歇 `liquidityTopUpCooldown`（12 tick），且**只补还有买入空间的账户**（`longCapacity ≥ 1 手`）。⚠️ 两条约束都是必需的：补进去的钱会被立刻挂成买盘（可用现金随即归零），拿"挂得起一手的账户数"当判据的话**每 tick 都会触发**（正式服实测 3 秒内连记 4 条日志），等于逐 tick 无限注水、还把账户反复标脏；而补给已打满 `longCapMult` 的账户则根本进不了买盘，只会变成闲钱把池子现金越垫越高（进而抬高力量天平的"弹药"票）——`longCapacity` 那条同时给机制设了自然上界：全池买入空间填满后它自动停止注水。

**这个指标必须用固定种子的配对 A/B 来判定**：它按种子的跑动方差极大（单跑 3%~45%，同一配置换个种子能差一个数量级），**单跑对比完全不可信**（我第一轮就是被这个坑了：先后读到 11.25%/11.48%、4.8%/6.0%/8.8%/9.6%，其实全在噪声里）。做法是 mulberry32 换掉 `Math.random`、同一批种子跑两遍配置做配对。8 个种子 × 3000 tick 的配对结果：**买盘空 10.98% → 7.17%**（8 个种子 7 个改善，配对 t≈1.7、p≈0.12——方向一致但**未达统计显著**）。**分解不清**：4 种子那轮显示"只开立刻补报"反而比基线差（28% vs 15%），怀疑是单独开着它会把买盘持续暴露给卖方、加速买方现金耗尽，只有和补款一起才划算——样本不足以定论，仅作观察记录。卖盘空档不受影响（0.07%）。**残留**：这个量级的空档是「机构转空头就不挂买盘」这个必要设计（不这样库存清不到 0、净空建不起来）的结构性代价，要根治得先收换手率（见下）。**补款的代价**：它会在单边市里按冷却上限持续小额注水（实测每只股票约每 8~18 秒补 2 个人头 × 8 手），长期跑会缓慢垫高池子现金（进而抬高力量天平的"弹药"票）——`longCapacity` 那道闸把它限在"全池买入空间"之内，量级约池子现金的百分之零点几/天，需要长期观察。

**玩法尺度 vs 真实尺度：换手率（2026-10-16 采集，同一轮真实数据对照发现）**：`day-probe` 新增的换手率指标显示游戏里**日换手率中位 37~46%**（日均成交 ~2500~3000 万股），而真实十只港股是 **0.98%**（p90 约 1.5%）——**差 38 倍**。NPC 每 tick 都在双边报价、报价中枢又有情绪离散度（`sentiment × centerShift` 可达 ±0.3%，大于点差），高估值的 NPC 买单会打穿低估值的 NPC 卖单，于是每一轮重报价都在成交。这条是**当前最大的真实度缺口**，而且它同时解释了两件事：① 竞价段占全天成交量只有 1%（真实约 10%）——不是竞价没量（实测开盘竞价均量 22~24 万股/股·日，与真实开盘竞价同量级），而是**分母被连续竞价撑大了 38 倍**；② 买盘侧为什么脆弱——**卖压几个 tick 就能把补款吃光**（补款总容量约 790k 元 ≈ 3.9 万股，而日均成交 2670 万股）。**要动它必须单开一轮**：它牵动挂单量/重报价频率/点差三处，会同时改盘口深度、贴板率与日波动，且需要新的"换手率"红线来守。


**消息**：盘中 20~60s 一条，作用 60s（**产出节奏 / scope 分布 / 文案按交易日阶段分段，见下「消息按天分段」**）；scope 分 机构/散户/全体；**文案按 scope 分池**（`news.js` 的 `TEMPLATES`：全体 = 大盘（20+20 条，恒生科技指数口径）、机构 = 研报/调研/大宗/席位、散户 = 股吧/小道/情绪，后两池各 12+12 条）。抽取顺序是「先定 scope，再从该池按方向取文案」，所以盘面不会出现「机构」scope 却播宏观政策这类错配。**个股消息还会再按股票分池**（`STOCK_TEMPLATES`，key = 股票名，见下）：十只股票各按自己的原型公司业务写了 4 个池 ×8 条，共 320 条，看文案就知道是哪只股票的事。`pickText(scope, dir, stock, session)` 决定取哪一层——该股有专属池就用专属池，没配则回退对应 scope 的通用池，盘后个股走公告池。池内去重按**池**独立记录（`recentByPool`，`REPEAT_GUARD = 12`；池子比它小时按「池长 − 1」收口），保证一轮抽完之前不重复，全用过才退回纯随机。文案不影响 `power`/`until`/情绪权重——仍是随机 0.3~0.8、60s 衰减。双通道作用——情绪（偏移报价中枢、触发吃单、挂单量倾斜）+ 直接乘性推公允价值（`fvDriftCoef: 0.0015`）；方向随牛熊阶段 70/30 偏置（`regimeBias: 0.2`）。**群体反应不对称**：散户/游资/大户跟消息同向追涨杀跌；机构 `sentimentByScope` 看见公开消息（全体+散户盘）后**对倒**——公开利好出货、公开利空吸筹，机构专属消息仍小幅同向（`publicNewsFade` / `instNewsFollow`）。

**消息按标的归属**：`scope=全体` 的宏观消息 → **大盘消息**（`stockId: null`，作用于全部 10 只，指数因此有系统性涨跌）；`scope=机构/散户` 的个股消息 → **随机挂到一只股票**，文案自动加【股票简称】前缀，只影响那一只的情绪与公允价。`NewsSystem.applies(n, stockId)` 是统一的过滤口：大盘消息对所有股票生效，个股消息只对自己的股票生效。

**消息按天分段（2026-10-16 起，`config.news.phaseRules`）**：key 对应 `day.phases[].key`，没配的阶段回退全局 20~60s + 三 scope 均匀抽；客户端约定「竞价 = 盘前、夜间 = 盘后，收盘竞价归盘中、午休单列」。
- **产出节奏 + 换阶段重排**：`maybeEmit` 用 `nextAtPhase` 记录 `nextAt` 是按哪个阶段排的，**阶段一变就按新阶段节奏重排**——不重排的话下午末尾排出的 +60s 会把 40 秒的夜间整段吞掉（首次调用只登记不重排，构造时已排过队）。盘前（开盘竞价 30s）8~16s、盘后（夜间 40s）8~15s（段内必出）、午休 18~35s（保底一条）、**收盘竞价刻意不配规则**（全局下限 20s ≥ 段长 20s → 恒无新消息，尾盘张力交给竞价机制）。
- **scope 分布**：盘前 全体 0.6 / 机构 0.25 / 散户 0.15（隔夜宏观为主）；午休 0.35 / 0.45 / 0.2、盘后 0.3 / 0.5 / 0.2（都偏机构，公告与公告解读）；盘中均匀。
- **文案**：盘后的**个股消息**改走 `ANNOUNCE_TEMPLATES`（盘后公告池 12+12：业绩预告 / 回购 / 减持 / 立案 / 重组……通用正文加【简称】前缀套到个股），大盘消息仍走「全体」隔夜宏观池；盘前与盘中沿用既有池。消息带 `session` 字段（盘前/盘中/午间/盘后），客户端只对非「盘中」渲染时段标签（老数据无 `session` 不渲染）。
- **作用期 `untilFloor`**：盘后消息 `until = max(now + 60s, 次日开盘竞价结束)`（`game.tick` 按 `dayEndsAt + 开盘竞价段长` 下发）——60s 墙钟会在夜间（40s）结束前就让消息过期，隔夜公允价值迁移（`stepFairValue` → `fvDrift`）与次日竞价的情绪/报价就全吃不到它，「盘后公告影响次日开盘」不成立。竞价结束那一刻恰好过期，不拖进盘中。实测（`day.test.js` [18]）：夜间消息竞价中段情绪仍为 0.187、公允推力 1.41e-4，竞价末过期。

### 3.1 交易日机制（`src/daycycle.js`，2026-10-16 起）

引入「天」之前行情是**一条连续时间轴**——没有开盘收盘、没有昨收、没有收盘价。现在一天被切成 6 段，段与段之间发生的事完全不同（集中撮合 / 连续撮合 / 冻结推进公允价值），这是「天」机制的全部内容。

**时间轴**（`config.day.phases`，合计 **620 秒 = 10 分 20 秒**）：

| 阶段 key | 中文名 | 游戏内时长 | 映射到真实时刻 | 可下单 | 连续撮合 | 竞价 |
|---|---|---|---|---|---|---|
| `auction` | 开盘集合竞价 | 30s | 09:15 → 09:25 | ✅ | ❌ | open |
| `morning` | 上午连续竞价 | 230s | 09:30 → 11:30 | ✅ | ✅ | — |
| `lunch` | 午间休市 | 40s | 11:30 → 13:00 | ❌ | ❌ | — |
| `afternoon` | 下午连续竞价 | 260s | 13:00 → 14:57 | ✅ | ✅ | — |
| `closeAuction` | 收盘集合竞价 | 20s | 14:57 → 15:00 | ✅ | ❌ | close |
| `night` | 休市结算 | 40s | 15:00 → 次日 09:15 | ❌ | ❌ | — |

- **刻意不按真实时长等比压缩**：真实 A 股盘中 250 分钟压到 10 分钟是 25 倍，等比压缩下收盘集合竞价只剩 7 秒——而竞价与尾盘恰恰是博弈密度最高的两段。这里给两段竞价合计 50s = 一天的 8%，日内连续交易占 79%。
- **`gameTime`/`gameMs` 把游戏内进度线性映射成真实交易时刻**，顶栏直接显示 `09:15`/`11:30`，玩家顺带学会真实规则。夜间 40s 映射 15:00 → 次日 09:15（1095 分钟），所以「一夜」在观感上也是完整的一夜。
- **纯函数**：`DayCycle` 只由 `startAt`（本轮开盘时刻）+ 当前时间推出阶段，**没有任何内部状态**。重启只需把 `startAt` 存进 meta 就能接着上一局的时间轴走；客户端也**不许自己算阶段**，一律吃服务端下发的 `state.day`。
- **主循环不吃 `Date.now()` 之外的时钟**，`locate()` 是 O(阶段数)，与停服多久无关（不会"补跑"中间阶段）。

**集合竞价**（`Market.auctionQuote` / `runAuction`）：

- **竞价阶段只入簿、不撮合**（`place` 里判 `auctionKind(now)` → `book.add` 而非 `match`）。此时**盘口允许买卖价交叉**——真实行情里的「虚拟开盘价」就是这么算出来的，客户端拿去当虚拟成交价展示。
- **虚拟成交价 = 最大成交量原则**：对每个候选价 P（= 买卖两侧价位并集），可成交量 `V(P) = min(Σ买价≥P 的剩余量, Σ卖价≤P 的剩余量)`，取 `V` 最大者；并列时取**最接近昨收**的那个（等价表达"不无谓地偏离"）。用两个有序数组归并 + 游标一次扫完，`V(P)` 天然是"先增后减"的单峰，不需要二分。
- **阶段结束的那一 tick 由 `Game.onPhaseChange` 逐个市场调 `runAuction(now)`**：按**价格优先、时间优先**在虚拟成交价上一次性成交，禁止自成交，收尾 `sweepCrossed()` 保证进入连续竞价时簿不再交叉（自成交残单走正式 `cancel`/`dropStaleOrder`，不能只 `book.remove`——会留一张账户侧 status=live 的幽灵单，把冻结与仓位预留锁死）；开不出价时也会 `sweepCrossed` 收尾。吃不完的委托**留在簿里**承接随后的连续竞价（真实市场就是这么承接的）。
- **所有成交统一按虚拟成交价**，挂得低的卖方也享受这个价（不是各按自己挂单价成交）。
- **价格笼子在竞价不适用**：笼子是相对上一笔成交价的 ±5%，而集合竞价相对昨收可以有 ±10% 跳空——照笼子判会把所有跳空单都判成"脱笼"。但**涨跌停照常约束**：`auctionQuote` 会把区间外的候选价直接跳过，`place` 也会按涨跌停拒单。
- **竞价最后 `cancelLockMs`（10 秒）内不可撤单**（复刻真实市场 09:20 那条硬线，也是整个竞价系统最有价值的心理设计点）。`Market.cancel` 里判 `auctionLocked(now)`，**内部撤单（`{internal:true}`：强平、结算、NPC 重报价）不受限**。
- **竞价报价两档：试探档 → 收敛档**（2026-10-16 起，`auctionCushionOpen` / `auctionProbeLastWeight` / `auctionConvergeMs`）。真实 09:15~09:20 可自由撤单，参与者会挂**试探性远价**博虚拟开盘价；这正是隔夜漂移能进到开盘价里的唯一通道——原先报价中枢一律硬夹最新价 ±3%，而竞价里的"最新价"还是**昨收**，跳空的尾部被整个切掉。现在：① **试探档**（开盘竞价、距锁单还早）把报价缓冲放宽到 **±8%**、并把中枢里"贴最新价"的权重从 0.4/0.25 压到 **0.18**（隔夜漂移不再被昨收稀释四成）；② 进入锁单窗口前 **2 秒**全体切到**收敛档**（回到常规 ±3%）——撤不掉就认账，最后一刻的报价必须落在真实意愿上，否则试探档的远价会被集中撮合在荒谬价位成交。`shouldRequote` 因此允许每个 NPC 在竞价里报**两次**（试探档一次、收敛档一次），其余时间仍只在簿空时补一次（跟着 tick 撤挂会把竞价簿搅散、凑不出集中成交量）。**只有开盘竞价放宽**：收盘竞价相对"刚走完的下午"不该凭空跳那么远（尾盘异动是另一个玩法维度，本轮刻意不做）。⚠️ **收敛档的前提是"全体 NPC 的挂单都能被撤掉"**——`tryAggressive` 的残单也必须登记进 `ownResting`，否则竞价簿里会留下 requote 撤不到的**无主委托**（见文末 2026-10-16 第三轮）。
- **竞价段的成交量还很薄**（已知残留）：`day-probe` 实测两段竞价合计只占全天 **~1%**（真实市场约 10%）。**根因不是竞价没量**——实测开盘竞价均量 22~24 万股/股·日，与真实开盘竞价同量级，而且竞价簿本来就交叉（见上「买卖价交叉」）；是**分母被连续竞价撑大了 38 倍**（游戏日换手率 37~46% vs 真实 0.98%）。所以修的方向是收换手率，不是给竞价加量：2026-10-16 试过"竞价里下一侧可成交单"，实测零收益，已撤回（见文末变更记录）。
- **竞价期间与休市期间不做风控强平**（`maybeLiquidate` 里 `!continuousNow(now)` 直接返回）。竞价簿里买卖价允许交叉，强平单按它撮合会被交叉价一路拉飞；休市则压根没有对手盘。另有一个 `_auctionRunning` 冻结标志：**阶段切换那一 tick 里 `phase` 已经翻到下一段**，`continuousNow()` 会误判成"已进入连续竞价"，但此刻竞价撮合正在跑，必须靠这个标志兜住（实测没有它强平单会把成交价拉飞）。

**日终结算**（`Market.settleDay` + `Game.settleDay`，由 `closeAuction → night` 的切换触发）：

- **当日定格成一根日线**（`flow.recordDailyBar`，2026-10-16 起）：今开/高低/收盘/量额/内外盘额在这一刻被记进 `market.dailyBars` 并落 `daily_bars` 表，K 线图就吃这份数据。**必须排在归零之前**——归零之后这些数就再也拼不回来了。记录有**归属校验**：只有「分时序列末点落在被结算的那一天」才记，停机数天后的补结算因此不会凭空多出一根重复的 K 线。
- **收盘价定格为新「昨收」**（`prevClose = lastPrice`），涨跌停区间随之滚动到「今日」。
- **今开/最高/最低/成交量/成交额归零**，`dayTradeCount` 归零——次日第一笔成交重新决定「今开」。`IndexFeed.settleDay()` 同理把指数高低量额清零。**当日内外盘累计同时清零**（`flow.resetDayFlow`）。
- **委托当日作废**：全部活动委托撤掉、退回冻结资金与仓位预留（真实市场收盘后未成交委托自动失效）。实测一天结束时约 **9800 笔**未成交委托被清掉。不清的话昨天的挂单会带着昨天的价格活到今天，玩家看到的盘口与自己的委托表都对不上。
- **指数那根日线要抢在成分股清零之前算**：`Game.settleDay` 先 `index.recompute(markets)`（只重算点位/量额/内外盘、不推分时点），再逐股 `settleDay`，最后 `index.settleDay`。顺序反了的话指数日线的量额会是 0，连收盘竞价那批成交也一起丢掉。
- 结算进度写进 `meta.day_settled`，供续跑判断。

**资金流向（内外盘 / 净流入）**（`flow.js`，2026-10-16 起）：

- **口径**：外盘 = 主动买成交（买家吃卖单），内盘 = 主动卖成交（卖家吃买单）。主动方向在 `Market.execute` 里就已定死（见 `onTrade` 的 `aggressorSide`），`flow.addTrade` 只做按日累计，**不重新判断方向**——所以盘口内外盘与逐笔的 B/S 标记永远一致。
- **净流入 = 外盘成交额 − 内盘成交额**，与真实行情软件同口径；另给 `outerPct`（外盘占比，>50% 说明主动性买盘占优）。当日一笔未成交时 `outerPct` 为 `null`（客户端显示 `--`，不显示 0% 或 50%）。
- **账实一致**：`外盘量 + 内盘量 === 当日成交量`、`外盘额 + 内盘额 === 当日成交额`（每笔成交都被归类一次，没有漏项）。`flow.test.js [1]` 把这条钉住了。
- **指数没有自己的成交**：内外盘是成分股的合计（`IndexFeed.recompute` 里逐股加总）。
- **当日累计必须落盘**（`market_state.outer_vol/outer_amt/inner_vol/inner_amt`）：不恢复的话重启后「外盘+内盘」会小于当日成交量，盘口资金与成交量对不上账。
- 集合竞价那一批集中撮合**整批按价格方向归类**（复用 `_runAuctionAt` 里 `price >= lastPrice ? 'buy' : 'sell'` 这条既有判据）：竞价价相对昨收跳空向上时，整段竞价量都记成外盘。这是「逐笔方向」口径的自然结果，玩家在逐笔里看到的也是同一批 B。

**隔夜跳空**（引入「天」最想要的那个机制）：

- 休市期间（午休 / 夜间）**行情价格冻结在收盘价、不接受下单、不撮合、不报价**，但 **NPC 的 `fairValue` 继续迁移**（`NpcManager.stepFairValue` 只走 `priceTrail` + `updateFairValue`）。于是次日开盘竞价的第一次集中撮合自然出现缺口。
- **`overnightDriftMul: 13` 只在夜间休市放大趋势推力**（`Market.isNight`，午休不算）——游戏里的 40 秒夜间代表现实的一整夜，不放大次日开盘价与昨收几乎贴在一起；午休同样 `closedForTrading`，但只是盘中暂停，同样放大会在 13:00 制造与隔夜同量级的假跳空。跳空幅度 ≈ 夜间漂移 / `priceCoupling`，再被涨跌停夹在 ±10% 内。
- **`fundOvernightFollow: true`：夜间基本面重心跟着同一倍数一起迁移**（2026-10-16 加）。这是把跳空做到真实量级最关键、也最容易漏的一步：只放大短端 `fairValue` 而 `fund` 不动的话，机构的定价锚（`fundWeight 0.7`）一夜之间"没改口"，而机构又是竞价簿里**单量最大的一侧**（`requoteQty` 最大档 10 万股 + 流动性地板回补），**最大成交量原则算出的竞价成交价被这批大单硬拉回昨收附近**——实测夜间公允漂移 1.55%、跳空只有 0.70%（漏斗 0.45）。真实市场的隔夜跳空恰恰来自"收盘后信息把基本面重估了一遍"，重心本就该跟着动。打开后跳空 std 从 0.64% 提到 1.4~1.9%。
- **真实跳空口径**（十只港股 5020 个「股票×交易日」）：std **1.82%**、中位 |跳空| **0.88%**、|跳空| ≥ 1% 占 **45.1%**、≥ 3% 占 **7.7%**、p99 6.27%。本轮实测 std 1.4~1.9%、≥ 1% 占 37~45%、≥ 3% 占 8.5%，同量级。`day-probe.js` 会输出这三项，改 `overnightDriftMul`/`fundOvernightFollow`/`bands` 都要盯它。
- **新闻在休市期照发**（`tick` 里消息不随 `closed` 关闭）：盘后公告正是隔夜跳空的燃料，停掉它「天」就没有夜了。盘后消息的作用期被抬到**次日开盘竞价结束**（见 §3「消息按天分段」），隔夜公允迁移与竞价情绪都吃得到它。

**涨跌停**（`config.priceLimit`，2026-10-16 起默认开启）：

- **日频机制**：区间 = `昨收 × (1 ± 10%)`，昨收**只在收盘结算时滚动**。没有交易日时钟时 `band()` 返回 `null`（否则会死锁——见下）。
- `band()/inBand()/clampPrice()` 三个钩子被 `place`（超区间拒单）、`auctionQuote`（候选价过滤）、`forceSellLong`/`forceCoverShort`（强平不接脱笼盘）共用。
- **±10% 之所以有意义，是因为趋势幅度已按「天」重标定**（见上「行情模型」）。两者是绑在一起的：`day-probe.js` 先给出原始日波动（用来定 `pct`），±10% 才是"只在尾部咬住"的熔断器。**当前实测（4 局 × 5 天 × 10 股 = 200 个「股票×交易日」）**：开启后**连续竞价时段贴板采样占比 4.7%**（目标 <5%）、最长连续贴板 2 天、被夹在板上的交易日占 3.0%（其中多数是「四舍五入到最小价位」造成的 10.0x%，不是真的越界）；关闭时超过 ±10% 的交易日占 2.0%（= 真实港股 1.2% 的「偶发涨停」频次）。**调 `trend.bands`、`priceLimit.pct`、`overnightDriftMul` 任何一侧，都要重跑 `day-probe.js` 的 on/off 对照**——跳空放大之后开盘就可能贴着板，贴板率与连板天数会被它一起带动。
- **已知待决策（副作用）**：波动率降下来之后**强平从 66.7 次/天 掉到 0 次/天**——即「杠杆爆仓」这个风险维度实际上被关掉了（`npc-probe.js` 的对照数据也能佐证：改动前 3000 tick × 4 局有 1062 次强平）。本轮把日波动收到真实的 1.4~1.7 倍之后**仍是 0 次/天**。如果要保住爆仓，可选：调低 `margin.maintenance` / 调高 `margin.ratio`（放大杠杆）、或把 `trend.bands` 取在「完全对齐真实」与「÷11」之间。**这属于用户确认过的交易规则（保证金 50% / 维持率 30%），改之前要问。**

**日内节奏（NPC 阶段感知，2026-10-16 起，`config.npc.rhythm`）**：引入「天」之后 NPC 仍是一根**均匀的时间轴**——报价、吃单、挂单量每 tick 一样密，段的差别只体现在"能不能交易 / 要不要集中撮合"上，盘面的交易密度是平的，观感与没有「天」时几乎一样。现在每只股票的做市引擎每 tick 从 `Game.tick` 收到一个阶段快照（`NpcManager.setSession({key, pct, auction, converging})`），据此算出一个 **0.75~1.45 的活跃度乘子**并摊到四条通道：

| 通道 | 敏感度 | 作用点 |
|---|---|---|
| 主动吃单率 | `aggroGain 1.0` | `step()` 里 `aggressiveRate` |
| 单笔挂单/吃单量 | `qtyGain 0.7` | `requote` 的双边量、`tryAggressive` 的单笔量 |
| 重报价频率 | `requoteGain 0.6` | `shouldRequote` 的 0.25 基础概率 |
| 点差 | `spreadGain -0.3` | `requote` 的点差（活跃段收窄、清淡段放宽） |

- 活跃度 = **阶段基准 × 段内 U 型曲线**。阶段基准：开盘竞价 1.15 / 上午 1.0 / 下午 0.88 / 收盘竞价 1.30（真实市场日内量能是 U 型：隔夜信息在开盘与尾盘两段释放、资金在这两段进出，午间清淡）。段内曲线（只作用于 `morning`/`afternoon` 两个长段）分段线性：段首 18% 从 1.45 衰减到谷底 0.85、中段保持 0.85、段尾 12% 回升到 1.25——比阶跃更贴近真实的"逐渐清淡 / 逐渐回暖"。
- **只调制交易行为，绝不碰公允价值与噪声**：定价路径必须与 `day.test.js [17]`（午休步进＝上午、夜间＝上午 × `overnightDriftMul`）的口径一致；把波动也按段缩放会让「午休不制造假跳空」这条不变量失效。也正因为如此，**没接时钟（`day.enabled=false`）时下发 `null`，活跃度恒为 1，与旧行为逐位等价**——直接调 `npc.step(now)` 的单元测试完全不受影响。
- 实测（`day-probe` 4 局 × 5 天）：日内量能占比从改造前的 **上午 46.6% / 下午 52.3%（均匀，且按段长下午本该更多）** 变成 **上午 52~60% / 下午 39~47%**，开盘段与尾段明显更重。

### 3.2 券商（出身门派）与消息分层（2026-10-16 起）

两份设计稿（`Doc/券商方案.md`、`Doc/消息分层方案.md`）在本轮一并落地。**改这块数值/规则前先读那两份**，这里只记实现要点与踩过的坑。

**券商 = 账号上的一个必选字段，把上面那批全局参数改成 per-broker 覆盖。** 解析全在 `Server/src/broker.js`（纯函数层，不持状态），`market`/`npc`/`auto`/`game` 只读它的结果，不各自算。

- **两级兜底**：`broker.forAccount(acc, {day})` → 优先券商覆盖值，没覆盖的回落上面的全局默认。**账户没有 `broker`（老档、NPC、测试里裸造的账户）逐位等于基准** —— 这是"引入券商不改老行为"的唯一保证。
- **NPC 的券商是纯展示标签**：`forAccount` 对 `isNPC` 直接返回基准。一旦让 NPC 也吃 per-broker 的费率/额度/券源，3160 个账户的容量与报价路径会一起漂移、盘口分布莫名畸变（§11.4.3）。
- **方向规则（本文件最重要的一条）**：相对基准"更好"的特权才按星级递进解锁，"更差"的代价**立刻全量**生效（`broker.privilege`）。不做这个方向判断，滑泰会"越升级借钱越少"。递进强度 = `min(star, 4)/4`（1★ 1/4 → 4★ 满额 → 5★ 同满额）。
- **值域**：佣金 `trade.feeRate` / 冷却 `trade.cooldownMs` / 锁仓 `trade.lockMs` / 做空冻结 `margin.ratio` / 融资自备 `margin.finance.ratio` / 维持率 `margin.maintenance` / 券源系数 / 券息倍率 / 策略条数 `auto.maxPerAccount` / 消息提前量 / 强平缓冲 / 禁买名单 / 通道卡顿概率。
- **拥挤税**：拥挤度是**配置里的固有属性**（不随真实账号占比变化，§9 D3），按档位只惩罚**佣金**与**券源**两项（不做报单延迟）。改拥挤度改 `brokers.list.<key>.crowd`。
- **声誉星级**：按**本券商**的累计成交额 + 累计盈利（相对入会时的 `realizedPnL` 基线）+ 有无爆仓记录评级。转户时新旧两家的进度都清空。
- **每周之星**：按**交易日号**轮转（一周一家，`daysPerWeek` 天），加成 = 佣金减半 + 融资额度 +0.5×。**没有交易日时钟时（`day < 1`）不启用**——否则老用例的费率会被悄悄改掉。
- **「策略槽」在现网没有对应键**：设计稿按槽位说话（基准 2 槽），实现按比例换算 `条数 = auto.maxPerAccount × 槽位 / baseSlots`。
- **强平缓冲**：其余五家 `liquidationBuffer 0.05` → 破维持线先只给「追保预警」横幅，再低 5 个百分点才真强平；天疯 `zeroBufferLiquidation` → 破线即全平。基准 0 → 无券商账户行为不变。
- **东风人气热度**：只统计**东风玩家**在该股的成交额 → 0~1 的热度（`market.dongfengHeat`）→ 放大该股**散户 NPC 的动量跟随系数**。只调制交易行为，不碰公允价值与噪声；没有东风客户时恒为 0。
- **消息分层**：消息「诞生 t0」≠「公开 t2」，中间是泄露期。`publicAt = t + leadMax`，各等级在 `publicAt − lead[tier]` 起可见（L0 内幕 6s / L1 机构 4s / L2 情报玩家 3s / L3 公众 0）。`scope=全体` 的 lead 恒 0（宏观没有内幕，维持现状）；`散户` scope ×0.5。`news.visibleFor(n, viewer, now)` 是唯一判据——**`publicAt` 缺失的消息视为立即可见**（老数据/裸消息的兼容口）。L1 复用现成机构，L0 从机构里哈希取前 k 名（每股恰好 1 个）。
- **泄露期绝不出现在公众视野**：`tapeSnapshot` / `stateFor.news` / `lastNews` 一律按 `publicAt` 过滤；达到 L2 的券商客户能在公开前看到"哪只股票有消息"，但**未满 4★ 时方向被遮蔽**（`masked`），5★ 才给方向。§7.2 的模糊异动提示走 `state.newsHints`（`config.news.irregularHint`，默认开）。
- **可观测性**：`news.noteLeakDrift` 在每条消息公开时记一次泄露期内的价格漂移并**只落日志不落盘** —— "消息公开前 N 秒价格已开始漂移"靠它验证，别靠感觉。

**踩过的坑（改这块前务必知道）**：

1. **账户名哈希必须带雪崩收尾**。NPC 账户名形如 `大米·机构1`…彼此只差末尾数字，裸 FNV-1a 的分布会塌成尖峰（实测均值 0.353、十分位 77/70/26/3/19/45/32/30/2/12，卡方远超临界值），加权轮盘会严重偏向某几家券商。`broker.hashUnit` 里补了 murmur3 的 `fmix32`，卡方降到 5.90（df=9）。**不要去掉那一趟。**
2. **提前量不做 tick 向下对齐**。向下对齐会把"满额 3s"砍成 2.8s（3000/700 → 4 tick），星级递进 0.75/1.5/2.25/3.0 整体错位。只保留下限夹取（`minLeadMs`，不足则抬到它）。
3. **券商图标要走白名单 + 缩略图**。静态服务是硬白名单，`/img/*.png` 原先一律 404；现在按 `config.brokers.list` 的 key 注册 `/img/broker-<key>.png`（1024 原图，卡片墙用）与 `/img/broker-<key>-96.png`（96px，盘口/逐笔/排行榜用）。原图合计 2786 KB → 缩略图 51 KB，**别在高频位置引用原图**。
4. **五档席位只放图标**（hover 显全名 + 占比）。价格列只有几十像素，塞两字简称会把价格挤花；简称保留在逐笔与席位榜。
5. **测试里改 `config.<段>.<键> = x` 的老写法对券商覆盖无效**——覆盖值来自 `config.brokers.list`，改全局基准只影响没有券商的账户。
6. **per-broker 参数必须查「谁在读它」，别只看「配置里写了」**。这一层最容易出的错不是算错，而是**算出来了没人用**：① `trade.lockMs` 曾是死的——锁仓判定在 `Account.sellableLong/freeSellableLong/reserveLong`（撮合与 UI 共用的唯一判定点），它不能 `require('broker')`（会成环），于是写死全局 10 秒，滑泰的「T+锁仓砍半 5 秒」只在 `market.place` 的**提示文案**里成立（实测 6 秒后仍卖不掉、文案却写 5 秒）。修法 = 三个函数加第三个参数 `lockMs`，由调用方传入 `brokerFor(acc).lockMs`（`market.place` 的卖出预检/预留、`market.lendShares` 的挂借闸门、`auto.js` 三处卖出、`game.serializePosition`/`serializeLending`），缺省回落全局基准（NPC 与无券商账户因此逐位不变）。② `broker.glitchDelay` 曾是**零调用方**的死函数，嗨通的「偶发通道卡顿」一点没生效；修法 = `market.place` 的冷却读它（`wait = bk.cooldownMs + glitchDelay(acc, bk) − 已过时间`，命中时这一单多等 1 个 tick，不累积）。**加参数时的自检口径**：`grep` 一遍该键在全项目的消费点，文案/展示/配置各算几处，剩下几处才是真正生效的。

**多股票要点（改行情/风控必读）**：
- `Game.markets` = 10 只股票的 Market + 1 个 IndexFeed（指数也进这张表，取价/落盘/广播一视同仁）；`Game.npcs` = 10 个 NpcManager。
- **NPC 账户每股一套**：`npc.init()` 给每只股票建 316 个账户，账户名带股票简称前缀（`大米·机构1`），现金与报单量按 `npc.capScale`（流通市值比）/ `qtyScale`（流通股数比）缩放，保证各股盘口深度与做市强度一致。
- **跨股票取价**：`market.priceOf = (stockId) => ...` 由 Game 注入，风控要按整个账户算权益就得知道其它股票的值；未注入时退化为「只有本股有价」（单股测试路径）。
- **委托号带股票前缀**（`600002-O15`）：每只股票各有自己的 `orderSeq`，不加前缀会在 `orders` 表主键上撞号；撤单按委托自身的 `stockId` 路由。
- **强平撤单也必须按委托自身股票路由**（`Market.cancelAny`）：强平前要撤掉该账户**全部**在途委托，而这些委托可能挂在别的股票的簿上——用本市场的 `cancel` 去撤会撤不到（自己的簿里没这张单），却已经删掉账户挂单表、改了状态、退了冻结，于是那张单留在别人的簿里变成「撤不掉、又仍会被撮合」的幽灵单，开空单占用的券源还会释放到错误的池子上。`Game` 通过 `market.marketOf` 注入市场解析器（未注入时退化为只有本市场，单股测试路径照旧）。
- **NPC 批次合并**（`Account.consolidate`）：NPC 每 tick 都在成交，一笔成交压一条批次，单账户能攒到几千条；而落盘写一个脏账户要把它的全部批次整段删除再写回，正式档实测每 tick 重写 40 万行批次、commit 占 3.5 秒。`Market.execute`（成交后）与 `Game.applySnapshot`（重启恢复后）对 NPC 账户按股票合并成一条（数量加权均价，数量/成本合计/负债/本金/保证金/预留量全部守恒，锁仓取最早批次＝原 FIFO 口径）。**玩家账户绝不合并**，保留 FIFO 的成本价与盈亏口径。
- **卖出/买入平仓不受方向锁限制，强平也不走 `place`**：`maybeLiquidate` 用 `forceSellLong`/`forceCoverShort` 直接改批次。旧档里可能残留多空并存（互斥规则之前建的），这类账户**只许平不许开**，平到一侧归零就回到单方向。
- **融券池每股一套**：挂借量、欠息、利息收付都记在 `Account.ledger[stockId]` 上，A 股的欠息不会被拿去补 B 股的出借人。
- **融资利息只摊本股批次**：每个市场各调一次 `accrueFinanceInterest`，若遍历账户全部持仓会把同一笔负债计息 10 次。

**tick 顺序**（`game.js tick()`）：
① **交易日定位**（`day.locate(now)`）→ **阶段切换时做该阶段的一次性动作**（竞价结束 → 逐股 `runAuction` 集中撮合；收盘竞价结束 → `settleDay` 日终结算）
→ ② 停牌过期（全市场）→ ③ news（方向偏置取各股 regime 均值；**休市也照发**）→ ④ **逐只股票**：休市时只跑 `npc.stepFairValue`，交易时段跑 `npc.step` → 持有该股敞口的账户 `maybeLiquidate` → 融券/融资利息 → 空头 5min 采样 → 分时入列 → ⑤ `auto.step`（休市跳过）→ ⑥ `index.update` → refreshStats → SSE 广播 → persist.commit。
休市（午休 / 夜间）时行情价格**冻结**、不接受下单、不撮合、不报价，但消息与公允价值照跑——这是隔夜跳空的全部来源。
强平扫描按 `acc.longs/shorts.has(stockId)` 先过滤：10 只股票 × 3160 个 NPC 账户全扫是几万次无效检查。

**续跑补结算**（`Game.ensureDaySettled`，`catchUpDay` 是同义入口；`tick()` 每帧兜底调用）：停服期间时间轴照走，可能已经跨过若干次收盘。判据是**「已收盘日」**——当前若在夜间则是今天，否则是昨天。**不能**用 `st.day > day_settled`：那样 day2 上午（昨天已结、今天还没收盘）会被误结，昨收滚成盘中价、当日量额被清零。不补的话昨收会锚在几天前的收盘价上，涨跌停区间整个错位、**所有委托都会被判越界**；tick 跨过 `closeAuction`（休眠唤醒、长 GC）时 `onPhaseChange` 看到的 prev 不是 `closeAuction`，会永远漏结，所以 `tick()` 每帧都走一遍。补结算只滚昨收与当日高低量额，**默认不动委托**（免得把玩家新一天刚挂的单清掉），只有当前落在夜间时才按「当日作废」撤单；落在夜间时会先补一次收盘集中撮合，否则崩溃在收盘竞价里的那批委托会被「当日作废」整批吞掉。`_daySettled` 记的是**哪一天的收盘已经滚进昨收**（夜间结算 = 今天，次日盘中补结 = 昨天）。

**股东快照不在 tick 里**：它跟着玩家写操作走（`login`/`order`/`cancel`/`lend`/`unlend` 成功后各记一份），**按 (账号, 股票) 分开存**（`_holderSnapshots` 键为 `名字#股票`）；`login` 会给每只股票各记一份基线。所以「较上次操作」的基线只随玩家动手而移动，不会被每 700ms 的 tick 冲掉，也不会串到别的股票。

**持久化要点**（改资金/持仓路径必读）：
- 任何改钱/持仓的路径必须 `journal.touch(account)` / `orderChanged(order)` 落脏标，漏标只能靠 300 tick sweep 兜底。
- NPC 报价单**不落盘**（写 NPC 账户时退回冻结、reserved 归零），重启由 `npc.step()` 重报；落盘会产生撤不掉的幽灵单。
- 恢复走 `game.applySnapshot()`；**绝不能调 `npc.init()`**（那是新局建仓）。**存档里已不在本局配置的标的（改了 `config.stocks`）的持仓/融券行会被丢弃并记一条 warn**——留着会让 `priceOf` 取不到价、整局起不来。`fairValue`/`fund`/机构情绪态不落盘，重启重锚；每只股票的 NPC 报价对象按账户名前缀分派回各自的 manager。
- 强平前必须撤该账户全部平仓挂单（**按委托自身股票路由，见上一节 `cancelAny`**）；结算按**实际成交量**入账（账实一致不变量，详见 MEMORY）。
- Windows 下 `server.py stop` 是 `taskkill /F`，**SIGTERM 钩子不会执行**——退出时不做落盘，全靠按 tick 增量写。
- **利息类变更走 `Market.notifyInterest`，NPC 账户不标脏**：利息每 tick 都在变（慢漂移），逐 tick 标脏等于每 tick 重写全部 3160 个 NPC 账户；NPC 本来就有 sweep 兜底，少写几百 tick 的利息漂移没有影响。玩家账户照旧逐 tick 落盘。
- **成交流水每 tick 按时间裁**（`persistence.tradeKeepMs`，默认 10 分钟，`idx_trades_t` 支撑）：读取侧只看最近若干条，不裁的话 NPC 之间每 tick 的成交会让 `trades` 按 6 MB/分钟无限膨胀（实测正式档 40 分钟攒到 2.9M 行、库 492 MB）。重启后的第一个 tick 会把上个窗口外的积压一次删掉，可能卡几秒到十几秒（一次性）。

## 5. HTTP API（`http.js`）

写接口要求 `Content-Type: application/json` + 同源 Origin + IP 限流；身份只认 **token**（`Authorization: Bearer`，SSE 用 `?token=`）。请求体里的 `name` 不是身份来源。**带 `stockId` 的接口缺省时回落到第一只股票（大米集团）；指数代码只对只读接口有效。**

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/login` | `{name, broker}` 按名字建号/登录（同名复用、不独占）。**首次开户必须带 `broker`**，缺了返回 `{ok:false, needBroker:true}`；**昵称新注册仅 ASCII**（`^[A-Za-z][A-Za-z0-9_-]{2,15}$`，老档中文账号放行） |
| GET | `/api/brokers` | **登录前可读**的券商展示元数据（六家文案/预览数值/拥挤度/本周之星/本服已选人数）。`/api/state` 的 `rules.brokers` 是同一份 |
| POST | `/api/broker/transfer` | `{broker}` 转户（1 个交易日冷却 + 转户费 = 总资产 0.1% 上限 5 万；开户首日免费重选 1 次）。失败原因在 `error` 里 |
| POST | `/api/broker/coupon` | 使用当日的免息券（招伤自带；拥挤税补贴档的券商也送），生效后当天融资/融券利息全免 |
| GET | `/api/state` | 完整快照：`markets[]`（10 只股票）+ `index`（含成分权重）+ `account.positions[]` + **`day`（交易日段）**。**不含分时**（10 只 × 10300 点太大） |
| GET | `/api/history` | `?stock=` 某只标的的完整分时（切股票时拉；**接受指数代码**） |
| GET | `/api/sparks` | 全部标的的**降采样**分时（每只 ~60 点），主页行情列表的迷你走势一次性拿全 |
| GET | `/api/daily` | `?stock=` 某只标的的**已收盘日线**（K 线图切到日线模式 / 换标的时拉；限流 `daily` 60/分钟；**接受指数代码**）。只回已收盘的那几根：当日那根要等收盘结算才定格，由客户端拿实时行情现拼，于是它每帧都在动 |
| GET | `/api/holders` | `?stock=` 某只股票的前十大股东 + 两层变动 + 基线时刻（进 tab/切股票时拉，前台 5 秒刷新） |

| POST | `/api/order` | `{stockId, action, qty, price, finance}`；action ∈ buy_open / sell_close / sell_open / buy_close；**指数代码直接拒** |
| POST | `/api/cancel` | `{orderId}`（按委托自身所属股票路由，不需要 stockId） |
| POST | `/api/auto` | `{op: create/update/remove, stockId, ...}` 策略（create 时 stockId 决定策略绑哪只股票） |

| POST | `/api/deposit` | `{amount}` 加钱（受终身上限；`deposit.enabled=false` 时返回"加钱功能未开放"） |
| GET | `/api/events` | SSE，`event: state` 每 tick 一帧（markets + index + 账户段）；15s 心跳；token 失效客户端自动重登 |
| POST | `/api/admin/halt` | `{minutes, reason}` **全市场停牌**，头 `X-Admin-Token` |

| GET | `/` `/index.html` `/app.js` `/style.css` | 静态客户端 |

每账户最多保留 5 个会话令牌（`MAX_SESSIONS_PER_ACCOUNT`）。

**`state.day`（交易日段，随每帧 SSE 下发）**：`{enabled, day, phase, label, trading, auction, locked, unlockLeftMs, phaseMs, phaseElapsedMs, phaseLeftMs, phaseEndsAt, dayEndsAt, gameClockMs, phaseGameMs}`。`phase` = 6 个阶段 key，`auction` = `'open'|'close'|null`，`locked` = 是否已进入不可撤单窗口，`gameClockMs` = **此刻**的游戏内真实交易时刻（供顶栏显示 09:15~15:00），`phaseGameMs` = 该阶段映射的真实时长（用于客户端按比例推进时钟）。时钟未配置时下发 `{enabled:false, trading:true}`，老客户端据此自动退回旧口径。**不含任何内幕**（没有 `fairValue`/`force`/意图）。`markets[].auction` = `{kind, price, volume, locked}` 是竞价阶段的虚拟成交价（`price:null` 表示盘口未交叉），非竞价阶段为 `null`。`markets[].band` = `{up, down}`，无交易日时钟时为 `null`。`markets[].flow` = `{outerVol, outerAmt, innerVol, innerAmt, net, outerPct}`（含指数的成分股合计），当日累计、结算时清零，**没有成交时 `outerPct` 为 `null`**。

**券商与席位相关的下发字段（2026-10-16 起）**：`rules.feeRate`/`cooldownMs`/`lockMs`/`marginRatio`/`maintenance`/`finance.ratio`/`auto.maxPerAccount` 都是**该账户券商的有效值**（未登录时给纯基准，且不套每周之星）；`rules.brokers` 是六家展示元数据、`rules.brokerMeta` 是玩法参数（昵称规则/转户参数/星级上限/席位设置）；`account.broker` = `{key,name,abbr,star,starMax,intensity,crowd*,有效数值,features,privileges,progress,weekly,coupon,transfer,stats}`（「我的券商」卡片的全部数据源）；`account.marginCall` = 追保预警（跌破维持线但未到强平线，**零缓冲的券商恒为 null**）；`players[]` 带 `broker`/`brokerRank`（**组内名次**）/`star`；`brokerBoard[]` = 券商榜；`newsHints[]` = 泄露期模糊异动提示；`news[]` 里的 `early`/`masked` 标记 L2 客户在公开前拿到的条目（`masked` = 未满 4★，看不到方向）；`markets[].seats` = 席位榜/龙虎榜（当日各券商买卖额与净买入，涨跌超 ±7% 时附 `top.buy/sell`）；`markets[].depth.{bids,asks}[].brokers` = 该档占比最高的前 2 家券商；`markets[].trades[].buyBroker/sellBroker` = 逐笔买卖席位。

## 6. 数据库表（DDL 全在 `db.js`）

`meta(key,value)` · `accounts(name PK, is_npc, role, cash, order_frozen, short_margin, realized_pnl, initial_long, last_order_at, created_at, deposited,` **`broker, broker_changed_at, broker_since_day, broker_stats, free_reselect_used, coupon_used_day, free_interest_day`**`)` · **`stock_ledger(account, stock_id PK, lend_offered, lend_interest_earned, lend_interest_debt, lend_interest_paid, finance_interest_accrued)`** · `lots(account,stock_id,side,seq,qty,price,ts,reserved,margin,debt,principal)` · `orders(id PK, account, stock_id, ..., status)` · `trades(..., stock_id, ...,` **`broker, counter_broker`**`)` · `sessions(token PK, account)` · `market_state(stock_id PK, last_price, prev_close, ..., short_interest, outer_vol, outer_amt, inner_vol, inner_amt, ...)` · **`daily_bars(stock_id, day PK, open, high, low, close, volume, turnover, outer_vol, outer_amt, inner_vol, inner_amt, settled_at)`** · **`prices(stock_id, t PK, price, vol)`** · `auto_strategies(id PK, account, stock_id, type, ..., state)`。

- `accounts` 是**账户级**口径：现金、挂单冻结、空头保证金合计、已实现盈亏都是跨股票汇总的一个数（玩家只有一份钱）。
- `stock_ledger` 是**按股票**的账户明细：融券挂借量与各类利息累计。融券池每股一套，所以挂借量/欠息必须按股票记账，否则 A 股的欠息会被拿去补 B 股的出借人、撤借闸门也会串池。没有挂借也没有欠息的股票不写行（3160 个 NPC 账户各写 10 行空数据不值得）。
- `prices` 主键是 `(stock_id, t)`：每只股票一条独立分时序列，**大盘指数也用同一张表落盘**（`stock_id = 999999`），于是指数的分时能随重启续上。
- `auto_strategies.stock_id`：策略绑定在哪只股票上；`restore` 时股票已不在本局配置的策略会被跳过，不留孤儿策略。

`lots.principal` = 融资批次借入的本金（含开仓手续费），开仓时写入一次、**只随平仓按比例减少**（`consumeLong` 里与 `debt` 同比例扣）；`debt − principal` 就是这批已计但未还的利息。`debt` 参与权益计算，`principal` 纯展示。

`trades` 是**有界表**：每 tick 按 `t < now − persistence.tradeKeepMs`（默认 10 分钟）删除旧行，靠 `idx_trades_t` 做区间删除，稳态下删掉的行数≈本 tick 新写的行数（实测 8 ms/tick）。不裁的话 NPC 之间每 tick 的成交会让它无限膨胀（665 行/秒）。裁剪只影响「重启后」能看到多少历史——运行期玩家成交记录走内存（`acc.tradeHistory`，最多 100 条）、逐笔走内存 `market.trades`（500 条），都不受裁剪影响。

`daily_bars` 是**日线表**（2026-10-16 起）：主键 `(stock_id, day)`，一行 = K 线图上的一根蜡烛，`day` 就是交易日号（与顶栏「第 N 天」同一口径），大盘指数用同一张表（`stock_id = 999999`）。只在日终结算时写（每标的每天一行，`ON CONFLICT` 覆盖，重复结算不会追加第二行），量额与内外盘都是当日合计。上限 `market.dailyBarsKeep = 260` 根，内存与恢复条数同口径。**只有已收盘的 K 线进这张表**：当日那根还没定格，客户端拿实时行情自己拼，所以开局到第一次收盘之间图上只有一根「正在走」的蜡烛。

`lots` 的**批次数**也被刻意压住：NPC 账户在 `Market.execute` 之后调用 `Account.consolidate` 把本股批次合并成一条（数量加权均价）。不合并的话单账户能攒到 3700 条碎片批次，落盘每 tick 要整段重写 40 万行（实测 tick 3.5 秒）。玩家账户不合并，保留 FIFO 口径。

`stock_ledger` 里四个利息字段分工：`lend_interest_debt`（做空欠息）**参与权益计算**（是负债）；`lend_interest_earned` / `lend_interest_paid`（出借累计收入 / 做空累计已付）与 `finance_interest_accrued`（融资累计已计利息）都**只做展示**——钱早已在逐 tick 的现金流/负债里走完账，三者不重复扣减权益。恒等关系：做空累计产生额 = `lend_interest_paid` + `lend_interest_debt`。

**schema 版本 = 4**（券商与席位）。版本 2 及更早的旧档**直接拒绝启动**：`prices` 换过主键、融券从账户列搬到了按股票的表、`market_state` 又加了内外盘四列、`daily_bars` 是新表，这类改动无法用 `ALTER` 补出来，只能开新局。

**版本 3 → 4 是原地 ALTER 升级**（`db.js` 的 `MIGRATION_4`）：新增的 9 列全是**可空或带默认值**的新列，没有主键/表结构变更，所以不需要清库——**正在跑的那一局能原地升上来**。升级后老账号的 `broker` 为 `NULL`，表示"还没选过券商"，该玩家下次登录时会要求补选（§9 D2）。升级前写下的成交流水没有席位列，那段磁带的席位显示为空（已知且可接受）。`broker`/`broker_stats` 这些列**只对玩家有意义**：NPC 的券商是由账户名哈希派生的标签，`persist.writeAccount` 明确对 NPC 写 `NULL`（落盘会踩「NPC 逐 tick 标脏」的禁忌，也让存档里多出一份与账户名冗余、可能不一致的副本）。

**股东操作快照不落库**：`_holderSnapshots`（**`名字#股票`** → 快照数组）纯内存环形缓冲，每个 (账号, 股票) 留最近 `HOLDER_SNAPSHOT_LIMIT=30` 次操作快照，每份记当时持股前 `HOLDER_SNAPSHOT_ROWS=30` 名（含占比），重启清空——所以表结构没变，也不需要迁移。

## 7. 客户端（`Client/`）

- **通信**：无轮询（股东榜在前台时 5 秒刷新一次）。首屏 `GET /api/state` + `/api/sparks`（迷你走势）+ `/api/history?stock=`（当前股票分时）→ `EventSource('/api/events')` 每 700ms 全量重渲染；另 200ms UI 定时器只做倒计时/时钟等本地展示。localStorage：`gushen_name`、`gushen_token`、`gushen_stock`（上次看的股票）、`gushen_chart`（图表模式 分时/日线）。
- **视图**：主页（**大盘指数卡** + 行情列表（指数行 + 10 只股票，各带迷你走势）/资产/持仓/排行/消息）+ 交易终端（**股票切换栏** + 走势图：分时三带（价格+均价/成交量/MACD(12,26,9)）或**日线蜡烛图**（蜡烛+成交量+MA5/MA10）+ **资金指标条**、五档、逐笔、下单面板、8 个标签页）。
- **图表模式（分时 / 日线，2026-10-16 起）**：图表标题左侧两个按钮切 `chartMode`（`minute`/`day`，记在 `gushen_chart`）。`drawChart()` 只做分发，两套画法各自成函数（`drawMinuteChart` / `drawDayChart`），**十字光标与画法共用同一份布局**（`dayLayout`），改坐标只改一处。
  - **日线数据**：已收盘的 K 线走 `/api/daily`（按需拉，与分时同款 `dayLoaded` 集合），**当日那根由客户端用实时行情现拼**（`daySeriesOf` 拿 `state.day.day` + `markets[].open/high/low/last/volume`），所以它每帧都在动、不需要额外推送。
  - **缓存作废时机 = 跨度 + 夜间**：服务端下发的「交易日号 + 是否夜间」变了就重拉（`lastDayKey`）。**漏了夜间这一次会出真 bug**：收盘结算把当日量额清零，客户端若还拿着旧缓存，就会拼出一根零成交量的假当日 K 线，把服务端刚落下的真 K 线盖掉（实测夜间真的看到过）。
  - 日线画法：阳线红实体、阴线绿实体（与分时同一套 A 股配色），不足 5/10 根时不画对应均线；最后一根是「正在走」的当日蜡烛时在收盘价点一个空心圈；x 轴用交易日号（第 N 天）而不是时钟，与顶栏口径一致。
- **资金指标条 `#flowStrip`（2026-10-16 起）**：走势图下方常显一行——外盘（主动买）量/额、内盘（主动卖）量/额、**资金净流入**（±额，红涨绿跌）、外盘占比（%），下面一条红/绿占比条。数据全部来自 `markets[].flow`，**客户端不自己算内外盘**；当日无成交时占比显示 `--`、副标题显示「当日暂无成交」、占比条各半。占比条宽度用 CSSOM 写（`el.style.width`），**不在 HTML 里拼 `style=` 属性**（CSP 禁内联样式）。
- **多股票上下文**：`marketList()` 取全部行情、`curMarket()` 取当前看的标的（股票或指数）、`positionOf(stockId)` 取该股持仓切片、`histories`/`sparks` 两个 `Map<stockId, 序列>` 分别存完整分时与降采样走势（切股票时拉一次全量，之后靠 SSE 每帧追加）。**全量拉取要用 `histLoaded`（已拉过的标的）判断，不能用 `histories.has()`**——`onState` 每帧给全部标的追加点，第一帧过后每只股票都在 `histories` 里，用 `has()` 判断会让 `/api/history` 永远不被调用、分时图只剩本次会话的点。**指数是只读视图**：五档/逐笔为空、四个下单按钮禁用、提交按钮显示「指数不可交易」、预计金额/手续费/可交易显示 `--`。
- **交易操作**：四方向按钮（买开/卖平/卖开/买平）+ 融资勾选 + 撤单 + 挂借/撤借 + 加钱 + 自动化 CRUD，下单/挂借/建策略都带当前 `stockId`。无可借券源时开空按钮禁用。**同股多空互斥**：`directionLock()` 按「已成持仓 + 在途开仓委托」算出本股已占用的方向，反向开仓按钮禁用并给出原因（按钮 title + 面板里的 `#dirLock` 提示行），提交按钮也一并拦（`renderCooldown` 里判，避免被 200ms 的 tickUI 覆盖回可点），「全部」快捷填量同样归零——判定口径与服务端 `sideLock` 完全一致。「加钱」按钮跟随 `rules.deposit.enabled` 显隐。
- **持仓/委托/成交**：都按股票展开——持仓按「股票 × 方向」多行（服务端 `account.positions[]` 已是按股票切片），委托与成交表带「股票」列。资产区（总权益/可用/浮盈/持仓市值/保证金/各类利息）都是**账户级汇总**口径。
- **消息 tab**：有「全部 / 只看大盘 / 当前股票」三个过滤按钮；每条消息带标的标签（个股显示股票名，大盘消息显示「大盘」）+ **时段标签**（`session` 为盘前/午间/盘后时渲染 `10.5px` 描边小徽标，盘中与无 `session` 的老数据不渲染）。
- **杠杆利息展示**：下单面板分三处——①「杠杆利息」块**常显两行**（做多·融资 / 做空·融券，各显示 `x%/分` + 折算 `≈y%/日`，`minuteRate × 1440`），当前这笔真会借钱/借券时对应行高亮（买入开多且**勾了融资**、或卖出开空），裸空模式显示「裸空不计息」；②「预计利息」行按当前委托数量估算这次开杠杆的成本（`¥/分` + `≈¥/日`），融资按借入口径（`市值×(1−ratio) + 手续费`）、融券按借券市值，都乘当前分钟息——**与服务端逐 tick 摊息的基数同一口径**，不计息时整行隐藏；③融资勾选行的 tag 只留杠杆口径（`自备 50% · 最高2倍`），利率交给杠杆利息块，避免重复数字把标签挤换行。
- **持仓利息（资产区）**：`融资负债`（`financeDebt`，跨股票合计）拆成 `融资本金`（`financePrincipal`）与 `融资已计息`（`负债 − 本金`）两行，两者之和恒等于融资负债；`融资已计息` 的 tooltip 里给出**累计**口径 `financeInterest`（含平仓时已随批次还掉的）。空头侧是 `做空欠息`（按股票加总）+ `做空已付息`。再加一行 `持仓利息 x/分` = `融资负债 × 融资分钟息 + 空头市值 × 融券分钟息`。「融券」tab 是**按当前股票**的视角（该股池子 + 我在这只股票上的挂借）。
- **股东 tab**：**按需拉取**（`/api/holders?stock=`，进 tab / 切股票时拉，前台每 5 秒刷新）——10 只股票 × 前 30 名每 tick 全推会把 SSE 帧撑爆。表格两列变动——「较开服变动」相对开服建仓、「较上次操作」相对本账户在该股上最近一次操作快照，都按「占比百分点 + 股数」两行显示；算不出时显示 `--`（还没操作过）或 `新进`（当时未进快照前 30 名）。点任意一行弹窗看该股东的占比走势折线 + 最近若干次操作流水。
- **券商 UI（2026-10-16 起）**：四块，全部吃服务端下发的字段，**客户端不自己算券商规则**（算两遍必然与服务端漂移）：
  - **登录开户卡片墙**：登录弹层 = 昵称输入 + 六张券商卡片（图标 + 名称 + 人设 + 强项/代价 chip + 关键数值 + 拥挤度条 + 当周之星角标）。展示元数据走**公开的 `/api/brokers`**（登录前就要有），并在 `init()` 里先拉它再决定要不要弹登录。昵称输入框实时校验（中文/太短/数字开头给提示），**己存在的中文老账号仍放行**——服务端裁决，前端只做软提示。开户后卡片墙隐藏。
  - **主页「我的券商」卡**：图标/名称/星级（满级位占位变灰）/拥挤度/9 个有效数值格/特权清单（当前值 + 满额对照 + 解锁进度条）/下一星进度/每周之星/代价清单/转户按钮/免息券按钮。进度条宽度一律走 CSSOM（CSP 禁内联 style）。
  - **转户弹窗**：六张卡片，每张标「当前券商 / 免费重选 / 转户费 ¥N / 暂不可转（冷却中）」，可点的才挂事件；底部写明费用与"转户会清空两边星级与进度"。
  - **席位**：五档每档放**占比最高的前 2 家券商小图标**（`hover` 显全名与占比，**不带简称文字**——价格列太窄）；逐笔新增「买席 / 卖席」两列（图标 + 两字简称，**简称必须有**：招伤与东风的红和行情涨红同色，只靠颜色会误读）；新增「席位」tab = 席位榜（当日各券商买卖额/净买入/成交占比，自己的席位高亮）+ 涨跌超 ±7% 时展开的龙虎榜（买卖前五席位）。排行 tab 加「券商榜」（客户数/总权益/组内第一）与玩家行上的**组内名次**。
  - **追保预警横幅**：`account.marginCall` 有值时出现，文案带上券商（破维持线但未到强平线才有；**零缓冲的券商（天疯）恒为空**）。**泄露期异动提示**：`state.newsHints` 渲染成消息列表顶部的一条金色提示（不点方向/原因/是谁）；消息列表里 L2 提前拿到的条目标「提前」（5★ 带方向）或「未公开」（未满 4★，`masked`）。
  - **图标规格**：`/img/broker-<key>.png`（1024 原图，只用于卡片墙与「我的券商」卡）与 `/img/broker-<key>-96.png`（96px 缩略图，五档/逐笔/排行榜这些高频位置）。**高频位置别引用原图**（原图合计 2786 KB vs 缩略图 51 KB）。服务端按 key 白名单托管，不做目录直出。
  - **布局约束**：逐笔是 6 列（时间/价格/量/方向/买席/卖席），所以 `.main` 的右栏宽度是 **300px**（264px 会把表头挤换行）；窄屏媒体查询里那条 `.tape-head, .tape-row` 的栅格也必须同步成 6 列。
- **安全约定**：CSP 无 `unsafe-inline`——**app.js 严禁内联 `style=` 属性**，样式写 style.css 用 class；服务端字符串插 HTML 前必须过 `esc()`。
- **视觉**：深色终端 `#0b0e14`，涨红跌绿（A 股配色），等宽数字，≤860px 移动端适配。
- **交易日 UI（2026-10-16 起）**：阶段一律吃服务端下发的 `state.day`，**客户端不自己算阶段**（客户端算的话一旦本机时钟偏了或掉线重连，横幅、倒计时与真实撮合窗口就会错位）。四块 UI：
  - **顶栏徽标 `#dayChip`**：`第 N 天 · 阶段名 · 倒计时`，竞价加金色/蓝色强调、休市降透明度。**顶栏时钟改成显示游戏内真实交易时刻**（`renderClock()`：`gameClockNow()` 走通显示 `09:23:41`，无 `day` 段则退回服务器时间）。
  - **阶段横幅 `#dayBanner`**（复用停牌横幅的样式族）：竞价段显示「虚拟成交价 xx · 可成交 N 股」+「距不可撤单 N 秒」；午休/夜间显示「午间休市，13:00 恢复交易」/「已收盘结算，未成交委托按当日失效」+ 恢复倒计时；**连续竞价时段整条隐藏**。
  - **盘口虚拟成交价条 `#auctionStrip`**（五档上方）：只在竞价段显示，`虚拟开盘价 / 虚拟收盘价 + 可成交量`，无交叉盘口时显示 `-- / 无交叉盘口`。
  - **下单面板 `#sessionNote` + 四方向按钮 + 提交按钮**：非交易时段（午休/夜间）一律禁用并给出原因（`renderCooldown()` 里判——它每 200ms 重写 `disabled`，只写在 `renderOrderPanel` 里会被覆盖回可点）。
  - **倒计时与游戏内时钟按本机流逝平滑推进**（`stateDrift()` = 距上一帧 state 的毫秒数，与冷却同口径，本机时钟偏了也不受影响）。`gameClockNow()` 用「当前 `gameClockMs` − 已走完的进度」**反推阶段起点**再按比例推进，**不能直接在 `gameClockMs` 上加漂移量**——那样漂移超过阶段末尾时会多算一整段跨度（实测 09:18:48 漂成 09:28:48，本该夹在 09:25:00）。
  - **分时成交量柱的日切检测**：收盘结算把当日成交量归零，`vol[i] − vol[i-1]` 会出负差（一根柱子凭空消失、下一根从零重新长）。检测到 `vol[i] < vol[i-1]` 就当成"新的一天"，用 `vol[i]` 本身当这一根的增量——开盘竞价那一笔巨量正好一根柱画完。
- **布局坑**：`.main` 必须 `grid-template-rows: minmax(0,1fr)` + overflow hidden，否则画布把行撑爆导致分时图溢出。指数卡（`.index-card`）必须显式 `flex-direction: row`——`.panel` 默认是列向 flex，不覆盖就会把卡竖着排。

  - **④ 竞价参与度实验（做了但已撤回，负结果）**：假设"竞价簿两侧不交叉所以没量"，给 NPC 加了"竞价里按情绪下一侧**可成交单**（买单挂到中枢之上、卖单之下）"的开关。实测**零收益**：打开/关闭两种配置下开盘竞价均量都是 **22~24 万股/股·日**、占比都是 0.9%（用"运行时改配置"的对照脚本同参数对跑）。原因：**竞价簿本来就是交叉的**——NPC 报价中枢有情绪离散度（`sentiment × centerShift` 可达 ±0.3%，远大于点差），实测撮合前最优买 20.16 已经高于最优卖 19.92，最大成交量原则早就有量可撮。没有实测收益就撤（config 与 `requote` 全部还原）。
  - **⑤ 换手率：本轮最大的发现**（`day-probe` 新增指标）。游戏**日换手率中位 37~46%**（日均成交 2500~3000 万股），真实十只港股 **0.98%**——**差 38 倍**。机制：NPC 每 tick 双边报价、中枢又有情绪离散度，高估值 NPC 的买单持续打穿低估值 NPC 的卖单，每一轮重报价都在成交。它同时解释了：为什么"竞价占全天一成"做不到（分母被撑大 38 倍，而竞价绝对量本身与真实同量级）、以及买盘侧为什么脆弱（补款总容量约 790k 元 ≈ 3.9 万股，卖压几个 tick 就吃光，而日均成交 2670 万股）。**要动它必须单开一轮**（牵动挂单量/重报价频率/点差三处，需要新的"换手率"红线来守）。
