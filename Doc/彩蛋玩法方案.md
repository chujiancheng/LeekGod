# 我是股神 · 彩蛋玩法方案

> 状态：**P0（MVP）已实现**（2026-10-16）。实现口径与本文的差异见 §13；P1/P2/P3 仍未实现。
> 相关文档：`券商方案.md`（§7 趣味彩蛋 / §5.4 声誉星级）、`消息分层方案.md`、`项目知识.md`（§3.3 是实现的权威口径）。

## 0. 一句话

给玩家的资产曲线装上一条**情绪轨**：赚到多少、亏到多少、什么时候被强平——不再只是一串跳动的数字，而会有**称号、演出、股神猫的一句台词，偶尔一张免息券**。

---

## 1. 定位与边界

| 做 | 不做 |
|---|---|
| 触发判定（服务端，权威） | 新交易机制（不改撮合 / 定价 / 风控任何一行） |
| 事件下发（复用现有 SSE 全量快照） | 不改 `market.place` / `npc.step` 的行为 |
| 演出（客户端 toast / 横幅 / 全屏） | 不给现金、不给额度、不给消息提前量 |
| 称号 + 成就墙 + 「股神墙」 | 不合并券商星级的判定口径 |
| 象征性奖励（每日免息券，复用现成字段） | 不碰 tape / 消息池 / 排行榜排序 |

**核心纪律：彩蛋是「观测层」，不是「机制层」。** 所有触发一律**只读**账户快照，绝不回写任何交易状态。任何一个彩蛋玩法的失败，都不应该能影响一次撮合的结果。

## 2. 判定口径（本方案最关键的一节）

### 2.1 用哪个数？

| 候选 | 问题 | 结论 |
|---|---|---|
| `equity`（组合权益，含浮盈浮亏） | 每个 tick 都在跳，"闪一下又回去"也会触发 | **只用于瞬时演出**，不给奖励 |
| `equity` 的**收盘结算值** | 一天一个数、顺序确定、可复现 | **所有硬门槛都用它** |
| `realizedPnL`（已实现盈亏） | 只反映平仓，长线不卖永远是 0 | 只给"落袋为安"类彩蛋 |
| `deposited`（终身加钱额） | 加钱已屏蔽，且靠加钱"买"到里程碑很没面子 | **不计入** |

> **为什么硬门槛必须走收盘**：项目已经有「天」（620 秒切 6 段，`daycycle.js`）。收盘结算是天然的采样点——一天一次、进程重启可复现。盘中触及只播演出，避免"差 1 块钱闪过去又回来"这种闹剧。

### 2.2 两条独立的尺子（**不要混**）

| 尺子 | 看什么 | 用在哪 |
|---|---|---|
| **绝对水位** | `dayCloseEquity` 相对初始 100 万 | 发家线（越赚越有排面） |
| **相对回撤** | `1 − dayCloseEquity / peakEquity` | 崩盘线（真实体感） |

**两条都必须有**：一个从 100 万做到 5000 万、又跌回 1000 万的玩家，绝对水位仍是 **+900%**（发家线全亮），但回撤是 **−80%**——那才是他真实的痛。只用绝对水位会漏掉所有大资金的崩盘；只用回撤会漏掉"从没赚过、一路阴跌"的玩家。

### 2.3 口径纪律

- 权益**必须**与服务端同一个函数取（`Game.equityOf` / `stateFor` 里的 `equity`），**前端不许自己重算**——多头市值 / 融资负债 / 欠息的加减顺序错一处，两边就差几毛钱，然后玩家投诉"我明明够 500 万了为什么不弹"。
- 隐藏量 `fairValue` / `fund` / `regime` / `force` **不得**参与任何彩蛋判定或文案（项目规定它们绝不下发客户端）。
- **NPC 全部不参与**（10 股 × 316 = 3160 个账户）。彩蛋是玩家专属；NPC 逐 tick 标脏是项目明令禁忌。

### 2.4 需要新增的账户记录（**玩家专属，NPC 不落**）

| 字段 | 含义 | 更新时机 |
|---|---|---|
| `peakEquity` | 历史最高**收盘**权益（水位线，单调不减） | 收盘结算 |
| `peakIntraday` | 历史最高**盘中**权益（只喂瞬时演出） | 每 tick（内存，不落盘） |
| `dayOpenEquity` | 当日起始权益（算当日收益） | 开盘 |
| `maxDrawdown` | 历史最大回撤（相对 `peakEquity`） | 收盘结算 |
| `fired` | 已触发的彩蛋 id 集合（幂等键） | 触发时 |
| `titles` | 已获得的称号 | 触发时 |
| `liqTotal` / `liqStreak` | 累计强平次数 / 连续爆仓交易日 | 强平时 / 结算时 |
| `greenStreak` / `redStreak` | 连续盈利 / 连续亏损交易日 | 结算时 |

> "首次做空就赚钱"这类需要动作埋点的，复用现有 `tradeHistory`（已带 `action`：`buy_open / sell_open / buy_close / sell_close`）与 `realizedPnL` 差分即可，不必新造事件流。

## 3. 彩蛋清单

四族：**A 发家 / B 崩盘 / C 爆仓 / D 行为**。
演出分级：**L1** 右下角 toast（复用现有 `toast()`）· **L2** 顶部横幅 + 猫头像 · **L3** 全屏过场（需点掉）· **L4** = L3 + 全服广播。

### 3.1 A 族 · 发家线（收盘权益，向上）

档距按**对数**排（约 ×1.5~1.7 一档）。按当前行情标定（日收益中位 ≈2.8% / std ≈4.4%）：**100 万 → 1000 万 ≈ 83 个交易日 ≈ 14 小时**（不加杠杆、不复利中断），**100 万 → 1 亿 ≈ 165 个交易日 ≈ 28 小时**。

| ID | 收盘权益 ≥ | 名称 | 演出 | 稀有度 |
|---|---|---|---|---|
| A01 | 110 万 | 保本出关 | L1 | 普通 |
| A02 | 150 万 | 五十个点 | L1 | 普通 |
| A03 | 200 万 | 翻倍人生 | L2 | 普通 |
| A04 | 300 万 | 三百万 | L2 | 普通 |
| A05 | 500 万 | 半个千万 | L2 | 稀有 |
| A06 | 800 万 | 八百万 | L2 | 稀有 |
| A07 | 1000 万 | **千万身家** | L3 | 稀有 |
| A08 | 2000 万 | 两千万 | L2 | 稀有 |
| A09 | 5000 万 | 准亿 | L3 | 史诗 |
| A10 | 1 亿 | **一个小目标** | L4 | 史诗 |
| A11 | 3 亿 | 三个小目标 | L4 | 传说 |
| A12 | 10 亿 | **封神**（你就是股神） | L4 | 传说 |

- **1 亿 = 「一个小目标」**是全局长线主目标：加钱已屏蔽、终身加钱上限 1 亿，**只能靠交易赚**。
- 传说档带**全服广播**，并把首次达成者**永久刻进「股神墙」**（见 §5）。

**B1 绝对水位跌破**（`dayCloseEquity`）：

| ID | 跌破 | 名称 | 演出 | 稀有度 |
|---|---|---|---|---|
| B1-01 | 90 万 | 出师不利 | L1 | 普通 |
| B1-02 | 70 万 | 七折促销 | L1 | 普通 |
| B1-03 | 50 万 | **腰斩** | L2 | 稀有 |
| B1-04 | 30 万 | 三折清仓 | L2 | 稀有 |
| B1-05 | 10 万 | 回到起点（方向反了） | L3 | 史诗 |
| B1-06 | 1 万 | 一万元户 | L3 | 史诗 |
| B1-07 | 1000 元 | 精确爆仓预备役 | L3 | 史诗 |
| B1-08 | ≤ 0 | **倒欠券商** | L4 | 传说 |

**B2 相对峰值回撤**（`1 − dayCloseEquity / peakEquity`）：

| ID | 回撤 ≥ | 名称 | 演出 | 稀有度 |
|---|---|---|---|---|
| B2-01 | 30% | 回吐 | L1 | 普通 |
| B2-02 | 50% | **一夜回到解放前** | L2 | 稀有 |
| B2-03 | 70% | 财富蒸发术 | L3 | 史诗 |
| B2-04 | 90% | 从 Billionaire 到 Beggar | L4 | 传说 |

> **重新武装（rearm）**：B2 触发后必须**回到距峰值 10% 以内**才能再次触发同级。否则在谷底反复震荡会不停播报，从彩蛋变成骚扰。
>
> **⚠️ 2026-10-17 修正：这条 rearm 机制已删除。** 理由：`fired` 本身就是**永久幂等键**（§2.4），同一档重复播报根本不可能发生，"防骚扰"这个目的已经由它达成；而"整族上闸"唯一可观测的效果是把**首次越过的更高档**一起压掉——峰值 1000 万跌到 450 万（回撤 55%）发掉 B2-01+B2-02 之后，再跌到 200 万（回撤 80%）**不会发 B2-03**，于是持续下跌只剩第一档、B2-04（90% · 传说档）几乎不可达。现在 B2 是一把正常的阶梯：**越过哪档就发哪档，每档一次**。若日后想回到"一段下跌只播一次（当时越过的最高档）"，就是把 `drawdownArmed` 加回来。

### 3.3 C 族 · 爆仓线

> ⚠️ **先看清现实**：2026-10-16 把日波动收敛到真实的约 1.5 倍后，**强平从 66.7 次/天 掉到 0 次/天**（见 `项目知识.md` §3 变更记录）。爆仓在当前参数下是**稀有事件**——这既是好事（触发时珍贵），也是风险（可能一整局没人见过）。

**已拍板（§12 D3）：不为救爆仓频率改风控参数。** C 族的立族之本改成一条完整的**风险体验链**——**预警（C00）→ 擦边（C01）→ 落地（C02~C07）**。整局没人爆仓时，「天台初体验」反而是一枚真·勋章。

## 4. 事件下发协议（最小侵入）

### 4.1 服务端

在 `stateFor()` 的 `account` 段加一个 `events`：

```js
account.events = {
  seq: 128,                    // 单调自增，客户端记住 lastSeq
  pending: [                   // 尚未播出的事件（≤ eventQueueMax，超出丢旧）
    { id: 'A05', seq: 128, day: 7, t: 1729..., kind: 'wealth',
      level: 'L2', rarity: 'rare', title: '半个千万',
      text: '...', mascot: 'smug' }
  ],
  titles: ['半个千万', '擦边过关'],
  peakEquity: 5230000,
  drawdown: 0.06,
  progress: { nextWealth: { id: 'A06', equity: 8000000, need: 2770000 } }  // 下一个目标进度
};
```

- 事件在**产生点**（收盘结算 / 强平 / 盘中演出）push 进 `acc.pendingEvents`（内存队列）；客户端每帧拿走 `pending`，靠 **`seq`** 去重。
- **为什么用 `seq` 而不是数组长度**：现有 `liquidations` 的做法是"比长度"，而它在 20 条处会截断——长度不再增长时新事件就静默丢了。`seq` 单调且不截断。
- `progress` 是顺手送的大礼：主页可以直接画"距离 800 万还差 277 万"的进度条，彩蛋就从"随机惊喜"变成"可追求的目标"。

### 4.2 客户端

复用现有 `toast()`（L1）与横幅容器，新增一个 `playEvent(ev)`：

| 级别 | 表现 |
|---|---|
| L1 | `toast(text, 'egg')`，2.5s 自动消失 |
| L2 | 顶部滑入横幅：猫头像 + 稀有度配色 + 打字机文案，4s 自动收 |
| L3 | 全屏遮罩 + 股神猫大图 + 文案 + 关闭按钮 |
| L4 | 同 L3，另加一行「【全服】XX 达成 XXX」推给所有在线玩家 |

- **队列串行**：同一帧来多条时按 `rarity` 降序排队，避免几个横幅叠在一起。
- **刷新不重播**：`localStorage` 记 `gushen_event_seq`；首次进入（无该键）= 从当前 `seq` 起步，**不补播历史**。
- **落点要让位（2026-10-17 实现口径，是实测出来的）**：屏幕顶部那块位置有三个主人。① 顶栏下面那三条**状态横幅**（停牌 / 交易日 / 追保预警）在文档流里——横幅得按它们实测的下沿决定自己的 `top`（没有它们时才是 60px），否则**追保预警这种必须被看见的提示会被盖住**，而它和 C 族彩蛋本来就是同时出现的；② toast 容器（`top: 68px` / `z-index: 90`）与横幅（`z-index: 95`）几乎完全重合，而 L1 是"先 toast、再弹横幅"的顺序——不让位的话**玩家看不到自己那条 L1 事件**，同时段的成交 / 爆仓提醒也一起没了。位置一律走 CSSOM（CSP 无 `unsafe-inline`），改 `top` 不引起重排。
- **自动收起要能取消**：手动点「收起」时必须撤掉这一条的自动收起定时器，否则它会在几秒后把**下一条**横幅提前掐掉并推进队列。

### 4.3 落盘

- **MVP**：`accounts` 加一列 `milestones TEXT`（JSON：`{fired, titles, peakEquity, maxDrawdown, liqTotal, liqStreak, greenStreak, redStreak}`）。
  - `SCHEMA_VERSION` 4 → **5**；老档 `ALTER TABLE` 补列、默认 `NULL`。
  - 老档首次初始化时 **`peakEquity` 设为当前权益**——设成 0 会让老玩家一进来就"回撤 100%"。
  - **只有玩家账户写这列**，与券商那几列同规矩（`db.js` 里明确写了 NPC 不落券商），避免逐 tick 标脏。
- **P2**：独立表 `account_events(account, id, day, t, payload)` 存完整履历（成就墙时间线要按时间回溯）。MVP 不做。

## 5. 称号与「股神墙」

- **称号**：每个彩蛋可给一个称号，稀有度四档：普通(灰) / 稀有(蓝) / 史诗(紫) / 传说(金)。
- **展示位**：主页"我的卡"、排行榜（附加列，**不参与排序**）、股东榜、席位榜（若实现）。
- **同时只挂 1 个**（玩家自选），避免头顶挂一长串。
- **股神墙**（**P1**，已拍板从 P2 提前）：全服**首次**达成 A10 / A11 / A12 / B1-08 / C05 的玩家永久记名 + 达成日期。解决"单机没有对手"的问题——**跟历史比、跟首达比**；实现成本只是一张表 + 5 个 key，是性价比最高的长期目标装置。
- **功德碑与耻辱柱并排**：股神墙刻意把「首个 1 亿」和「首个倒欠券商」挂到同一面墙上——**亏得很有排面，本身就是乐趣**。
- **负面称号的体面**：爆仓王这类"负面传说"称号有意做得**很帅**（金色、戴王冠 / 戴钢盔的猫），玩家才愿意挂出去。
- **负面事件广播（已拍板：默认开，留逃生门）**：B1-08「倒欠券商」与 C05「爆仓王」**默认全服广播**（耻辱感是这类游戏的乐趣来源，参见 `券商方案.md` 的"杀人诛心"），但 ① 文案走**「敬礼」口径**而非嘲笑（"本服第 1 位亲手把自己打进负资产的勇士已诞生——致敬"）；② 给玩家一个**本地开关** `gushen_egg_broadcast_neg`（默认开）关掉自己的负面广播——没这道门，社死会直接变成弃游。

## 6. 文案与演出基调

三档基调，`config.milestones.tone` 切换：

| 基调 | 赚钱类 | 亏钱类 | 爆仓类 |
|---|---|---|---|
| `savage`（毒舌，**默认**） | "哦，赚了？运气不错。" | "关灯吃面，猫也在陪你。" | "天台排队，前面还有 3 个。" |
| `gentle` | "不错，稳住别飘。" | "回撤是交易的一部分。" | "券商帮你止损了，别难过。" |
| `deadpan`（面瘫） | "权益 +10%。" | "权益 −50%。" | "已强制平仓。" |

## 7. 奖励策略（**平衡红线**）

**主奖励 = 称号 + 演出 + 猫的一句台词**（零数值影响）。

**唯一允许的实质奖励：每日免息券**——复用**已有**的 `couponUsedDay` / `freeInterestDay` 字段（`db.js` / `store.js` 里已存在），不新造任何数值系统。

**已拍板（§12 D5）的收窄规则——只给「因果自洽」的族**：

| 族 | 给不给券 | 理由 |
|---|---|---|
| C 族（C02 首次爆仓 / C03 / C04 连环 / C06 打不死的小强） | ✅ 给 1 张 | 券降低的是**杠杆成本**，正好对冲"因为上杠杆而亏"这件事 |
| B2 回撤 ≥ 50% | ✅ 给 1 张 | 同上：大回撤多半伴随高杠杆 |
| A 族（发家线） | ❌ 不给 | 赚钱的人不需要安慰；发给赢家就是免费午餐，破坏平衡 |
| D 族（行为） | ❌ 不给 | 与风险无关，发了会变成刷券套路 |

- 上限沿用现成限制：**每天最多 1 张**、**每类彩蛋只给一次**。

**明确禁止**：

- ❌ 给现金 / 加钱额度 / 融资额度加成 → 直接破坏平衡与 `券商方案.md` §8 的校验清单。
- ❌ 给消息提前量 → 会改变 `消息分层方案.md` 的信息不对称结构。
- ❌ 撤单费减免 / 降低保证金率 → 会动用户确认过的风控参数。

## 11. 守门测试清单（实现前必过）

1. **幂等**：同一 `id` 只触发一次；重启后不重放（`fired` 落盘生效）。
2. **老档兼容**：无 `milestones` 列的档能正常启动；首日**不**把 `peakEquity` 初始化为 0（否则立刻报"回撤 100%"），而是初始化为当前权益。
3. **NPC 不落盘**：跑 3000 tick × 10 股，`accounts.milestones` 非空的行**全部是玩家**；NPC 行不受影响。
4. **口径一致**：判定用的 `equity` 与 `stateFor` 下发的是**同一个数**（同一函数取），断言二者相等。
5. **结算兜底路径**：人为跳到跨天（模拟休眠 / 长 GC），`ensureDaySettled` 那条路径也要判一次硬门槛。
6. **回撤单调与阶梯**：`peakEquity` 只增不减；B2 **越过哪档发哪档**、每档一次（不重复播报），一段持续下跌里 30% → 50% → 70% → 90% 应依次点亮（**早期设计的"整族上闸 + rearm"已于 2026-10-17 删除**，见 §3.2）。
7. **不污染消息池**：跑若干天后 `news` 列表里**不出现**彩蛋条目；`pickText` 的池去重行为与改动前逐位一致。
8. **性能**：判定 O(1)/玩家，**不新增逐 tick 全账户扫描**（3160 个 NPC 一个都不扫）；`events` 段体积有上限。
9. **刷新不重播**：`localStorage` 的 `gushen_event_seq` 生效；首次进入不补播历史事件；**换号 / 服务端 `seq` 回退时水位要跟着重置**（否则新账号的事件全被挡住）。
10. **回归**：`npm test` 全绿（现有 900+ 条不许红）；验收一律用 `PERSIST_FILE` 指向临时库（见 `AGENTS.md`）。

## 12. 关键决策（已拍板）

> 原「待拍板 6 项」已由 AI 全权拍板，实现时按此执行；数值可在调参阶段微调，结论不再重开。

**D1 A 族档数：保留 12 档，且刻意「前密后疏」。**
- 100 万 → 800 万 用 ×1.3~1.6 的密档（A01~A06）：新玩家需要高频正反馈才留得住。
- 1000 万 → 10 亿 拉成 ×2~3.3 的疏档（A07~A12）：后期要的是"大目标"，不是"连续的小惊喜"。
- 「一个小目标 = 1 亿」保留为唯一的里程碑级目标（按当前行情约 165 个交易日 ≈ 28 小时；加钱已屏蔽，只能靠交易赚）。**不加"新手保护档"、不因难度下调**——长线目标的价值就在于它不容易。

**D2 剧透基调：默认 `savage`，加一条「软着陆规则」。**
- 全局默认毒舌，与项目整体语气一致。
- 权益**跌破 10 万**后，崩盘 / 爆仓类文案**自动降级 `gentle`**，与 `tone` 设置无关。嘲讽的甜区是"还输得起的人"；亏到只剩一成本来就难受，再嘲讽就是劝退。
- 玩家本地可覆盖（`gushen_egg_tone`）。

**D3 爆仓彩蛋：不调风控参数，改用「风险体验链」。**
- **不动** `margin.maintenance` / `margin.ratio` / 强平滑点。理由：① 这是用户确认过的规则；② 强平 0 次/天的真因是"波动按真实口径收敛"这个**明确的设计目标**，把它放回去救彩蛋频率是本末倒置；③ 稀有本身就有价值。
- C 族立族之本改为三段链：**预警 C00（风险度 ≥80%）→ 擦边 C01（≥95% 未爆）→ 落地 C02~C07**。
- **给后人留的梯子（本轮不做）**：若将来确实要恢复爆仓频率，**优先调 `margin.maintenance`（30% → 40~45%）**，不要动 `trend.bands`——前者只影响杠杆账户的强平线；后者会连带改日波动、贴板率与换手率，还要重跑 `day-probe` 全套红线。

**D4 负面事件广播：默认开，但用「敬礼」口径 + 留逃生门。**
- B1-08「倒欠券商」与 C05「爆仓王」默认全服广播。耻辱感是乐趣来源，不给广播等于把最有趣的彩蛋藏起来。
- 文案走**致敬**口径，不做人身嘲讽；并给玩家本地开关 `gushen_egg_broadcast_neg`（默认开）关掉自己的负面广播——没这道门，社死会直接变成弃游。

**D5 免息券奖励：给，但只给「因果自洽」的族。**
- 只给 **C 族（首次 / 连环爆仓、打不死的小强）与 B2 回撤 ≥ 50%**——券降低的是杠杆成本，正好对冲"因为上杠杆而亏"。
- **A 族（发家线）一张不给**：发给赢家是免费午餐，破坏平衡。
- 上限沿用现成限制：每天最多 1 张、每类彩蛋只给一次。

**D6 股神墙：做，并从 P2 提前到 P1。**
- 全服**首次**达成 A10 / A11 / A12 / B1-08 / C05 者永久记名 + 达成日期。
- 单机游戏最缺"对手"，首达记名是最便宜的长期目标装置（一张表 + 5 个 key）。
- **功德碑与耻辱柱并排**：首个 1 亿和首个倒欠券商挂同一面墙。

**D7 口径红线（不可动摇，复述一遍便于实现时自检）。**
- 硬门槛**只认收盘结算权益**；盘中只做演出、不给奖励。
- 权益必须与服务端**同一函数**取，前端不许重算。
- 彩蛋**只读快照、不回写交易状态**；NPC 一律不参与、不落盘。
- 与 `券商方案.md` 声誉星级**口径独立，禁止合并**。
- 广播**不进 `news` 列表、不参与 `recentByPool`**。

## 13. P0 实现说明（与本文的偏差）

实现落在 `Server/src/milestones.js`（判定内核）+ `game.js`/`market.js`/`persist.js`/`db.js` 接线 + `Client/{index.html,app.js,style.css}` 演出。**权威口径记在 `项目知识.md` §3.3**，这节只列"实现与本文不一样的地方"，免得后来人照着本文去改代码。

| 本文写的 | 实际实现 | 为什么 |
|---|---|---|
| §4.1 `account.events = {seq, pending[], …}` | `account.events = {enabled, seq, events[], count, titles[], title, peakEquity, drawdown, maxDrawdown, progress}` | 没有 ack 接口，"未读队列"这个语义立不住；改叫 `events`（**滚动窗口**，超出 `eventQueueMax` 丢旧）。多给了 `enabled`/`count`/`title`/`maxDrawdown`——卡片要用的都顺手给了 |
| §4.1 `titles: ['半个千万', …]` | `titles: [{id, title, rarity, level, day}, …]` + `title`（当前展示的那一个） | 只给字符串的话前端画不出稀有度配色，也选不出"当前称号" |

| §2.4 需要 `peakIntraday` / `dayOpenEquity` / `greenStreak` / `redStreak` / `liqStreak` / `dayOpenEquity` | **都没做** | 它们服务的是盘中演出与 D 族（P2）。P0 里加了就是没人读的死字段——本项目在券商那轮已经吃过"配了没人读"的亏 |
| §3.3 C 族含 C03~C07 | **只做 C00 / C01 / C02** | 与 §9 的 P0 清单一致（C00 是 §12 D3 拍板后补的"预警"环）。C03~C07 需要跨日强平计数与"不下单天数"埋点，属 P2 |
| §4.3 `milestones TEXT` 里存 `{fired, titles, peakEquity, maxDrawdown, liqTotal, liqStreak, greenStreak, redStreak}` | 存 `{seq, fired, titles, peakEquity, maxDrawdown, dayEvaluated, liqDay}` | ① **`seq` 必须落盘**——重启后从 0 重计数会让客户端存着的 `lastSeq` 把新事件永远挡住；② `dayEvaluated`（同日只评估一次的幂等键）是必须落盘的；③ `liqDay`（C01「未爆」的判据，2026-10-17 加）也要落盘，否则重启后当天已爆的账户会再收一条"擦边过关"；④ 后面那几个计数器 P0 用不到 |
