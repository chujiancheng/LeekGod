## 0. 与方案一的关系

方案一的 L2 是「每池抽 56 人出去串门」，本质还是**池子思维**——剩余 260 人仍然是"做什么的"。

方案二要解决的是另一件事：**现实市场里没有「每股 316 个专属玩家」这回事**。有的只是：

- 一群普通投资者，各看各的、各买各的；
- 一批做市商，负责把盘口铺开。

所以方案二把角色彻底分开：

| 现在 | 方案二 |
|---|---|
| 每只股 316 个账户，既做市又投机，名字叫「大米·游资1」 | **3160 个独立投资者**（有名有姓有城市）+ **每股票 6 家券商自营做市**（共 60 个） |
| 账户归属靠名字前缀 `大米·` | 归属显式存库（`home_stock`），名字与归属彻底解耦 |
| 机构/游资/大户/中户/散户 = 一只股票上的五档 | 五类**投资者性格**，跨股票通用 |

但要动的东西比方案一多。不过因为**不用背兼容包袱**，实际工期 ≈3.5 天（方案一 2.5 天里有一半是迁移与回填）。

好消息：**不需要重写做市引擎**。`NpcManager` 的 `requote` / `tryAggressive` / `thinBookFloor` 那套逻辑全部保留，只是把它的 `npcs` 从 316 个换成 6 个做市商。这比「从零重写一套组合投资者」便宜一半以上。

## 1. 名字：账号与展示名分家

这是整个方案的地基。

### 1.1 现状的问题

```
acc.name = '大米·游资1'
```

一个字段同时承担三件事：**唯一键、所属股票、人类可读的名字**。所以名字必须带股票前缀，而带前缀就等于告诉玩家"这个 NPC 是给大米集团配的"——一假露全假。

### 1.2 拆成两个字段

`accounts` 表已经有 `nick` 列（玩家昵称用，NPC 一直是 NULL），直接拿来用：

| 字段 | 值 | 用途 |
|---|---|---|
| `name` | `npc-0312` | 主键、流水引用、券商/消息的哈希种子 |
| `nick` | `曹俊（杭州）` | **只有这个会被玩家看见** |

`Game.displayName()` 本来就是 `acc.nick || acc.name`（`game.js:988`），所以股东榜、成交回报、盘口挂单显示**一行代码都不用改**。

### 1.3 五类身份的命名规则

| 类型 | 数量/股 | 规则 | 样例 |
|---|---|---|---|
| 机构 | 10 | 「双字 + 双字 + 机构后缀」，后缀分资本/资产/投资/私募/资管/基金/创投/控股 | 望元私募、沐信资产、磐石创投、九泽资产 |
| 游资 | 6 | 「江湖标签 · 绰号」，标签是地域帮派/打法 | 宁波桑田路·孙叔、涨停敢死队·赵哥、成都系·徐总 |
| 大户 | 20 | 姓名（60% 三字）+（城市） | 冯志（济南）、王婷珊（福州）、崔强峰（西安） |
| 中户 | 60 | 同上 | 蔡萍（厦门）、程超航（福州）、郑露雅（常州） |
| 散户 | 2200 | 同上 | 董航（广州）、于艳（佛山）、黄梅（济南） |

生成器 = `src/identity.js`，种子是 `类型 + 序号`，**确定性**（重启后同名同人）：

```
h(seed)  = FNV-1a + murmur3 finalizer（avalanche 后相邻 seed 不会撞桶）
姓名     = 姓(60) × 名(42~46 单字/双字) × 性别(62% 男) × 城市(28)
```

实测 2200 个散户里重名 136 个（6.1%），最高重复 3 次 —— **这个重名率恰好真实**（现实里"张伟"有几十万），而且展示名带城市，视觉上不冲突。账号唯一由 `npc-xxxx` 保证。

### 1.4 做市商的名字

用**券商自营席位**，项目已有 6 家券商（`broker.js`），天然对得上：

```
钟信自营　华泰自营　招商自营　天疯自营　嗨通自营　东风自营
```

玩家在盘口看到「钟信自营 卖1 5000 手」，立刻就懂——这是券商自营盘在做市，不是某个散户在挂单。比现在「大米·机构3」真实一个数量级。

## 2. 归属显式化（不迁这一步，名字改不了）

### 2.1 schema 一次改到位

不用迁移脚本，直接改 `db.js` 的 DDL（`SCHEMA_VERSION` 提到 9，反正库是新建的）：

```sql
-- accounts：多加两列，NPC 的身份完整存库，不再靠解析名字
home_stock  TEXT,     -- NPC 的"常住"股票（只表示初始建仓在哪，不限制它买什么）；玩家 NULL

-- stock_ledger：初始持仓按股票精确记账（替代 accounts.initial_long 那个单值）

-- makers：做市商单独一张表也比混在 accounts 里清楚，但混着更省事（见 §3）
```

## 3. 做市商独立（"更贴近现实"的另一半）

### 3.1 现在的问题

`requote()` 让 **316 个散户/中户/大户各挂一张买单一张卖单**来铺满五档。这是为了"盘口有人"而硬造出来的设定——现实中散户不会 24 小时双边报价。

### 3.2 改法

```
每股票：NpcManager（定价脑不变）
        └─ npcs: 6 家券商自营（role = 'mm'）
                 ├─ 资金独立注入（不再来自投资者池）
                 ├─ 每 tick 双边挂 2~3 档，单笔量 = 原 requoteQty × 50
                 └─ 不参与投资者决策，只负责报价 + 承接
3160 个投资者：完全独立，由 InvestorDesk 驱动
```

**保留的**：`updateFairValue` / `updateTrend` / `updateCycle` / `updateForce` / `updateMoodPolar` / `updateIntent` —— 定价脑一行不改，它继续决定"这只股票该值多少钱"。
**保留的**：`requote` 的双边挂单逻辑、`thinBookFloor` 薄盘保护、`impactCap` 吃单限制、买盘供给保护（历史三次事故的修复都在这几条里）。
**改的**：`this.npcs` 只有 6 个对象；`requoteQty` 按 `316/6 ≈ 50` 放大，并按档位拆成 2~3 张单。

`recycleLiquidity` 的语义变得正当了：**这就是给做市商补充做市资金**，不再有"给散户发钱"的荒诞感。

### 3.3 做市商露脸（已定：露）

- **盘口**：挂单方显示「钟信自营」「华泰自营」，玩家一看就知道是自营盘在做市，不是散户在挂。
- **股东榜**：不特殊处理，做市库存攒够了自然进前十大（标签「自营」）。初始库存 0，靠做市过程积累——这和现实里券商自营盘的库存波动是一回事。

给一个配置开关 `npc.maker.public = true`，想隐身时改成 `false`：不进股东榜、挂单显示为「机构专用」。两种都不需要改代码逻辑。

实现上做市商就是 `accounts` 里 `role='mm'` 的账户（每股票 6 个，共 60 个），`nick` 存「钟信自营」，`home_stock` 指向它负责的股票。前端 `ROLE_LABEL` 加一行 `mm: '自营'`、`ROLE_CLS` 加 `mm: 'role-inst'` 即可。

## 4. 投资者怎么决定买什么

### 4.1 关键设计：每个人有自己的估值

真实投资者**看不到** `fairValue`（那是上帝视角）。但市场又需要"贵了有人卖、便宜了有人买"的均值回归力。

解法：给每个投资者一个**私人估值**：

```
我的估值 = 发行价 × (1 + 个人偏置 ±8%)，之后每天向"我的持仓成本 + 市场价"缓慢靠拢
```

- 同一天，甲觉得阿狸值 105、乙觉得值 118 → 天然产生分歧与成交量
- 价格跌破大多数人的估值 → 有人接；涨过大多数人估值 → 有人卖
- 不需要暴露 `fairValue`，回归力来自"很多人的偏见平均"

### 4.2 注意力范围（决定性能，也决定真实感）

真实投资者不会同时盯 10 只票。按类型分配：

| 类型 | 盯几只 | 看什么 |
|---|---|---|
| 机构 | 10（全部） | 估值偏离 + 趋势 + 消息 + 组合权重 |
| 游资 | 3（动量前 3） | 涨幅榜、成交量异动、消息 |
| 大户 | 4（持仓 + 涨幅前 2） | 估值、趋势 |
| 中户 | 3（持仓 + 热门前 1） | 盈亏、消息 |
| 散户 | 2（持仓 + 涨幅榜第 1） | 昨天涨了没有、群里在说什么（消息） |

3160 × 平均 2.6 只 ≈ **8200 次评分/轮**，再按 8~20 tick 错峰摊开 → 每 tick 约 600 次，比现在的 3160 次还轻。

### 4.3 行为参数（分层，必须差异足够大）

| | 换手周期 | 单笔占流通盘 | 估值权重 | 动量权重 | 消息权重 | 止损 |
|---|---|---|---|---|---|---|
| 机构 | 1~3 游戏日 | 0.05%~0.2% | **1.4** | 0.3 | 0.6 | 无（配置型） |
| 游资 | 5~40 tick | 0.02%~0.1% | 0.5 | **1.5** | **1.2** | −7% |
| 大户 | 60~200 tick | 0.02%~0.08% | **1.2** | 0.5 | 0.5 | −15% |
| 中户 | 30~100 tick | 0.005%~0.02% | 0.9 | 0.8 | 0.8 | −12% |
| 散户 | 10~60 tick | 0.001%~0.005% | 0.4 | **1.3** | **1.5** | −10%（且恐慌踩踏） |

这张表就是"市场有分层"的全部秘密。现在这五类的差异是调出来的（`config.npc.types`），改版基本可以沿用，只是从"池级"变成"个人级"再加 `ownBias` 随机扰动。

### 4.4 下单方式

| 类型 | 方式 | 理由 |
|---|---|---|
| 散户 | 市价追（吃单，`BUY_OPEN` 打卖一） | 现实里散户就是点"买入" |
| 游资 | 市价 + 偶尔打板（挂涨停价吃单） | 追热点 |
| 大户/中户 | 限价挂在自己估值附近，等成交 | 不着急 |
| 机构 | 分 3~5 笔、每笔隔几 tick 的 TWAP | 建仓不能一把打飞 |

**投资者在外股不挂长期单**（除大户/中户的小额限价），避免污染别股的 `sideDepth` 判断。

## 5. 守恒、流动性与防穿帮

| 事项 | 规则 |
|---|---|
| 股数守恒 | 初始按 316/股 分掉 96% 流通盘给 3160 个投资者，剩 4% 划给 6 家自营做库存（见下） |
| 做市资金 | 独立注入，规模 = 原 `liquidityFloor` 口径；`recycleLiquidity` 只补给做市商 |
| 自营初始库存 | 流通盘的 **4%**（`maker.initInventoryPct`）。方案原文写 0，实测行不通：没有货就没有卖盘，开盘只能挂买一边 |
| 单股外股资金上限 | 该股流通市值的 8%，**全市场口径**（一张 `game.crossExposure` 表，316 个池共用） |
| 每 tick 跨股成交笔数 | **全市场** 12 笔（`cross.maxTradesPerTick`）。池级预算等于没预算：316 个池 × 3 = 948 笔/tick |
| 单账户仓位 | 外股总市值 ≤ 自有权益 60%；单只外股 ≤ 30%（本股底仓不计入，那是出生就发的） |
| 本股筹码 | 不设保底（真实投资者会清仓换股），但受上面的仓位上限约束 |
| 风控强平 | 不用改，`maybeLiquidate` 本来就按股票扫全账户 |

## 6. 风险与代价

1. **盘口质感会变**：从 316 个人各挂一张，变成 6 个做市商各挂 3 档。深度总量能对上（量放大了），但**档位集中度、撤单节奏**完全不同，`thinBookFloor` / `impactCap` / `liquidityBidDepthLots` 这些按人头调的常数必须重跑 probe。这是最大的一块不确定性。
2. **散户必须"活"**：3160 人里 2200 是散户，他们的行为决定市场有没有烟火气。要给散户足够的"无理由交易冲动"（现实里散户就是会手痒），否则盘面会比现在淡。
3. **存档**：删库重建，没有迁移成本。但**改完必须先删 `game.db` 再启动**，否则旧库缺列会直接报错——这是唯一容易踩的坑，建议 `server.py` 启动时检测 schema 版本不匹配就明确提示"请删 data/game.db 重开"。
4. **玩家观感剧变**：股东榜从「大米·散户12」变成「曹俊（杭州）」，成交回报里全是人名。这是想要的效果，但要接受"10 只票各有 316 个本地人"这个设定消失。

## 9. 实施中踩到的坑（都已修，改这块之前先看一遍）

1. **自营必须有初始库存（流通盘 4%）**。方案原文写"做市商初始持仓 0，靠做市过程积累"，
   实际跑不起来：没有货就没有卖盘，开盘只有一边盘口。
2. **跨股闸门必须是全市场口径**。预算与单股暴露最初写在 `NpcManager` 上，316 个池各算各的，
   「每 tick 3 笔」实际是 948 笔，「单股 8% 流通盘」实际是 316×8%——闸门形同虚设。
   现在统一挂在 `Game` 上（`game.crossBudget` / `game.crossExposure`），由 `npc.crossStore()` 取。
3. **`game.tick` 的股票遍历顺序必须逐 tick 轮转**。预算是全市场共享的，固定按 `this.stocks`
   顺序遍历会让排在前面的几个池每 tick 把预算吃光，后面三百个池的投资者一辈子轮不到外股。
4. **注意力短名单必须含「已有外股持仓」**。只给涨幅榜的话，买进来的票一旦掉榜就再也看不见，
   永远卖不掉（尸体仓位）。见 `cross.watchHold`。
5. **`foreignMV` 必须排除 `homeStock`**。机构在自家票上有 330 万股（约 6600 万），
   算进"外股仓位"会让 `maxForeignPct × 权益 − 本股市值` 恒为负，跨股一笔都做不成。
6. **私人估值的锚是「当前市价」，不是发行价**。价格走出数倍之后，以发行价为锚 = 全员只卖不买。
7. **新建 NPC 账户必须立刻 `market.notifyChange(acc)`**。落盘靠 `sweep` 分片轮转（300 tick 一轮），
   新局 3160 个账户只写得进 1/300，重启就读回残档（机构只剩 6 个）。这是 P0 之前就存在的既有 bug，
   被"重启后 NPC 少了一大半"的表面现象掩盖了。
8. **NPC 现金落盘按「分」取整**（`persist.writeAccount` 的 `r2`）。守恒断言容差用半分，
   不要用 `1e-6`——逐位相等在小数点后第 4 位就破。
