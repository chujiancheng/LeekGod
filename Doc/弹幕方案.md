> 目标：分时图上飘「场内声音」——玩家能发，NPC 也会说；NPC 的话由真实持仓盈亏驱动，亏多了会骂街，爆仓了会哀嚎。

## 0. 一句话与三条底线

**分时图上方飘过一行行短句，说话的是这个市场里的人**——3160 个有名有姓的投资者，加上真实玩家。

三条底线（决定后面所有取舍）：

1. **弹幕不是聊天室，是「场内声音」**。顶栏的「在线人数」是真人，弹幕里大多数是 NPC 投资者。文案、标签、身份展示全部按「这个市场里有几千个投资者」来立，不能让人感觉「就 2 个人在线怎么刷这么多」。
2. **NPC 只描述已经发生的事 + 主观情绪，绝不描述未来**。`fairValue` / `force` / `intent` / `llmPlan` 一个都不许出现在文案里（与开放接口的内幕红线同一口径）。弹幕可以剧透「我亏麻了」，不能剧透「主力要拉了」。
3. **弹幕是情绪，不是情报**。消息（`news`）负责基本面与内幕分层，弹幕不进 `news[]`、不参与消息去重池、不落库。想从弹幕里挖 alpha 的人应该一无所获。

## 1. 为什么要做

| 现状 | 问题 |
|---|---|
| 分时图是一条干净的线 + 量 + MACD | 冷。除了价格没人说话，`news` 是"公告"口吻，离盘面很远 |
| 3160 个 NPC 只在后台撮合 | 玩家完全感知不到「有几千人在这个市场里」，NPC 真实身份方案的成果只体现在股东榜前三名 |
| 玩家的盈亏体验是私人的 | 爆仓、割在地板上、追高被套——这些最有情绪的时刻，场里没有任何反应 |

弹幕补的正是这一块：**把图上发生的事，翻译成人话**。价格砸下去的时候有人骂，拉起来的时候有人吹，玩家会觉得「这个盘是活的」。

## 2. 形态：三层呈现

### 2.1 L1 飘屏（主形态）

在分时图**价格区**右→左飘过一条条短句，4 条泳道（窄屏 3 条），单条穿屏 8~10 秒。

```
┌──────────────────────── 分时 ─────────────────────────┐
│  [散户]割在地板上了          [游资]谁在砸我？报个名      │  ← 泳道 1
│         [机构]这个位置不接，谢谢                          │  ← 泳道 2
│  [大户]追保电话打我三次了                                  │  ← 泳道 3
│  ─────────────────────────────────────────────  ─────  │
│   ╱╲    ╱╲                                              │
│  ╱  ╲__╱  ╲___                    ●  ← 事件锚点          │
│ ╱            ╲___╱╲                                     │
├───────────── 成交量 ────────────────────────────────────┤
├───────────── MACD ─────────────────────────────────────┤
└────────────────────────────────────────────────────────┘
```

- **只占价格区上半部**（`PAD_T` 起 ~64% 高度），不压到量带与 MACD。
- **十字光标激活时整层降到 35% 不透明度**，读数优先。
- 单条格式：**只有正文，不挂 `[类型标签]`**——标签文字会占掉半条弹幕，正文一律 `var(--ink)` 底色胶囊。
  身份只靠文字颜色区分：机构金 / 游资红 / 大户紫 / 中户蓝 / 散户灰 / 自营淡 / 玩家（金色胶囊 + 加粗）。

### 2.2 L2 事件锚点（差异化形态，建议做）

不是所有弹幕都该飘走。**强平、封板、大额成交、竞价异动**这几类，在图上的 `(t, price)` 位置钉一个 4px 的小点，悬停（十字光标靠近）弹出卡片：

```
        ● 曹俊（杭州）14:23
          追保电话打我三次了
```

理由：飘屏是「当下」，锚点是「这天发生过什么」。玩家下午三点打开图，能看见上午十点那根大阴线上钉着三个小点——点开是「XX 爆仓了」。**这条比飘屏更能让人记住这个盘是有人的**，而且成本很低（一次按需拉取 + 画几个点）。

- 当日锚点最多 30 个，超出丢弃最旧的（免得一天下来满图都是点）。
- 只在分时模式画；K 线模式整层隐藏。
- 5 日视图照常显示今天的锚点（`axisCoord` 已经把跨天坐标处理好了，直接复用）。
- 数据**按需拉**：`GET /api/danmaku/marks?stock=`（切股票时拉一次），不进每帧 state——10 只股票 × 30 个锚点每帧下发是纯浪费。

### 2.3 L3 弹幕面板（P2，可选）

「消息」tab 隔壁加一个过滤按钮「弹幕」，或独立小面板列出今日弹幕（含锚点事件的完整列表）。P2 再说，P0/P1 不做。

## 3. NPC 弹幕引擎（核心）

### 3.1 谁说：六类人格

直接复用 `identity.js` 的展示名与 `npc.js` 的类型分档，**不新建人格系统**：

| 类型 | 展示名样例 | 语气 | 典型台词 |
|---|---|---|---|
| `inst` 机构 | 望元私募 | 冷静、居高临下、惜字 | 「这个位置不接。」「量不对。」 |
| `hot` 游资 | 宁波桑田路·孙叔 | 嚣张、江湖气、爱点名 | 「谁在砸我？报个名。」「三点前给你拉回去。」 |
| `big` 大户 | 曹俊（杭州） | 焦虑、爱炫耀、爱算账 | 「昨天还赚 80 万，今天倒亏 20。」 |
| `mid` 中户 | 周敏（成都） | 半懂不懂、爱给建议 | 「这形态要破位了吧？」 |
| `small` 散户 | 李小雨（西安） | 情绪化、自嘲、问蠢问题 | 「割在地板上了，我人麻了。」「还能上车吗？」 |
| `mm` 自营 | 钟信自营 | 官方腔、不表态 | 「双边报价正常。」（低频，只在流动性异常时） |

**一个硬规则：单账户 10 分钟内最多说 1 条**，同一只股票同一秒最多 1 条。否则玩家会看到「曹俊（杭州）」在 3 分钟里骂了 12 次街，立刻穿帮。

### 3.2 什么时候说：情绪驱动，不是随机抽样

这是整个方案的关键设计。**不要让 NPC 随机说话**——随机说话的 NPC 一眼假。要让话从真实状态里长出来：

每次要发声时，服务端做三步：

1. **选桶**：在该股全部 NPC 里按真实浮盈排序（`pnlOf(n)`），取最惨队列 / 最爽队列。`updateForce()` 本来每 tick 就全扫一遍 316 个 NPC 在算 `pnlOf`——**顺手记下最惨/最爽各 1~2 个（连人带盈亏）**，不要再扫第二遍。
2. **选池**：`(类型, pnl 区间, 当前盘面状态)` → 定位到一个文案池。
3. **填值**：模板里的 `{pct}` 必须来自这个人的真实 `pnlOf`（四舍五入到整数），填完再校验一次，差太远就换一条不带数值的。**文案里的数字必须是真的**，否则玩家一对股东榜就露馅。

### 3.3 事件矩阵

| # | 触发条件 | 谁 | 层级 | 文案示例 |
|---|---|---|---|---|
| 1 | 浮亏 ≤ −15% 且持仓 > 0 | `small` / `mid` | chat | 「我不玩了，把钱还我」「这票是不是有人在出货」 |
| 2 | 浮亏 ≤ −30% | `big` / `hot` | chat | 「再跌 2 个点我就认了」「躺平，随你砸」 |
| 3 | **强平**（`Game.onLiquidate`） | 任何 | **event 锚点** | 「追保电话打我三次了」「天台见」 |
| 4 | 割肉后 5 分钟内价格反弹 ≥ 3% | 刚卖出的人 | chat | 「我刚割的，你跟我说这个？」 |
| 5 | 买在当日高点 ±0.5% 后回落 ≥ 3% | 刚买入的人 | chat | 「一买就跌，我是不是被盯上了」 |
| 6 | 浮盈 ≥ +15%（`hot` / `big`） | 最爽队列 | chat | 「这波吃了 30 个点，谢谢抬轿」 |
| 7 | **涨停 / 跌停封板**（边沿触发） | 全类型随机 | **event 锚点** + chat | 「封死了，明天见」/「跌停板撬不开」 |
| 8 | 消息公开后 3~15 秒 | `inst` 优先 | chat | 「利好出尽，谢谢」/「这公告我上周就知道了」 |
| 9 | 竞价高开 / 低开 ≥ 2% | `hot` / `small` | chat | 「高开这么多，谁在抢？」 |
| 10 | 14:57 后 3 分钟内振幅 ≥ 2% | `small` | chat | 「尾盘这一下是什么意思」 |
| 11 | 大盘指数 ±2% | 跨股，挑 1~2 只 | chat | 「全市场都在跌，不怪你」 |
| 12 | 玩家单笔成交 ≥ 流通市值 0.05% | 该股 NPC | chat | 「有大哥进场了」「刚刚谁砸的那么大」 |
| 13 | **玩家被强平** | 该股 NPC | **event 锚点** | 「刚刚有人被抬走了」 |
| 14 | 收盘结算后（夜间） | `small` / `big` | chat | 「又亏一天，明天再说」 |

第 12/13 条是**性价比最高的一条**：玩家大额买入或爆仓时，场上有人评论他。玩家会立刻感觉到「这个世界看见我了」。成本极低——`Market.execute` 里已经知道双方账户，判一下 `!acc.isNpc` 即可。

#### 3.3.1 「NPC 回应玩家」到底是什么（三档，别混着说）

这三个档位的实现成本、露馅风险、观感完全不同，必须分开定：

| 档 | 触发 | 长什么样 | 实现成本 | 露馅风险 |
|---|---|---|---|---|
| **A 纯背景音** | 无 | NPC 各说各话，玩家做什么都没人理 | 0 | 无 |
| **B 被动反应**（**已定，P1 实现**） | 玩家**做了**某件事：大额买入 / 清仓割肉 / 被强平 / 涨停板上挂大单 | 「有人割在地板上了」「刚刚有人被抬走了」「封单里有个大的」 | 极低（`execute` 里判 `!acc.isNpc`） | 低——**没人会去测试一个陈述句** |
| **C 主动跟风**（**本期不做**） | 玩家**发了**弹幕，2~5 秒内 NPC 以 20% 概率接一句 | 你发「跑」，下面飘过来一句「跑得掉吗」 | 中（要给弹幕打语义标签） | **高**——玩家会立刻开始试探它 |

**B 和 C 的本质区别是「会不会被当成对话」。**

B 是「场里发生了事，旁边有人嘀咕了一句」，玩家不会对着它回话，因为它没有指向性（说「有人」，不 @ 你）。C 是「有人在接我的话」，一旦玩家意识到这点，下一步一定有人发「1+1 等于几」——答不上来就当场露馅，而且是当着所有人的面。**接话会把「弹幕是氛围」变成「弹幕是客服」。**

所以 B 的三条硬约束：
1. **绝不说玩家昵称**，一律「有人」「大哥」「刚才那笔」；
2. **只说已发生的事实**，不评价、不建议（「这波接得漂亮」可以，「你该跑了」不行——后者变成喊单）；
3. **同一玩家 5 分钟内最多被评论 1 次**，否则像被监视。

C 如果真要做，只有一条可控路径：**按标签接，不按语义接**。预设短语 chips 天生带标签（`跑` → `panic`、`冲` → `chase`、`接飞刀` → `catch`），NPC 按标签选池；手打的自由文本只做关键词兜底，匹配不上就不接。同一玩家 5 分钟内最多被接 1 次、全服 20% 概率起步（先灰度到 5% 看反应）。

**已定（2026-10-20）：做 B，不做 C。** B 能给到「世界看见我」的八成，而 C 多出来的两成，代价是玩家开始怀疑整片弹幕——C 将来要做，按上面「按标签接」的路子单独立项、单独拍板。落地口径见 §3.3.2。

#### 3.3.2 B 档的落地口径（已拍板：先做 B，不做 C）

> **决策（2026-10-20）：做被动反应 B，不做 C。** B 的判定钩子和 P0 的 `danmaku.js` 是同一处代码（都在 `Market.execute` 旁挂），分两次改反而更贵——所以三个触发点**并进 P0**，锚点留 P1。C 档（NPC 接玩家的话）本期不做，将来要做需重新拍板。
> 理由不是成本，是**露馅半径**：B 说错了只是措辞不对，C 说错了是当着所有人的面证明这片弹幕是假的。

**触发点收成三个（矩阵第 12/13 条拆细）**

| 触发 | 判定位置 | 条件 | 文案池 |
|---|---|---|---|
| **大额买入** | `Market.execute` 旁挂 | 玩家 60 秒内累计买入额 ≥ 流通市值 0.05% | `hot` / `big` → 「有大哥进场了」「这单子不像散户」 |
| **清仓割肉** | 同上（卖出侧） | 该股持仓归零 + 批次均价高于成交价 + 单次卖出 ≥ 20 万 | `small` / `mid` → 「有人割在地板上了」「刚那笔是止损吧」 |
| **玩家被强平** | `Game.onLiquidate`（已有钩子） | `!acc.isNPC` | 全类型 → 「刚刚有人被抬走了」+ **event 锚点** |

矩阵里第 12 条的「涨停板上挂大单」不放进来：它的判定点在 `placeOrder` 而不在成交，且「多大算大」在封单里没有稳定口径，容易在封板日刷屏。等 P2 连锚点一起看。

**两个必须做对的工程细节**

1. **判定下沉到 `execute`，但绝不在 `execute` 里做重活。** `execute` 是撮合热路径，一单可能分十几笔成交。做法是 O(1) 记账：`danmaku.onPlayerAction(acc, stockId, side, amount, now)` 只往 `Map<accId, {buy, sell, t0}>` 里累加，达阈值才入队并清空。
2. **聚合窗口 + 冷却，缺一不可。** 60 秒聚合窗口防「一单拆十笔发十条」，触发后该账户 30 秒内不再累加。没有窗口的话，玩家下一笔 1 万块的零碎单会接着触发。

**「有人」是协议级约束，不是文案约定**

下发给客户端的 item 里，`playerB` 类**只允许这五个字段**：`actor:'someone'` / `side` / `amountBand`（`<200万`、`200~1000万`）/ `stockId` / `t`。**不带 playerId、不带昵称、不带精确金额。**

- 文案池里没有 `{nick}` 这种变量——模板只有 `{side}` `{band}`。测试断言 `vars` 键集合等于白名单，多一个就红；
- 防的不只是「被围观」，还有**同服其他人的 API 抓包**：一旦下发 playerId，别人拉一次 `/api/state` 就能把「谁在买」对上号，等于免费龙虎榜。

**观感上怎么让玩家知道这条在说他**

不用「你」，用一个**左侧 2px 亮边 + 稍慢的移速**（14s 走完全程 vs 普通 10s）。玩家自己那笔成交被评论时，他能看出这条跟别的不一样，但说不出哪里不一样——这比写「你被围观了」有效得多。频次上他 5 分钟内只会看到一次，不会觉得被盯着。

**冷却按「被评论」算，不按「触发」算**：`playerCooldown: Map<accId, lastMs>`，5 分钟。玩家连砸十笔也只被说一次；但如果他先大额买入（被评论一次），四分钟后爆仓，强平那条仍然要出——因为爆仓是事件锚点，不受 chat 冷却约束。

**测试要钉住的六条**

1. 玩家小额买入（< 0.05% 流通市值）不产生任何弹幕；
2. 单笔 500 万拆成 12 笔成交，只出 1 条；
3. 触发后 5 分钟内同一玩家再触发，不再出；
4. 强平不受 5 分钟冷却影响，且必带锚点；
5. `playerB` item 的键集合严格等于白名单（这条防的是将来有人好心把 nick 加回来）；
6. NPC 自己的成交**不触发** `playerB`（判 `acc.isNPC`，别把 3160 个 NPC 互相评论成菜市场）。

### 3.4 频率：漏斗 + 预算

弹幕太少冷场，太多挡图。三层漏斗：

```
全服      ≤ 1 条 / 1.5 秒（≈40 条/分钟，跨 10 只股票）
单股      ≤ 1 条 / 6 秒，且 ≤ 4 条/分钟（稳态）
单账户    ≤ 1 条 / 10 分钟
```

稳态下单股约 **4 条/分钟**：4 条泳道 × 单条占道 10 秒 = 容量 24 条/分钟，占用 1/6，观感是「时不时飘一条」——不吵，但一眼能看出有人在。事件级（强平/封板）**不占稳态配额**，允许短时突发到 12 条/分钟。

**只为「有人在看」的股票生成**：服务端维护 `watchers: Map<stockId, lastSeenMs>`。打点有两处：

1. `/api/history?stock=`（切股票 / 刷新时本来就会拉）顺手调 `noteWatch`；
2. **`GET /api/danmaku/watch?stock=`（60 秒心跳，已实现）**——一只票的 history 只拉一次，
   没有心跳的话玩家盯盘满 5 分钟（TTL）后 watcher 就过期，这只票从此不再生成弹幕。
   客户端在 200ms 的 `tickUI` 里按 60 秒节流发一次，只在「交易终端 · 个股 · 分时」发。

没人看的股票不生成弹幕——省 CPU，也避免 10 只股票分掉配额导致你正在看的那只冷冷清清。
（早期实现里「零 watcher 就随机全市场」的兜底已删除，它会把配额摊到没人看的票上。）

### 3.5 三条红线（写进测试）

1. **不剧透未来**：文案池里不许出现 `fairValue` / `force` / `intent` / `llmPlan` 的任何数值或方向判断。测试断言：下发的 item 键集合固定为白名单，多一个键就红。
2. **不提前评论泄露期消息**：NPC 对消息的反应必须过 `NewsSystem.visibleFor(item, viewer, now)`——消息还没公开，NPC 就当不知道。这条最容易漏：`news` 的泄露期是给高星级券商玩家的特权，NPC 一嘴「这公告我上周就知道了」等于把内幕广播给全服。
3. **不骂人**：只骂行情、骂公司、骂「主力」，**不出现真人玩家昵称**（第 12/13 条用「有人」「大哥」指代）。脏字全部走阴阳怪气（「真行」「你厉害」），不做脏话过滤器的军备竞赛。

### 3.6 文案库结构

新建 `Server/src/danmaku-text.js`（纯数据 + 纯函数，与 `milestones.js` 的 `TEXT` 同款）：

```js
POOLS = {
  small: {
    deepLoss: ['割在地板上了，我人麻了', '这票我熟，熟了三次了', ...],  // 每条 8~12 句
    cutLoss:  [...], chaseHigh: [...], limitUp: [...], limitDown: [...],
    win:      [...], news: [...], auction: [...], idle: [...]
  },
  mid: {...}, big: {...}, hot: {...}, inst: {...}, mm: {...}
}
```

- **总池起步 300 条，目标 720 条**（每类 × 每情境 8~15 条主句，见 §3.7.1），比 `news.js` 的 320 条大一号。
- 去重按池独立记最近 N 条（抄 `news.js` 的 `recentByPool`）。
- 长度硬约束：**≤ 20 个汉字的优先**，最长不超过 `config.danmaku.player.maxLen`（24），飘屏一行放得下。

### 3.7 文案从哪来：**只用固定池**（已拍板，2026-10-20）

> **决策：不接大模型。** NPC 说的话 100% 来自 `danmaku-text.js` 的本地文案池 + 组合规则。
> 本节保留「为什么不上大模型」的依据，以及将来想开这个口子时该从哪里接——但**本期不实现**。

#### 3.7.1 为什么不上（依据留档，避免以后重提）

| 障碍 | 实测 / 口径 |
|---|---|
| **延迟** | 现役模型 `mimo-v2.6-flash` 走推理链路，`config.js` 注释记着实测 **单次 8~25 秒**、timeout 给到 40 秒。弹幕的时效预算 ≤ 2 秒——20 秒后飘过来一句「谁在砸我」，价格早跑没影了，只剩出戏 |
| **不可审核** | 在线生成的文案直接进直播间，中间没有人工环节。这个项目里坐着真人玩家，一句不合适的输出就是事故；固定池每一句都经过一遍眼睛 |
| **不可测试** | 现有 1283 + 607 条测试全是确定性的。在线生成要 mock、要断言「模型这次没说错」，成本远高于收益 |
| **依赖面** | 大模型主力脑刚被关（`data/llm.local.json enabled:false`）。弹幕若依赖同一条链路，等于把「有没有人说话」押在一条会因欠费 / 网络 / 429 挂掉的路上——**冷场比没弹幕更伤** |

#### 3.7.2 用结构换多样性：组合式文案（主手段）

固定池的痛点是重复，但重复可以靠**结构**解决：

```
一句话 = [语气前缀] + [主句] + [变量槽]
         （4~6 个）    （每池 12 条）   （{pct} / {股票简称}）
```

- `small.deepLoss` 12 条主句 × 6 个前缀（`唉，` / `真行，` / `不是，` / `我服了，` / `……` / 空）= 72 种表面变体；
- 再叠 `{pct}` 的真实数值（`亏了 23 个点` 每个数字都不同），有效变体 ×3；
- 池内去重窗口设 15 条：同一句话 15 次之内不重复。

6 类 × 10 情境 × 12 条 = **720 条主句**，撑起约 **3000 种表面变体**。一个玩家盯着同一只股票泡一小时大约听到 240 条，重复率可以压到个位数。**这是本期唯一的扩池手段**，代码量约 30 行（`pickText(kind, scene, vars)` 里做前缀抽样）。

配套两条约束：
- **前缀不许无脑套**：`inst` / `mm` 两类不加语气前缀（机构不会「唉，」），只走主句；`hot` 的前缀池单独一套（江湖气）。
- **变量槽填完要回读校验**：`{pct}` 必须与真实 `pnlOf` 同号、整数部分一致，对不上就退化成不带数字的那条。

#### 3.7.3 池子多大、什么时候补

| 阶段 | 主句条数 | 依据 |
|---|---|---|
| P0 上线 | **300**（每类 6 情境 × 8 条） | 够撑住 10~15 分钟的观感，先验证节奏与闸门 |
| 观察后 | 补到 **500~720** | 按下面「池健康度」的数据补最缺的那几池 |

**池健康度埋点**（服务端一行统计，不落库）：每个池记 `hits` 与 `repeatHits`（命中了去重窗口内文本的次数），每 5 分钟往日志打一次 `hits / repeatHits / 池内条数`。`repeatHits / hits > 15%` 的池就是该补的池——**用数据决定补哪一池，而不是平均撒**。

#### 3.7.4 以后想开的口子（**本期不实现**，只留插口）

万一以后要接，正确的接法只有两种，且都不改变本期架构：

1. **离线扩池**：一次性脚本按「类型 × 情境」各要 30 条不同说法 → 机械校验（长度 / 禁用词 / 池内不重复）→ 人眼抽检 10% → 并进 `danmaku-text.js`，生成的 JSON 进仓库可 diff 可回滚。模型当**编辑**不当演员，40 秒超时在这里无所谓。
2. **只做「对玩家的反应」**：§3.3 第 12/13 条（玩家大额买入 / 被强平）频率低（一天约 20 次）、时效宽松（5 秒后飘过来反而自然）、上下文值钱。红线是**事实由规则给、措辞由模型给**——喂结构化事实，禁止它自己编数字与「跌停了」「公告了」这类断言。

留插口的具体做法（现在就写进代码，为的是将来只换一处）：

```js
// danmaku.js —— 唯一取文案的地方。将来接模型只替换这个函数体的实现，
// 其余（闸门、选桶、seq、下发）一行不动。
pickText(kind, scene, vars) { return pickFromPool(kind, scene, vars); }
```

真要开的时候还有四条硬要求，写在这里免得将来踩：独立开关（**绝不复用 `npc.llm.enabled`**，否则关 AI 主力会连带哑掉弹幕）、独立日预算熔断、`timeoutMs` 单给 2000 且超时**直接发池里的兜底句**（不等重试）、输出过 `validateLlmText()`（长度 / 数字 / 事实词 / 敏感词）。

## 4. 玩家弹幕

### 4.1 入口

图表标题行右侧加一个 `#dmToggle` chip（`弹幕 · 开`），点它展开图表面板底部浮起的输入条（`absolute` 覆盖，不占文档流、不改 `.chart-panel` 高度——这块高度已经被移动端修过两轮，别再碰）：

```
[──────────────────────────────]  [发送]   ✕
 冲 | 跑 | 接飞刀 | 主力在装死 | 这票我熟 | 稳住
```

- 6 个预设短语 chips，点一下直接发——**移动端 90% 的弹幕会是点出来的，不是打出来的**，这也是控量最有效的手段。
- `Enter` 发送，`Esc` 收起；发完自动收起并保留草稿。
- 开关状态记 `localStorage.gushen_dm`（`on` / `off`），默认开。

### 4.2 校验与配额

| 规则 | 实际值 | 理由 |
|---|---|---|
| 长度 | 1~24 字符（trim 后，按码点算） | 一行放得下 |
| 冷却 | **5 秒/账号**（`player.gapMs`） | 够按不过来 |
| 频率 | 6 条/分钟（单股）+ **120 条/自然日**（单账户） | 防脚本 |
| 同文重复 | **60 秒内同一文本拒发** ✅ | 防复制粘贴刷屏 |
| 内容 | **禁 URL / 导流句式 / 纯符号 / 同一字符连刷 ≥6**，敏感词表命中即拒 ✅ | 不回显命中了哪个词，不给试探留信号 |
| 身份 | 必须已开户 | 未开户 / token 失效直接 401 |
| 禁言 | `muteUntil` 未过期则 403 | **未实现**（P2 与后台接口一起做），当前靠冷却 + 日配额兜底 |

限流复用了现成的 `config.http.rateLimit.write`（30 次/分钟，与改昵称等轻量写共用），
没有单独开 `danmaku` 桶——每条弹幕自己已经有 5 秒冷却 + 6 条/分钟，比 12 次/分钟更严。

### 4.3 展示

- 玩家弹幕：`[玩家] 昵称：正文`，自己发的加金色描边（1.5px）+ 名字前一个 `我` 角标，**上屏时从右往左穿屏一次，不重复**。
- **不显示券商标签和组内名次**——弹幕是情绪场，挂上「招伤证券 ★5」就变成炫富场了。
- 乐观上屏：本地立刻插一条（带 `clientId`），服务端帧回来按 `clientId` 去重替换成真实 `seq`，避免「发了没反应」的 700ms 空窗。

## 5. 服务端设计

### 5.1 新模块 `Server/src/danmaku.js`

```js
class DanmakuFeed {
  constructor(stocks, opts)          // opts = config.danmaku
  post({ stockId, from, name, kind, text, level, price, account })
                                     // 唯一入口：过闸门 → 分配 seq → 入 ring → 返回 item
  step(now, ctx)                     // 每 tick 调；内部节流，到点才抽样闲聊
  onEvent(ev)                        // 事件级（强平/封板/大额/玩家爆仓），不占稳态配额
  snapshot(now)                      // state 段：最近 20 条 + seq（跟 news.tapeSnapshot 同口径）
  marks(stockId, day)                // 当日锚点，最多 30 条
  watch(stockId, now)                // 观看打点（/api/history 里顺手调）
  validate(acc, text, now)           // 玩家文案校验 + 配额，返回 {ok, error, retryInMs}
  mute(account, ms) / mutedUntil(a)  // 禁言
}
```

**不变量**：
- `seq` 全局单调，**只在内存**，重启归零（见 §5.5 的水位陷阱）。
- ring buffer 只存最近 60 条 / 10 分钟，超出丢弃。**不落库**。
- `snapshot()` 每帧全量下发最近 20 条——与 `news` 每帧 50 条同口径，不引入增量协议。

### 5.2 数据契约

> **以本节为准**（2026-10-20 修订）：下面这份是 `snapshot()` 实际下发的字段。
> 草案早期用的是 `seq / level / price / name`，落地时定成了 `id / kind / type / from`——
> 客户端水位靠 `id`，条目性质与说话人类型分成 `kind` 和 `type` 两个字段，语义更清楚。

```js
state.danmaku = {
  seq: 2145,                 // 服务端当前最大 id（客户端用它判断「服务端重启了没有」）
  items: [
    { id: 2145,              // 全局单调递增；客户端水位只认它
      t: 1760000000000,
      stockId: '600003',
      kind: 'npc',           // npc（NPC 闲聊/情绪）| player（玩家发的）| event（强平等事件）
      type: 'hot',           // 说话人类型：inst|hot|big|mid|small|mm|human —— 前端只用来选配色
      text: '谁在砸我？报个名',
      from: '韭菜甲',         // **仅 kind='player'**：玩家昵称（NPC 一律没有这个键）
      flag: 'playerB',       // **仅被动反应**：客户端给这条加左侧金边、飞得慢一点
      price: 108.32 }        // **仅 kind='event'**：L2 锚点要按 (t, price) 钉点，闲聊没有落点
  ]
}
```

**不下发**：`account`（NPC 内部键，会被当探针）、`broker`（NPC 归属）、任何持仓/盈亏明细。前端只有名字和类型——和股东榜的口径一致（那里带 `account` 是为了查持仓曲线，这里没有这个需求）。

### 5.3 API

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/danmaku` | `{stockId, text, clientId}` → `{ok, item}`；失败 `{ok:false, error}`（错误文案直接给玩家看：冷却 / 同文 / 太长 / 不合适 / 未知标的） |
| GET | `/api/danmaku/watch?stock=` | **观看心跳（已实现）**：交易终端每 60 秒一次，只打点不产出。只认个股，指数/未知标的返回 404 |
| GET | `/api/danmaku/marks` | `?stock=` 当日事件锚点（P2，切股票时拉一次，限流 `holders` 档） |
| POST | `/api/admin/danmaku` | 运维：`{op:'mute'\|'clear', account, minutes}`，头 `X-Admin-Token`（P2） |
| GET | `/api/danmaku` | 历史 50 条（P2 面板用） |

写接口走现成的 `guardWrite`（同源 + JSON + 限流）与 token 鉴权，与 `/api/nick` 同一套。

### 5.4 挂载点

| 触发 | 挂在哪 | 备注 |
|---|---|---|
| 强平 / 玩家爆仓 | `Game.onLiquidate(acc, now)` | 已有回调（彩蛋 C02 在用），加一行 `danmaku.onEvent(...)` |
| 封板（涨/跌停） | `Game.tick` 逐股，边沿检测 | 新增 `lastLimitState: Map<stockId, 'up'\|'down'\|null>` |
| 大额成交 | `Market.execute` 后（Game 侧收集） | 判 `!acc.isNpc` 走 §3.3 第 12 条 |
| 消息反应 | `Game.tick` 的 news emit 之后 | 延时 3~15s 才「有人说」，排队而不是当场 |
| 闲聊抽样 | `NpcManager.step` 末尾（复用 `updateForce` 的最惨/最爽桶） | 内部节流，不需要每 tick 算 |
| 玩家发送 | `POST /api/danmaku` | 直接 `post()` |
| 观看打点 | `http.js` 的 `/api/history` | 顺手 `watch(stockId)` |

**不要**在 `Market.execute` 里直接发弹幕（那是撮合热路径，一 tick 可能几十笔），只记录候选事件，由 Game 每 tick 统一仲裁。

### 5.5 配置 `config.danmaku`

> 以本节为准（2026-10-20 修订）：实际是**扁平结构**，早期草案按 stock/npc/ui 分组的写法没落地。

```js
danmaku: {
  enabled: true,                 // 文案 100% 取自本地池，无任何模型调用（§3.7）
  prefix: true,                  // 语气前缀总开关（关掉就是纯主句，方便对比观感）
  // —— 全服 / 单股 / 单账户三层闸门 ——
  globalGapMs: 1500,             // 任意两条之间至少隔这么久（tick 700ms → 实际约 2.1s）
  stockPerMin: 4,                // 单股稳态 4 条/分钟
  stockGapMs: 6000,              // 单股两条之间至少 6 秒
  accGapMs: 600000,              // 单账户 10 分钟最多 1 条
  speakChance: 0.55,             // 每次触发 tick 真的开口的概率
  quietPhases: ['lunch', 'night'], // 午休 / 夜间密度减半（方案 §2.4）
  quietFactor: 0.5,
  queueTtlMs: 60000,             // 待发反应滞留上限，超时丢弃不补播
  snapshotMs: 5000,              // 每帧下发窗口（客户端按 id 去重）
  itemLimit: 60,                 // ring buffer 上限
  watchTtlMs: 300000,            // 观看打点 TTL；客户端 60 秒心跳续期
  // —— 玩家被动反应（§3.3.2）——
  playerB: {
    enabled: true,
    floatMvPct: 0.0005,          // 大额买入：60 秒累计 ≥ 流通市值 × 0.05%
    windowMs: 60000,
    quietMs: 30000,              // 触发后 30 秒不再累加
    minAmount: 200000,           // 清仓割肉的最小累计成交额
    commentGapMs: 300000,        // 同一玩家 5 分钟内最多被评论 1 次
    liqGapMs: 120000,            // 强平播报 2 分钟去重（不受上面 5 分钟约束）
    maxPerMin: 2,                // playerB 自己的 1 分钟配额（不占单股 4 条闲聊配额）
  },
  // —— 玩家主动发 ——
  player: {
    enabled: true,
    maxLen: 24,
    gapMs: 5000,                 // 5 秒冷却
    perMin: 6,                   // 单股 6 条/分钟
    sameTextGapMs: 60000,        // 同文 60 秒内拒发
    maxPerDay: 120,              // 单账户自然日上限（内存计数，重启清零）
  },
}
```

客户端侧是常量（`Client/app.js` 弹幕段）：屏上最多 8 条、4 条泳道（高度不够自动减）、
**匀速 70px/s**（窄屏 60，playerB 再 ×0.78），位移 `--dm-dist` 按容器宽度现算。

### 5.6 不落库 + 水位陷阱

- 弹幕**全部内存**，重启清空。理由：它是氛围，不是记录；落库还要背上 30 天清理与迁移。
- **`seq` 重启归零会踩彩蛋踩过的坑**：客户端 `gushen_dm_seq` 记着上次播到 900，服务端回来 `seq=3`，`seq > lastSeq` 永远不成立 → **一条弹幕都不播**。两处必修：
  1. 客户端每帧检查 `info.seq < dm.lastSeq` → 视为「服务端重启 / 换存档」，重置水位；
  2. 换账号（`setIdentity` 检测名字变了）时清 `gushen_dm_seq`。
  这与 `gushen_event_seq` 的处理逐条对应（`Doc/项目知识.md` §3.3 已记过一次事故）。

```css
}
```

- `pointer-events: none` 是硬要求：十字光标、拖动平移都靠 canvas 的 pointer 事件，弹幕层不能吃掉。
- 动画用 CSS `transform` + `will-change`（GPU 合成），**不用 rAF 逐帧改 style**，也不参与 canvas 重绘——canvas 每帧全量重绘已经够忙了。
- 时长与位移走 `el.style.setProperty('--dm-dur' / '--dm-dist', ...)`（CSSOM 允许，CSP 禁的是 HTML 里的 `style=` 属性）。

### 6.2 泳道调度

```js
const lanes = [...Array(LANE_COUNT)].map(() => ({ tailX: 1e9, freeAt: 0 }));

function dmPump(now) {                    // 挂在现成的 200ms UI 定时器上
  dm.queue = dm.queue.filter((q) => now - q.t0 < DM.queueTtlMs);   // 过期丢弃，不补播
  if (!dm.queue.length || dm.onScreen >= DM.maxOnScreen) return;
  const lane = lanes.find((l) => l.freeAt <= now && l.tailX < chartW - 24);
  if (!lane) return;
  const item = dm.queue.shift();
  const w = measure(item);                                  // 估算 width ≈ 字数 × 字号
  lane.freeAt = now + (w + 24) / SPEED * 1000;              // 前一条的尾巴离开屏右边界
  lane.tailX = chartW - 24;
  spawn(item, lane, w);
  lane.timer = setTimeout(() => { lane.tailX = -1e9; }, ((chartW + w) / SPEED) * 1000);
}
```

要点：
- **匀速不做超车**（全部 70px/s），一旦变速就会出现「后一条追上前一条」的叠字。
- 入队上限 6 条、6 秒过期：宁可丢，不补播陈年弹幕（玩家看到「14:02 割肉」在 14:09 才飘过来最出戏）。
- 密度设置 `高/中/低/关` 只改 `maxOnScreen` 与 `lanes`（4/3/2/0），不影响服务端生成。

> **落地口径（2026-10-20）**：上面那段 `freeAt / tailX` 的调度器**没有实现**，实际做法更简单——
> 服务端已经保证单股两条之间 ≥ 6 秒（`stockGapMs`），而一条飞完全程约 10 秒，
> 所以客户端只需「按容器高度算几道（`clientHeight / 22`，上限 4）+ 轮询分配」，
> 同速不会追尾。密度设置（高/中/低/关）也还没做，当前固定 4 道、屏上最多 8 条。
> 「入队上限 6 条 / 6 秒过期」由**服务端**的 `snapshotMs = 5000` 承担：客户端只播最近 5 秒的条目。

### 6.3 事件锚点（canvas 内）

在 `drawMinuteChart()` 的**行情线之后、十字光标之前**插一段（复用同一个 `xa/x` 与 `y` 闭包，不另算坐标）：

```js
if (!isKline() && dmMarks.length) drawDmMarks(ctx, dmMarks, x, y);
```

- 画 4px 实心点 + 1px 浅色光环，颜色按 `level`（强平红 / 封板金 / 大额蓝）；落在域外的跳过。
- 悬停：复用 canvas 的 `mousemove`，命中半径 8px → 定位 `#dmTip`（绝对定位的小卡片，`pointer-events:none`）。
- **坐标必须走 `axisCoord`**，与画线、刻度、十字光标同一套——这是这个项目最容易错位的地方（`Doc/项目知识.md` §7 里三处都强调过）。

### 6.4 与现有 UI 的冲突检查

| 风险 | 处理 |
|---|---|
| 压住十字光标读数 | 光标激活时 `.dm-layer.dim`（opacity .35） |
| 压住量带 / MACD | 层高锁 62%，只覆盖价格区 |
| 压住 `#chartZoom` 按钮 | 层 `z-index:3` < 按钮 4，且右侧留 66px |
| 移动端挤占 | 3 条泳道、字号 11px、`speedPxPerSec` 60 |
| 主题（7 套，含 3 套浅底） | 文字走 `--ink`、底衬用 `color-mix(in srgb, var(--float-bg) 72%, transparent)`，切主题后 `repaintTheme()` 不用管（DOM 层吃 CSS 变量） |
| 浅底主题看不清 | 每条弹幕带半透明底衬 pill（bilibili 老规矩），不用描边 |

### 6.5 性能预算

- DOM 节点上限 `maxOnScreen` = 8，用完即回收（`animationend` 里 `remove()` + 池化复用）。
- 每帧 SSE 只做一件事：`items.filter(seq > lastSeq)` 入队，**不碰已有节点**。
- 单次量测 4 条/分钟 × 1 次 `measureText` ≈ 0（可忽略）。

## 7. 验收

### 7.1 服务端 `Server/test/danmaku.test.js`（当前 54 项，全绿）

- 频率闸门：单股 4/分钟、全服 1/1.5s、单账户 10 分钟 1 条；
- **没人看就不生成**（零 watcher 一条不出）+ **心跳过期后停止生成**；
- **停牌不生成**（tick 传 `halted`）；午休/夜间密度减半（`quietFactor`）；
- **说话人冷却**：playerB 的说话人也要守单账户 10 分钟，全员冷却时宁可不发；
- **全服闸门对 playerB 同样生效**：同一 tick 到期的两条只放一条，下个节奏点补第二条；
- 事件级（强平）不占稳态配额，但受队列 TTL 与冷却约束；
- `seq` 单调递增；`snapshot()` 只回最近 `snapshotMs` 内的条目；
- **键白名单**：playerB item 只含 `id/t/stockId/kind/type/text/flag`（多一个就红——防剧透的机械保证）；
- 玩家校验：长度 / 冷却 / **同文 60 秒** / **URL** / **纯符号** / **连续重复字符** / 敏感词 / 未开户；
- 文案 `{pct}` 与真实 `pnlOf` 同源（取被选中那个人的真实浮盈，不是队列头部的）；
- 文案池完整性：5 类 × 4 情境各 ≥ 8 条、playerB 三个情境各 ≥ 8 条、零脏字、无昵称变量；
- 重启后 `seq` 归零 → 客户端水位重置逻辑（客户端侧断言，见 7.2）。

### 7.2 客户端 `Client/test/client-day.test.js` [24] 弹幕（16 项）

按现有测试的风格做**源码级断言**（这个文件本来就是静态检查 + 桩环境，不跑像素）：
