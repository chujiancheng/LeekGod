# 我是股神 · 头像系统方案（脸面）

> 状态：**设计稿（待拍板）**。本文只定设计与施工口径，代码未动。
> 相关文档：`头衔方案.md`（境界 = 面子）、`券商方案.md`（门派 = 规矩）、`弹幕方案.md`（玩家弹幕）、`彩蛋玩法方案.md`（解锁条件源）、`项目知识.md`（§3.4 账号与昵称 / §3.6 境界 / §6 表结构 / §7 客户端）。

## 0. 一句话

**给每个账户一张别人看得见的脸**：底图由玩家选，外环是境界，角标是券商——三层合成，零上传、零数值、零审核。

排行榜上现在只有「昵称 + 数字」。昵称不要求唯一（`accounts.nick` 可重名、可随时改），于是榜上出现两个「老王」时，除了账号没有任何东西能区分他们。头像补的就是这一格：**先认脸，再认名字。**

---

## 1. 定位与边界

| 做 | 不做 |
|---|---|
| 玩家从 **33 张预置图**里选一张脸 | **上传自定义图片**（无对象存储、无审核、CSP `img-src 'self'`） |
| 境界色环 + 券商角标自动合成 | 捏脸 / 分层换装（脸型 × 发型 × 配饰） |
| 六个落点：顶栏 / 排行榜 / 股东榜 / 弹幕 / 持仓弹窗 / 选头像卡 | 任何数值特权（费率 / 额度 / 券源 / 排序 / 消息提前量） |
| 按**券商、历史最高境界、彩蛋成就**解锁 | 按**当日盈亏 / 持仓 / 方向 / 爆仓**变化（情报红线，见 §2.3） |
| 没选过也必有一张默认脸（账号哈希派生） | 替换吉祥物与彩蛋猫（那是另外两套语义） |
| 只存 **key**，图走服务端白名单 | 存 URL / data URI / 外链 / base64 |

**一句话纪律：头像只回答「这人是谁」，不回答「这人现在怎么样」。**

## 2. 四条原则

### 2.1 头像是「别人看你的」，吉祥物是「你看的」

项目里已经有一个「外观」系统：`MASCOTS` 11 只，主页 hero 立绘 + 主题换装。头像绝不能和它抢位置，否则玩家会问「我到底该打扮哪个」。分工写死：

| | 吉祥物（已有） | 头像（本方案） |
|---|---|---|
| 语义 | 我的桌面摆件 / 陪伴 | 我在场里的**公共形象** |
| 谁看得见 | **只有自己**（主页 hero） | **所有人**（榜单 / 股东榜 / 弹幕） |
| 位置 | 主页 hero 大图 | 顶栏小头 + 各处 18~64px |
| 跟随主题 | 是（默认跟随主题换装） | **否**（头像跨主题不变，否则切主题等于换脸） |
| 入口 | 「外观」弹层 | 点头像本身 |
| 落库 | 只存 localStorage | **落库**（别人要看，必须服务端权威） |

彩蛋横幅里那 4 张股神猫（`egg-cat-*`）也保持原样——它是**事件的表情**，不是玩家的脸。谁做了什么彩蛋，横幅上就该是猫得意 / 猫淡定，而不是玩家的头像。

### 2.2 用三层合成换组合数

美术只画 **33 张脸**，但玩家看到的是三层叠出来的：

```
        ┌─────────────┐
        │  ① 底图      │  33 张，玩家选
        │  ┌───────┐  │
        │  │  脸   │  │  ② 外环：9 种境界色（自动，来自 realm.group）
        │  └───────┘  │  ③ 角标：6 家券商色点（自动，来自 broker.color）
        └─────────────┘
```

33 × 9 × 6 = **1782 种观感，33 张素材**。加一家券商 = +1 个色点（不用画脸）；加一个大境界 = +1 条色 token（不用画脸）；出一套赛季限定 = 只画 4 张脸，自动继承全部环与角标。

这条是整套设计的经济性所在：**变化的维度交给已有的系统（券商 / 境界），头像只负责"长相"。**

### 2.3 头像不许编码日内状态（情报红线）

境界色环已经公开了「这人大概有多少钱」——但这不算泄露，因为排行榜本来就把权益摆在第一列。真正不能进头像的是**日内状态**：

- 「今天亏了 / 今天赚了」（可以从脸的颜色读出来 → 变成盘中情绪指标）
- 「刚被强平」（爆仓头像 → 提前知道有人要砸盘）
- 「满仓 / 空仓 / 在做空某只票」（方向 → 直接是 alpha）

一旦头像能读出这些，弹幕里那句「刚刚有人被抬走了」就会被对号入座，`/api/holders` 也等于开了第二个探针。所以口径写死：**头像只承载静态身份（长相 / 门派 / 境界段位），不承载任何日内变量。**

> 推论：不做「亏钱表情」「爆仓滤镜」「持仓方向角标」。哪怕实现成本是一行 CSS 也不做——这类东西一旦上线，将来一定有人拿它当信号源。

### 2.4 没有「无脸」这个状态

新号从开户那一刻起就必须有脸：`avatar` 为 `NULL` 时按 `hash(account)` **确定性派生**一张基础脸（见 §5.2）。

- 榜单不能有空头像位（20 行里 3 个灰块，看起来像页面坏了）；
- 也不能所有人默认同一张（榜上一排一模一样的脸 = 没做）；
- 确定性 = 同一账号永远同一张，重启、换设备、清缓存都不变。

|---|---|---|---|
| `egg-a07` | 千万身家 | `A07`（1000 万） | 豪 |
| `egg-a10` | 一个小目标 | `A10`（1 亿） | 金光 |

| `egg-c02` | 天台初体验 | `C02`（首次强平） | 安全帽 |

彩蛋组是唯一「越惨越有脸」的一组——这正是本项目的调性（`savage` 基调），也给了亏损玩家一个正向反馈：**亏到极致也能解锁点东西。**

### 3.6 为什么基础组不做「攒」

- 新玩家第一天最需要的是**选择感**，不是收集感。给他的 12 张如果只开 1 张，他只会觉得「这游戏在吊我」。
- 项目里已经有两套进度（境界、彩蛋），再叠第三套 grind 会让「我今天该干什么」失焦。
- 昵称不要求唯一，所以 12 张全开还有一个实际作用：**重名玩家能靠脸区分**。
- 收集欲交给 §3.4 / §3.5 两组——它们的解锁条件本来就在玩（钱、成就），不需要额外肝。

### 3.7 key 命名规则

- 全小写 kebab-case，`^[a-z][a-z0-9-]{1,15}$`（≤16 字符）。
- 基础组用裸名（榜单里要短），其余组带前缀（`broker-` / `realm-` / `egg-`），前缀保证跨组不撞。
- **key 一旦上线永不删除、永不复用**：老档里存着它。真要下架，图留着、从目录里摘掉 → 读到未知 key 时回落默认脸（§4.6），不会裂图。

## 4. 三层合成与视觉规格

### 4.1 合成公式

```
头像 = <img> 底图  +  box-shadow 环（--rtone）  +  角标圆点（broker.color）
```

三层全部由**客户端**合成，服务端只给两个 key（`ava` + `broker`）与一个 `realm.group`。不在服务端拼图、不生成雪碧图、不做图片合成——那样每加一个组合就要多一张图。

### 4.2 尺寸档

| 落点 | CSS 尺寸 | 取图 | 环宽 | 角标 | 说明 |
|---|---|---|---|---|---|
| 弹幕（玩家发言） | 18px | `-96` | 1.5px | 无 | 只在 `kind:'player'` 的条目出现 |
| 股东榜行 | 18px | `-96` | 1.5px | 无 | 与 18px 文字行高对齐 |
| 排行榜行 | 22px | `-96` | 1.5px | 无 | 最频繁重建的一处 |
| 顶栏 | 26px | `-96` | 2px | 无 | 点击入口，`cursor:pointer` |
| 主页名片 | 40px | `-96` | 2px | 11px 点 | P1 |
| 持仓弹窗头 | 44px | `-192` | 2px | 12px 点 | 别人看你的仓位时的第一眼 |
| 选头像卡 | 64px | `-192` | 3px | 16px 点 | 弹层内，唯一能看到细节的尺寸 |

两档图就够：≤40 CSS px 用 `-96`（2 倍屏要 80，够），>40 用 `-192`（2 倍屏 128，够）。**不要在两个位置都引用 512 母版**（33 张 × 512 ≈ 6~10 MB，参考券商图标踩过的坑）。

### 4.3 外环（境界色）

- 取值：`--rtone` ← `var(--realm-<realm.group>)`；未确认 / 老服务端无 `realm` → `--realm-mortal`（中性灰）。
- 画法：`box-shadow: 0 0 0 var(--ring) var(--rtone)`，`border-radius: 50%`，`--ring` 按尺寸档给（见 4.2）。
- **禁用 `--red` / `--green`**：那是涨跌语义，拿来当环色会被读成「这人在涨还是跌」（与 `头衔方案.md` §7 配色红线同一条）。
- 环不参与任何排序或提示，纯粹是「一眼看出段位」。

### 4.4 角标（券商）

- 只在 **≥40px** 出现：22px 上放一个 6px 色点只会像脏点。
- 画法：右下角实心圆，填 `broker.color`，1px `var(--panel)` 描边压出边界，`title` 给全名。
- 小尺寸不给图形，靠 `<img title="钟信证券 · 金丹真人">` 的 hover 文案补。
- NPC 也画角标（他们的券商是 `broker.js` 派生的展示标签），与玩家同一套规则。

### 4.5 素材规格

| 项 | 规格 |
|---|---|
| 母版 | 512×512 PNG、透明底、圆形安全区（内容不越 480 直径） |
| 派生 | `avatar-<key>-96.png`（≤40px 用）、`avatar-<key>-192.png`（>40px 用） |
| 路径 | `Client/img/`；母版放 `art/avatars/<key>.png`（**不进站**） |
| 白名单 | `http.js` 里**循环 `config.avatar.catalog`** 注册两档，漏登记 = 404 裂图（老坑） |
| 构图 | 正面半身、脸占画面 ≥55%、最细线 ≥3px @96、纯色或双色底、禁止细密纹理与文字、外轮廓强 |
| 禁止 | 真人照片风格、写实渲染、带水印（参照 `egg-cat` 那批裁水印的旧账） |

#### 4.5.1 构图模板（33 张共用骨架）

所有素材按同一骨架画，识别**不靠细节、靠轮廓**：

| 层 | 规格 | 说明 |
|---|---|---|
| 安全区 | 内容不越 480/512 母版直径 | 外环画在图外（box-shadow），素材不预留 |
| 脸 | 面部直径 ≈ 母版 56%，眼线压画面 45% 线 | 正面、微仰 0°，不侧脸不低头 |
| 肩线 | 底部 22% 处被圆边裁切 | 服饰只露肩部一条，做组内差异 |
| **轮廓锚** | 每张**唯一**识别物，长在头顶/轮廓线上 | 24px 下靠剪影认人的唯一依据（见 §3.2 视觉锚列） |
| 道具 | ≤1 件，贴脸侧、不出安全区 | 只给 40px 档可见的细节，不与锚物抢剪影 |
| 底色 | 纯色无纹理（组底色，§9.3） | 禁渐变、禁花纹 |

轮廓锚选型规则：① 全部**外溢出脸轮廓**（芽/角/耳/雪/卷发），内贴细节（眼镜、围巾）只做辅助；② 锚物占母版宽 ≥12%，否则 24px 时不足 3px；③ 12 张锚物两两剪影不撞（横条 vs 竖条 vs 圆簇 vs 角状）。

### 4.6 裂图降级

`<img onerror>` → 隐藏图片，显示**首字头像**（昵称第一个字，底色 = `--rtone` 淡化 20%）。

理由：榜单里一个破图标比一个字更难看；而且删 key / 漏注册时，行高与列宽不会因此错位（`<img>` 的 `width/height` 已固定，兜底节点同尺寸）。

## 5. 数据结构与解锁判定

### 5.1 schema 11

```sql
-- accounts 新增两列
ALTER TABLE accounts ADD COLUMN avatar TEXT;        -- 玩家自选的头像 key；NULL = 从没选过（用派生默认）
ALTER TABLE accounts ADD COLUMN broker_seen TEXT;   -- 待过的券商 key，逗号分隔（转户不丢；券商组头像的解锁依据）
```

- `SCHEMA_VERSION` 10 → **11**，两条都是纯 `ADD COLUMN`（可空、无默认值），与 v4→v8 那批同款，**在跑的那一局能原地升上来**。
- `avatar` **不与 `nick` 合并**：`nick` 是名字（可改、可重名），`avatar` 是图（key 稳定、不参与任何匹配）。
- `broker_seen` 在 `onboard` 与 `/api/broker/transfer` 两处追加（去重），只增不减。**顺带**给将来「曾用门派」徽记留了口子——现在只服务头像解锁。
- 新库 DDL 直接带这两列；`persist.writeAccount` 加两个字段。

### 5.2 默认脸怎么来（确定性派生）

```js
// avatar.js
const DEFAULT_OF = (account) => BASE[identity.hash('ava:' + account) % BASE.length];
```

- 复用 `identity.hash`（已带 murmur3 的 `fmix32` 雪崩收尾）——**不能**用裸 FNV-1a：NPC 账号 `npc-0001/0002` 相邻，不雪崩会大面积塌进同一个桶（券商分配踩过一模一样的坑，见 `项目知识.md` §3.2 坑 1）。
- 加 `ava:` 前缀是为了**与券商标签的哈希解耦**：直接 `hash(name)` 会让「钟信客户」和「某张脸」系统性地绑在一起，榜上一眼看出规律。
- `NULL` 不写库、不 `touch`：派生是纯函数，玩家一辈子不换脸就一辈子不落这一列。

### 5.3 NPC

- `avatar.of(acc)` 对 `isNPC` **只走派生**，永不读列、永不写列（`persist.writeAccount` 对 NPC 写 `NULL`）——「NPC 逐 tick 标脏」是本项目禁忌。
- NPC **只用基础组**，不戴境界脸、不戴彩蛋脸：给 NPC 戴上「渡劫·雷劫」会让人以为 NPC 也有境界，而 NPC 的 `milestones` 恒为 `NULL`。
- 结果：股东榜 30 行里，玩家有自选脸，NPC 有稳定的派生脸——榜看起来像「一堆人」，不像「一堆占位符」。

### 5.4 解锁判定（服务端唯一权威）

`avatar.stateOf(acc)` 返回 `{key, chosen, unlocked[]}`，三个来源：

| 类型 | 判据 | 取数点 |
|---|---|---|
| `base` | 恒真 | 目录 |
| `broker` | `broker_seen` 含该 key | `accounts.broker_seen` |
| `realm` | `idxOf(milestones.peakEquity)` 的大境界 ≥ 目标 | `realm.js` + `peakEquity` |
| `egg` | `milestones.fired` 含该 id | `accounts.milestones` |

- **前端不做判定**，只渲染服务端给的 `unlock.text`（与 realm 整表同一规矩：写死一份，改配置那天它就静默变成骗人的说明书）。
- 彩蛋关掉（`config.milestones.enabled=false`）或境界关掉（`config.realm.enabled=false`）时，对应组**整组不下发**——否则会出现「永远解不开的锁」（同「彩蛋关掉时不渲染 0.0% 回撤」那条口径）。
- `peakEquity` 缺失（老档、从没结算过）→ 境界组按当前 `realm.group` 兜底；`realm` 也缺失 → 该组不发。

### 5.5 为什么目录进 config 不进表

33 条静态数据放 `config.avatar.catalog`，与 `config.realm.ladder` 同款。不进表的原因：运营改一行要写迁移、每次读要查库、还要处理「表里有一条但没图」。

`require` 时做**启动校验**（配错直接起不来，同 `realm.js` 对 ladder 的处理）：

1. key 唯一、符合 `^[a-z][a-z0-9-]{1,15}$`；
2. 每组非空，组 id 唯一；
3. `broker` 组的 `value` 必须在 `config.brokers.list` 里；
4. `realm` 组的 `value` 必须在 `config.realm.groups` 里；
5. `egg` 组的 `value` 必须在 `config.milestones` 全部 id 里——**漏一个 = 永远解不开的锁，必须在启动时红**。

## 6. 下发与接口

### 6.1 `POST /api/avatar`

```
POST /api/avatar   { "key": "bull" }
→ 200 { ok: true, avatar: { key: "bull", name: "死多头" } }
```

| 情况 | 返回 |
|---|---|
| 缺 key / key 非字符串 | 400 `{ok:false, error:'头像参数不合法'}` |
| key 不在目录里 | 400 `{ok:false, error:'没有这张脸'}` |
| key 未解锁 | 403 `{ok:false, error:'这张脸还不属于你', unlock:{type,text}}` |
| 与当前相同 | 200 直接回（不写库、不 `touch`） |
| 正常 | 写 `accounts.avatar` + `persist.touch(acc)` |

- 鉴权：会话令牌（`Authorization: Bearer`），与 `/api/nick` 同级。
- 限流：走**已有的 `write` 档**（30/分/IP），不新开一档——换脸是低频操作，再加一档只会让 `config.http.rateLimit` 变长。
- 日志：`logger.info` 一行 `头像 user001: bull → bear`（不记图、不记路径）。
- **不需要新表、不需要新的 SSE 帧**：换脸后下一帧 `account.avatar` / 榜单 `ava` 自然就变了。

### 6.2 字段表

| 位置 | 字段 | 形态 | 频率 |
|---|---|---|---|
| 自己 | `account.avatar` | key 字符串 | 每帧（增量帧也有） |
| 排行榜 | `players[].ava` | key 字符串 | 每帧，≤20 行 |
| 股东榜 | `/api/holders` → `rows[].ava` | key 字符串 | 按需（前台 5 秒） |
| 持仓弹窗 | `/api/player/positions` → `ava` | key 字符串 | 按需 |
| 弹幕 | 条目 `ava` | key 字符串 | 仅 `kind:'player'` |
| 头像目录 | `rules.avatars` | 整组 33 行 | **仅首屏 `/api/state` 与 SSE 首帧** |

`rules.avatars` 的形状（与 `rules.realm` 同款）：

```js
{
  enabled: true,
  groups: [
    { id: 'base', label: '基础', hint: '开户即全部解锁', rows: [
      { key: 'bull', name: '死多头', unlock: { type: 'base', text: '' } },
      // ...
    ]},
    { id: 'broker', label: '门派', hint: '进过这家券商即解锁，转户不收回', rows: [
      { key: 'broker-zhongxin', name: '钟信门面',
        unlock: { type: 'broker', value: 'zhongxin', text: '转户到钟信证券后解锁' } },
    ]},
  ]
}
```

`stateFor(token, {lite:true})` 只给 `{enabled}`——33 行 × 文案 ≈ 2.6 KB，每 700ms 发一遍纯浪费（与 38 档境界表同一处理）。

### 6.3 只下发 key，绝不下发路径

客户端自己拼 `/img/avatar-<key>-96.png`。目录的每一行都不带 `src`——一旦配置里能写 URL，白名单就形同虚设（这是所有图片来源里最容易被绕过的一条）。

### 6.4 体积账

| 项 | 大小 |
|---|---|
| 每帧榜单（20 × `"ava":"bull",`） | ≈ 280 B |
| 每帧自己（`account.avatar`） | ≈ 20 B |
| 股东榜 30 行（按需，5 秒一次） | ≈ 420 B |
| `rules.avatars` 首帧一次 | ≈ 2.6 KB |
| 首次加载图片（榜单 20 个不重复 key × 96px ≈ 8 KB） | ≈ 160 KB 一次性 |

可以忽略。**但不要**给 `markets[].trades[]`（逐笔）加 `ava`：那里是券商席位不是人，每帧 30 条 × 10 只股票，纯浪费且视觉会乱（逐笔已经有买席/卖席图标）。

## 7. 客户端落点

### 7.1 六个落点

| 位置 | 尺寸 | 为什么在这儿 |
|---|---|---|
| 顶栏（昵称左侧） | 26px | 让玩家知道「这是我的脸」，也是**唯一入口** |
| 排行榜行 | 22px | 这方案存在的主要理由：重名玩家靠脸区分 |
| 股东榜行 | 18px | 让 30 行看起来像一群股东，不是 30 个字符串 |
| 弹幕（仅玩家） | 18px | 玩家发言本来就是「金色胶囊 + 加粗」，加一张小脸是场内唯一的真人标识 |
| 持仓弹窗头 | 44px | 点「持仓」看别人时的第一眼，也是最大的一处公共展示 |
| 选头像卡 | 64px | 弹层内唯一能看清细节的尺寸 |

**刻意不放**：五档、逐笔、席位榜、券商榜——那些位置的主角是券商，塞玩家头像会让「席位数」和「人数」混在一起；彩蛋横幅——那里是猫的语义。

### 7.2 每帧重建与闪图

排行榜与股东行是 `innerHTML` 整块重写（每 700ms）。头像必须满足：

- `<img>` 固定 `width/height`（= CSS 尺寸），避免重写时行高跳动；
- `decoding="async"`，**不要 `loading="lazy"`**——重写后懒加载会先出空白再补图，看起来就是闪；
- 同一 `src` 命中浏览器内存缓存，实测不闪；若真机（尤其 Safari）出现闪烁，备选方案：每 key 一条 `.ava-<key>` CSS class 走 `background-image`（+33 行 CSS，换零解码）。**先按 `<img>` 实现，闪烁成为实测问题再换**，别提前优化。

### 7.3 CSP：环色走 CSSOM

```js
// app.js —— 设置环色。style.css 里 .ava { box-shadow: 0 0 0 var(--ring) var(--rtone, var(--realm-mortal)); }
el.style.setProperty('--rtone', 'var(--realm-' + (realm && realm.group || 'mortal') + ')');
```

- **不许**在 `innerHTML` 里拼 `style="..."`：CSP 是 `style-src 'self'`，内联样式被拦后节点还在、样式静默作废（本项目真踩过，很难发现）。
- 尺寸与环宽用 class（`.ava.s18` / `.s22` / `.s26` / `.s40` / `.s44` / `.s64`），不用内联尺寸。

### 7.4 选头像弹层

```
┌──────────────── 换一张脸 ──────────── ✕ ┐
│ 基础 · 开户即全部解锁                    │
│ [脸][脸][脸][脸][脸][脸]                 │  桌面 6 列 / ≤860px 4 列
│ [脸][脸][脸][脸][脸][脸]                 │
│ 门派 · 进过这家券商即解锁                │
│ [脸][🔒脸][🔒脸][脸][🔒脸][🔒脸]        │  锁卡：灰 + 锁图标 + 条件文案
│ 境界 · 历史最高境界解锁                  │
│ ...                                     │
│                             [ 关闭 ]     │
└─────────────────────────────────────────┘
```

- **入口只有一个**：顶栏头像（26px）+ 主页名片（P1）。不做二级入口，避免和「吉祥物 / 外观」弹层打架。
- 卡状态三态：`已选`（金环 + 勾）、`可换`（hover 抬 1px）、`锁定`（灰度 + 锁 + 条件文案）。
- 点锁卡：`toast(unlock.text)`，**不发请求**（省一次 403）。服务端仍然会校验——前端拦截只是体验，不是安全边界。
- 换脸成功：卡上加金环、顶栏头像原地刷新、`toast('换脸成功。名字没变，人设变了。')`，弹层**不关**（玩家常常连着试几张）。
- **不打断开户**：开户第二步仍然是「昵称 + 券商」两件事，不加第三步。默认脸已经在了，第一次进主页时给一个金色「新」点即可（§8.1）。

### 7.5 移动端（≤860px）

- 选头像弹层 4 列，卡 56px（图仍取 `-192`）。
- 排行榜头像降到 20px（省 2px 给昵称）；股东榜 18px 不动。
- 顶栏头像保留 26px，但昵称在窄屏本来就只显示 6 个字，正好被头像「占」的那点宽度由昵称截断吸收。

## 8. 文案与演出

### 8.1 首次引导（P0）

开户完成 → 进主页时，若 `avatar` 为 `NULL`（从没主动选过）：

- 顶栏头像右上角一个金色小点（`.has-new::after`，与「游戏规则」同一个写法）；
- 一条 toast：`给你配了张脸：韭菜本菜。不合眼缘？点右上角换。`
- 点开弹层即清掉小点（写 `gushen_ava_seen`，只提示一次）。

**不做强弹窗**：开户已经有一套四格漫画，再加一个全屏选脸会让人想关掉页面。

### 8.2 换脸动效（P0）

- 头像原地翻牌：`transform: rotateY(180deg)` 300ms，中点换 `src`（CSS 变量 + `transitionend` 兜底定时器）。
- `prefers-reduced-motion: reduce` → 直接换图，不做位移与旋转。

### 8.3 解锁提示（P1）

借彩蛋的事件通道发一条 L1（`kind:'avatar'`，复用 `milestones.emitTransient` 的滚动队列与 `seq`），文案：

- 境界：`{境界}解锁：{脸}。钱到位了，脸也跟上。`
- 彩蛋：`天台初体验 → 安全帽。亏出来的，戴着吧。`
- 券商：`钟信门面到手。转户也带得走。`

**不新增 SSE 段、不新增 ack 协议**——客户端的水位（`gushen_event_seq`）已经能处理。

### 8.4 基调

头像文案只有 8 句左右，**不接 `milestones.tone` 三档**（为一个 8 句的表引入三套文案是过度设计）。语气统一走 `savage`：短、损、不带说教。

## 9. 美术生产

### 9.1 先做 12 张，验证一条硬标准

批量的前提是「24px 可读」这条标准被验证过。所以：

1. **P0 先出基础组 12 张**（+ 券商组 6 张可并行）；
2. 缩到 24px 贴在榜单行里看——认不出是谁就重画，不要靠「放大看挺好看」过关；
3. 过了这条线，境界组 / 彩蛋组按同一套构图批量做（它们的细节更多，反而更容易在小尺寸糊）。

### 9.2 流程

```
AI 生成（正面半身、统一 prompt 尾缀）
  → 抠图去底（透明 PNG）
  → 512 裁切（圆形安全区，脸占 ≥55%）
  → art/avatars/build_web_assets.py（Pillow，参照 art/onboarding-comic 的做法）
  → Client/img/avatar-<key>-96.png / -192.png
  → http.js 循环注册（config.avatar.catalog）
```

### 9.3 一致性锚

| 组 | 底色 | 作用 |
|---|---|---|
| 基础 | 米灰纸感 | 12 张放一起像一套，不像 12 个画师 |
| 券商 | 各家门派色（`broker.color` 淡化） | 一眼看出门派，与角标同色 |
| 境界 | 各境界 `--realm-*` 淡化 | 与环同色，脸和环是一套 |
| 彩蛋 | 金 / 黑 | 稀有度感 |

| 方案 | 否决理由 |
|---|---|

| 头像进排序 / 加特权 | 与「观测层零特权」红线直接冲突 |

## 12. 风险与取舍

| 风险 | 处理 |
|---|---|
| **和吉祥物认知混淆** | 入口分家（头像点自己 / 吉祥物在「外观」）、文案分家（「脸」vs「立绘」）、文档分家（本节 2.1 写死） |
| 榜单每帧重建导致闪图 | 固定宽高 + `decoding=async` + 不加 lazy；实测有问题再换 CSS class 背景图（§7.2） |
| 24px 下 AI 图糊成一团 | 构图硬标准 + 先做 12 张验证（§9.1） |
| 33 张风格不统一 | 分组底色 + 统一 prompt 尾缀 + 一次只出一组 |
| 删 key 导致老档裂图 | 未知 key 回落默认 + 首字兜底（§4.6）；key 永不复用 |
| 头像被当成「身份凭据」 | 无任何鉴权含义：改头像不影响令牌、账号、订单；`/api/avatar` 只认 token |
| 玩家用头像+昵称冒充他人 | 榜单一律以 `account` 认人；同名同脸也只能「看起来像」，点「持仓」查的是账号 |
| 素材体积 | 两档派生 + 长缓存（`public, max-age=86400`）+ 只渲染可见行 |

**取舍一句话**：这套系统只做「可辨识」，不做「可表达」。想表达个性去改昵称、选吉祥物；头像负责让别人一眼认出你，别的一概不管。
