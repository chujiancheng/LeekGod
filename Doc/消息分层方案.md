# 我是股神 · 消息分层（信息不对称）设计方案

> 状态：**已实现 MVP + v2 核心**（2026-10-16）。落地代码见 `Server/src/news.js`（`visibleFor` 与三个读取口的 `viewer` 参数）、
> `npc.js`（`applyTags` 派生的情报等级）、`game.js`（tape/SSE 过滤与异动提示）、`config.news.lead*`。
> v3（合规层 / 假消息 / 内幕购买渠道）**未实现**，`config.news.compliance.enabled` 默认 `false`；
> v2 清单里的 **§7.3「延迟回看」也未落地**（席位榜/龙虎榜没有「公开 N 秒后才可查」的时间门禁），**2026-10-16 用户拍板先不做**。
> 落地后对本文有几处修正，见文末变更记录与 §13（§13.1 两处实现偏差、§13.3 两处口径澄清）。
> 目标：把现在"所有人同一 tick 同时知道"的消息，改成像真实市场一样——**有人先拿到消息，偷偷买进或出货，股价先动、消息后到**。

---

## 0. 一句话结论 + 决策摘要

给消息加一层「**时间分层 + 可见性分级**」：让 **消息诞生（t0）≠ 消息公开（t2）**，中间插入一段 **泄露期**。
只有情报等级够高的参与者（机构 NPC，v2 起加付费情报玩家）在这段窗口里就能读到消息并据此提前动手；公众（散户 NPC + 普通玩家）要等到 t2 公开才知道，届时只看到「股价莫名其妙先动了一波」。
**不新增任何交易机制**——提前量的变现全靠现有的 `fvDrift` / `sentiment` → NPC 报价 → 撮合这条老路径自然发生。

**已拍板的四条主决策（详见 §12）：**

| # | 决策 |
|---|---|
| **D1** | **提前量分期上**：MVP **只给 NPC 机构**（玩家侧零改动）→ v2 给玩家情报渠道 → v3 上合规层与假消息 |
| **D2** | **lead 上限 6s**；大盘宏观消息（`scope=全体`）**lead 恒为 0**；个股消息按 scope 折扣 |
| **D3** | **合规惩罚与假消息都做，但只跟 v3 一起上**（没有玩家提前量时合规层无意义），MVP/v2 全关 |
| **D4** | **与券商方案口径统一为「相对公开时刻 t2 提前」**，且按声誉星级 **1/4 强度递进**（招伤 4★ 才满额 3s）→ 已回改 `券商方案.md` §3.3 / §4 / §6 |

## 1. 现状诊断：为什么现在人人同时知道

三条代码事实（当前实现）：

1. `game.js:452` `news.maybeEmit(now, bias, {phaseKey, untilFloor})` 在**同一 tick 的逐股 NPC 循环（`game.js:460`）之前**执行。也就是说，消息诞生的那一 tick，10 只股票的 NPC 立刻在 `step()` 里读到它。
2. 读取端**零时间门禁**：
   - `npc.js:342` `fv *= 1 + this.news.fvDrift(now, this.stock.id)` —— 公允价值直接被消息推。
   - `npc.js:730 / 736` `sentimentByScope(now, stockId)` / `sentiment(scope, now, stockId)` —— 情绪扰动。
   - `news.js:833 / 851 / 873` 三个读取函数只按 `until > now`（是否还有效）过滤，**不看"何时公开"**——因为**根本没有这个概念**。
3. `game.js:929-930` `state.news = this.news.tapeSnapshot(50)` + `lastNews`，在**同一 tick 末**经 `http.js:190 broadcastAll()` 用 SSE 推给所有玩家。

**结论**：消息 = 一次无差别的全局广播。**诞生 tick = 全体 NPC 生效 tick = 所有玩家看到 tick**，三者完全重合。`news` 对象里只有 `t`（诞生）和 `until`（过期），**没有"公开时刻"这个字段**——所以信息不对称在当前架构下无处安放。

唯一沾边的东西是 `券商方案.md` §3.3 的"招伤证券 -3s 消息提前量"，但它：① 是设计稿未实现；② 只覆盖玩家、不覆盖 NPC；③ 语义模糊（是"我早 3s"还是"别人晚 3s"）。本方案把它收编为 L2 并定死口径（见 §12 D4）。

## 2. 设计目标

- **G1 信息不对称一等公民**：让"同一时刻不同人知道的不一样"成为机制，而不是彩蛋。
- **G2 提前量能变现、且是零和**：早知道的人真的能提前建仓/出货，这笔钱从"后知道的人"（公众跟风盘）身上赚，不是系统白送。
- **G3 有迹可循 + 有代价**：普通玩家能从盘口读到异动痕迹（不是纯黑箱）；越级使用情报要担监管风险。

## 3. 核心模型：消息生命周期三段式

```
t0 诞生 ─────── t1 内幕可见 ─────── t2 公开 ─────── until 过期
   │  孕育期    │      泄露期       │      公开期      │
   └─ 只有系统 ─┴─ 少数人偷偷动手 ─┴─ 全体跟风 ───────┘
```

| 阶段 | 区间 | 谁能感知 | 市场表现 | tape / 客户端 |
|---|---|---|---|---|
| **孕育** | `[t0, t1)` | 仅系统（可选最高级内幕 L0） | 无 | 完全不可见 |
| **泄露** | `[t1, t2)` | 内幕层 + 机构层 + 情报玩家 | **股价先动、盘口异动、但没消息** | **不可见（关键）** |
| **公开** | `[t2, until)` | 全体（含散户/游资/大户 NPC + 普通玩家） | 公众跟风、二次跳 | 可见 + SSE 广播 |

**这一张表就是本方案的全部。** 泄露期的"不可见"是三段式的灵魂：消息此刻**已经在驱动机构 NPC 的公允价与报价**，但**还没有进公共 tape、也没有经 SSE 广播**，所以玩家只看到价格异动、看不到原因。

## 4. 情报等级：谁能早看到

| 等级 | 名称 | 对应代码实体 | 可见起点 | 定稿提前量 |
|---|---|---|---|---|
| **L0** | 内幕 insider | 机构 NPC 里再抽 `insiderFrac = 0.1` 的一小撮（"消息庄家"，10 股共 10 个） | `t0` 起 | **6s** |
| **L1** | 机构 inst | 现有 `type === 'inst'` 的机构 NPC（10 股 ×10 = 100 个，天然"聪明钱"） | `t1` | **4s** |
| **L2** | 情报玩家 vip | 券商天赋（招伤）/ 情报订阅 / 临时内幕（v2 起） | `t1`（稍短） | **3s** |
| **L3** | 公众 public | 散户 / 游资 / 大户 NPC + 普通玩家（**默认，不传 viewer**） | `t2` | **0** |

提前量**按消息 scope 折扣**（`leadByScope`，见 §10.1）：

| scope | 折扣 | 理由 |
|---|---|---|
| `全体`（大盘宏观） | **0** | 政策/宏观没有内幕可言，一律 t0 = t2 **完全维持现状** |
| `机构` | 1.0 | 研报/调研/大宗本来就是机构先知道 |
| `散户` | 0.5 | 股吧小道本来就是"传言"，机构消息面广故能稍早，但折扣 |

要点：

- **L1 直接复用现成机构**（MVP 的全部内容）：机构本来就在做 `publicNewsFade`（公开利好出货、公开利空吸筹，`npc.js:727-733`）。给它提前量之后，这条"对倒"逻辑升级成 **"利好正式公开前先抢筹拉高 → 公开时散户跟风 → 机构反手出货"**，即教科书式的「利好出尽是利空」，**与现有机制同源，不打架**。
- **L0 的抽取方式学 `券商方案.md §11.4.1`**：从账户名做确定性哈希派生（`accName` 天然唯一：`大米·机构1`），**不落盘、不占存档版本号、不触发逐 tick 标脏**。重启后同一 NPC 仍是同一身份。
- **提前量向下对齐 tick 边界**（`tickIntervalMs = 700ms`），且 **最小生效 lead = 2 tick（1.4s）**；折算后不足 2 tick 的一律按 0 处理——避免"名义上有提前量、实际完全看不见"。

## 5. 读取端口改造：最小侵入，守住项目纪律

项目纪律是「**只调制交易行为、绝不碰公允价值与噪声公式**」。本方案**完全遵守**——不新增任何交易机制，只给已有的读取口加一个"观察者"参数：

```js
// news.js —— 与现有 applies() 并列新增
static visibleFor(n, viewer, now) {
  if (now >= n.publicAt) return true;              // 已公开：人人可见
  const tier = (viewer && viewer.tier) || 'public';
  const lead = (n.lead && n.lead[tier]) || 0;      // 该等级相对 publicAt 的提前量
  return now >= n.publicAt - lead;
}

// 三个读取口加可选 viewer（不传 = public，行为与现状逐位一致）
fvDrift(now, stockId = null, viewer = null)          { ... if (!NewsSystem.visibleFor(n, viewer, now)) continue; ... }
sentiment(scope, now, stockId = null, viewer = null) { ... 同上 ... }
sentimentByScope(now, stockId = null, viewer = null) { ... 同上 ... }
```

**关键点：`viewer` 默认 = 公众。** 不传参的老调用（含全部现有测试）行为**逐位不变**，`npm test` 老用例不会红。这是本改造能在现有架构里低成本落地的前提。

配套改动：

| 位置 | 改动 |
|---|---|
| `news.js maybeEmit` | 生成 news 时补齐 `publicAt = t`、`lead = { insider, inst, vip }`（按 scope 折扣后再对齐 tick）；`tape` 只收 `publicAt ≤ now` 的（或 tape 全收、快照时过滤）；`active` 仍全量（供 NPC 读取）；`until` 语义不变（仍从 t 起算） |
| `npc.js step / updateBias` | 传自己的 tier：`inst → 'inst'`、L0 抽中者 → `'insider'`、其余 → 不传（public）。**例外**：`updateForce` 里读「散户盘情绪」那一处（力场投票用 `sentiment('散户', …)`）**刻意不传 viewer**，走公众视角——机构要判断的是"跟风盘在追什么"，那是公众看到的情绪；见 §13.3 |
| `game.js` | 逐股循环里给 NPC 传 tier；`stateFor` 的 `news` / `lastNews` 按 `publicAt ≤ now` 过滤 |
| `http.js` | **无需改**：SSE 只下发 `state`，过滤已在上一步完成 |
| `config.js` | 新增 `news.lead` / `news.leadByScope` / `news.insiderFrac` / `news.irregularHint` / `news.compliance` |
| `persist.js` | **实际无需改**：消息磁带**从不落盘**（`persist.js` 存的是成交流水 tape、行情快照、账户与订单，**消息系统不在其中**；每次启动 `new NewsSystem()` 重建为空）→ 根本没有 `publicAt` / `lead` 字段要带。§13.1 #3 那个「老档无字段」兼容口，实际服务的是**测试里直塞 `news.active` 的裸消息**，不是老存档；见 §13.3 |
| `indexfeed.js`（指数） | **无需改**：指数由成分股价格算出，成分股在泄露期先动 → 指数自然先动 |
| `Client` | v2 起：异动提示 UI；v3 起：情报等级显示、合规预警 |

## 6. 剧本：一笔"偷偷买进"是怎么发生的

以**利好**为例，把机制讲成画面：

1. **t0** 系统生成利好。个股公告/机构调研类 → L0 内幕提前 6s；大盘宏观类 lead = 0（无提前）。
2. **t1** 机构 NPC（L1，提前 4s）读到 → 其 `fv` 上移 → 开始在卖盘**悄悄扫货、抬高买价**。此刻 **tape 里没有这条消息，SSE 也不广播** → 玩家只看到"XX 莫名放量上攻，盘口单边变薄"。
3. **t1 窗口内**（v2 起）：情报玩家（L2，招伤 -3s）也看到了 → 跟着偷买；普通玩家若读懂"逐笔大单 + 五档单边 + 量能脉冲"，可自行跟上（这是留给大家的公平观察窗口）。
4. **t2** 消息公开 → 广播 → 散户/游资/大户 NPC 追涨 → **第二次跳**（公众反应）。
5. **t2 之后**：机构借助现有 `publicNewsFade` 在公众跟风中**反手出货** → 见顶回落。

利空完全对称（机构提前砸盘/借券 → 公开后散户恐慌 → 机构吸筹）。

→ 全程**没有一行新交易代码**：机构"提前"的动作就是把它现在 t2 才有的 `fvDrift`/`sentiment` 读取，提前到 t1 生效而已。

## 7. 让公众"看得见痕迹"（公平窗口）

"偷偷"不能是纯黑箱，否则普通玩家只剩被割。三条披露，**分期上**：

1. **保留并强化微观结构可读性**（已有，MVP 即生效、零代码）：逐笔大单、五档深度单边坍塌、分时量能脉冲，本身就会在泄露期暴露机构动作。这是最重要的公平窗口。
2. **异动提示**（`irregularHint`，**v2 开，MVP 关**）：个股在泄露期出现异动时，客户端给一条**模糊提示**——「XX 出现大额资金异动」，**不点方向、不点原因、不说是谁**。
   > MVP 刻意关掉：让"读盘口"成为玩家真本事，也保住"零玩家侧改动"这个最低风险前提。MVP 阶段改用一个**服务端调试指标**（泄露期成交额 / 价格漂移，落日志不落盘）来验证机制确实在起作用。
3. **延迟回看**（**v2 开**，承接龙虎榜玩法）：公开 N 秒后才可查席位/资金流，"事后才知道是谁在动"。

## 8. 玩家侧：情报渠道 + 合规代价（v2 / v3）

### 8.1 怎么"买到"提前量（v2）

| 渠道 | 提前量 | 来源 |
|---|---|---|
| 普通券商 | 0（L3） | 默认 |
| 招伤证券天赋 | 0.75~3s（L2，**按声誉星级 1/4 递进**） | 收编 `券商方案.md §3.3`，口径见 §12 D4 |
| 情报订阅（花钱买时间） | 2s（L2） | 每日/一次性购买的"Level-2 消息源" |
| 内幕交易（灰色，v3） | 6s（L0） | 与"消息庄家"NPC 私下接触，临时获得 |

> **星级递进**：承接 `券商方案.md §9 D7`「每升一级只解锁 1/4 特权强度」——招伤 1★ 只给 0.75s、2★ 1.5s、3★ 2.25s、**4★ 才满额 3s**，5★ 额外给"标的方向"（同额提前量 + 提前量内可见方向，不给强度）。

### 8.2 代价：合规层（v3，`compliance.enabled`）

泄露期针对该消息标的的成交额累计超阈值 → 触发「监管问询 / 立案调查」：

- **罚没**该段盈利的一部分（`penaltyRate`，定稿 0.4 = 40%）；
- **情报等级降级 / 冷静期** `cooldownMs`（定稿 60s，回到 L3）；
- **声誉星级扣分**（承接 `券商方案.md §5.4`）。

→ 把"偷偷提前"从**无脑优势**变成**高风险高收益**，与游戏既有"风险换收益"的调性一致。

## 9. 消息本体的分级（不是所有消息都能提前）

| 消息类型（对应现有池） | 谁能提前 | 有效 lead（L1 机构视角） |
|---|---|---|
| 个股公告 / 业绩 / 重组（`ANNOUNCE_TEMPLATES`，盘后，scope=机构） | 内部人 → 机构 | 6s / 4s |
| 机构研报 / 调研 / 大宗（scope=机构） | 机构 → 大户 | 4s |
| 散户情绪 / 小道消息（scope=散户） | 基本无（本就是"传言"） | 2s（×0.5） |
| 大盘宏观（scope=全体） | **无** | **0（维持现状）** |

**进阶：假消息 / 反向陷阱（v3）。** 泄露期放出的可能是庄家**故意**散布的假利好，用来吸引跟风盘出货。让"提前知道"不总等于赚钱，同时天然抑制"内幕必胜"。

## 10. 定稿数值

### 10.1 config 新增

```js
news: {
  // ... 现有键一律不动 ...
  lead: {
    insiderMs: 6000,  // L0 内幕
    instMs:    4000,  // L1 机构（MVP 的全部内容）
    vipMs:     3000,  // L2 情报玩家（满额 = 券商方案招伤 -3s）
    publicMs:  0,     // L3 公众
  },
  // 按 scope 折扣 lead：宏观无内幕（恒 0）、公告最好提前、散户消息本就传言
  leadByScope: { 全体: 0, 机构: 1.0, 散户: 0.5 },
  minLeadMs: 1400,      // 最小生效提前量（2 tick）；折算后不足此值按 0 处理
  insiderFrac: 0.1,     // 机构里再抽多少比例当 L0（10 股 → 每股 1 个）
  irregularHint: false, // §7.2 异动提示：MVP 关，v2 开
  compliance: {         // §8.2 合规层：MVP/v2 关，v3 开
    enabled: false,
    penaltyRate: 0.4,
    cooldownMs: 60000,
  },
}
```

**量级核对**：`tickIntervalMs = 700ms`，所以 4~6s ≈ **6~9 tick**——足够机构完成几轮重报价与吃单；而消息间隔 20~60s、作用期 60s，提前量最多占 **10%**，不会让"提前"变成碾压性的长期优势。

### 10.2 风险与取舍（R3 已闭环）

| 编号 | 风险 | 处置 |
|---|---|---|
| **R1** | 提前量过大 → 机构永远赢、玩家没法玩 | lead 上限 6s（占作用期 10%）；`全体` scope 恒 0；`minLeadMs` 下限；§7 痕迹披露；v3 假消息 |
| **R2** | 读路径 +viewer，接口面扩大、易出回归 | **默认参数 = 公众、零行为变化**；老测试不红；§10.3 新增测试守门 |
| **R3** ✅ | ~~与 `券商方案.md` 的"消息提前量"口径冲突~~ | **已闭环**：统一为「相对公开时刻 t2 提前」，招伤 -3s = L2 `vipMs 3000` 满额、按星级 1/4 递进；`券商方案.md` §3.3 / §4 / §6 已回改并追加变更记录 |
| **R4** | 与 `untilFloor`（盘后消息活到次日竞价）叠加，跨段提前量不好算 | leads 用**绝对 ms**、跨段不特殊处理；`until` 仍从 t 起算，语义不变 |
| **R5** | L0 身份若落盘会污染 NPC"不逐 tick 标脏"的现状 | 学 `券商方案.md §11.4.1`：账户名哈希派生，**不落盘** |

### 10.3 必须新增的测试（守门）

1. 不传 viewer 时，`fvDrift/sentiment/sentimentByScope` 与现状**逐位一致**（回归红线）。
2. L1 在 `t2 - instMs` 起可见，之前不可见；折算后 < `minLeadMs` 时 lead 视为 0。
3. `scope=全体` 的消息 `lead` 恒 0（`publicAt === t`），行为与现状一致。
4. `tapeSnapshot` / `stateFor.news` / `lastNews` **不含** `publicAt > now` 的消息（泄露期不外泄）。
5. 老存档（无 `publicAt/lead` 字段）加载后行为与现状一致。

## 11. 分期（定稿）

| 期 | 范围 | 玩家侧改动 | 风险 |
|---|---|---|---|
| **MVP** | **只做 L1 机构提前**（NPC 内部信息不对称）+ L0 内幕抽签 + tape/SSE 过滤 | **零改动**（异动提示也关） | 最低。先产出"股价先行、消息后到"的观感，靠调试指标验证 |
| **v2** | 玩家情报渠道（券商映射 L2 + 星级递进 + 情报订阅）+ 异动提示 + 延迟回看 | 中等 | 中。需定 UI 与平衡 |
| **v3** | 合规层（罚没/降级/扣星）+ 假消息 + L0 内幕渠道 | 大 | 高。复杂度推高一档 |

**MVP 的验收口径**：不传 viewer 的老路径零变化 + 泄露期 tape/SSE 无泄漏 + 日志能证明"消息公开前 N 秒价格已开始漂移"。

## 12. 关键决策（已拍板，不再重新开题）

**D1 提前量分期上：MVP 只给 NPC 机构，玩家侧零改动。**
- 理由：MVP 的价值是**先验证"信息不对称"这个观感是否成立且不破坏现有定价**。玩家侧一动，就要连带做 UI、情报渠道定价、合规层，风险与工作量同时翻倍，且会掩盖机制本身的问题。
- 玩家在 MVP 阶段不是没事干——§7.1 的盘口痕迹（逐笔大单 / 五档单边 / 量能脉冲）就是给他们的"免费情报"，读到就是本事。
- 落地：MVP 只改 `news.js` + `npc.js` + `game.js` + `config.js` + `persist.js`，`http.js` / `Client` 不改。

**D2 lead 上限 6s；大盘宏观（`scope=全体`）lead 恒为 0；个股按 scope 折扣。**
- 上限 6s：占消息作用期（60s）的 10%、占消息间隔（20~60s）最多 30%，能看见但不足以碾压。
- `全体` 恒 0：政策/宏观**没有内幕可言**，强给提前量既不真实、又会让指数在泄露期整体漂移（10 只一起动，观感像"大盘抽风"）。设 0 后大盘消息**完全维持现状**，把风险面收窄到个股。
- `散户` scope ×0.5：散户消息本就是传言，机构消息面广故能稍早，但不宜与机构消息同等待遇。
- 附加工程约束：**向下对齐 tick（700ms）**、**最小生效 1.4s（2 tick）**，避免"名义有提前量、实际看不见"。

**D3 合规惩罚与假消息都做，但只随 v3 一起上。**
- 合规层的前提是"玩家能提前"，MVP/v2 玩家要么没有提前量（MVP）、要么是合法渠道（v2 券商天赋/订阅）——此时罚玩家不合逻辑。所以 `compliance.enabled` 默认 `false`，v3 与"内幕渠道"同批开。
- 假消息同理：它是用来抑制"内幕必胜"的，得先有玩家侧内幕渠道才成立。
- 定稿参数：`penaltyRate 0.4`、`cooldownMs 60000`（冷静期回 L3）。

**D4 与券商方案口径统一为「相对公开时刻 t2 提前」，并按声誉星级 1/4 递进。**
- 原 `券商方案.md §6` 写"按券商**分档延迟**"，与本方案（提前）**方向相反**，实现时会互相吃掉——必须定死一种。
- 选"提前"而非"延迟"：延迟语义要么让非招伤客户看到旧世界（等于给所有人加晚点，无意义），要么要在广播层给每档连接维护不同的消息队列（SSE 是同一份 `state`，改造成本高）。**提前**只需在读路径加 viewer 过滤，且天然与 NPC 侧共用同一套 `visibleFor`。
- 招伤 `-3s` = L2 `vipMs 3000` 的**满额值**；承接 `券商方案.md §9 D7`「每级只解锁 1/4 强度」→ 1★ 0.75s / 2★ 1.5s / 3★ 2.25s / **4★ 才满 3s**。
- 已同步回改 `券商方案.md`：§3.3（强项措辞）、§4（表头与招伤行 + config 键说明）、§6（对接点那一行），并在其 §12 变更记录追加一条。

## 13. 实现说明（2026-10-16）

### 13.1 落地与本文的两处偏差

1. **`publicAt` 不是 `t`，而是 `t + leadMax`**（本文 §5 的表格里写的是「生成 news 时补齐 `publicAt = t`」）。
   照原文写会让三段式**完全不成立**：如果公开时刻就是诞生时刻，那么 `visibleFor` 对任何等级在 `t` 时刻都已返回可见——
   不存在"部分人能看到、公众看不到"的窗口，机制是死的。改成 `publicAt = t + max(lead)` 之后：
   孕育期 = `[t, publicAt − lead_inst)`、泄露期 = `[.., publicAt)`、公开期 = `[publicAt, until)`，
   与 §3 那张表**逐格对上**。`scope=全体` 的 lead 全为 0 → `publicAt = t`，宏观消息完全维持现状 ✓。
2. **提前量只做下限夹取，不做 tick 向下对齐**（本文 §4 要求"向下对齐 tick 边界 + 最小生效 2 tick"）。
   两者一起用会把**满额 3s 砍成 2.8s**（3000 / 700 = 4.28 → 4 tick），而"满额 3s"是券商方案里招伤的招牌数字，
   星级递进 0.75 / 1.5 / 2.25 / 3.0 会整体错位。真正要防的只是"名义有提前量、实际一个 tick 都看不见"——
   那一条由 `minLeadMs` 兜住，于是 1★ 的 0.75s 被抬到 1400ms（可观测）。
3. §10.3 的回归红线「不传 viewer 时与现状**逐位一致**」按下面这条落实（原表述在 `publicAt = t + lead` 下不可能字面成立）：
   **没有 `publicAt` 字段的消息视为立即可见**。`visibleFor` 对裸消息/老数据返回 `true`，
   于是老调用（含既有测试直接塞 `news.active` 的写法）行为不变；同时函数签名加的是**可选**参数，老调用不炸。
   > 注：消息磁带**不落盘**，所以这里的「老数据」在真实运行中并不存在，兼容对象是测试里直塞的裸消息——详见 §13.3 #1。

### 13.2 其余落地细节

- **L0 内幕**按"机构账户里哈希取前 k 名"（k = round(机构数 × insiderFrac)，至少 1）抽取，而不是"哈希 < frac"：
  后者会让某些股票抽不到内幕，那几个池的公允价值晚 2 秒才动，十只股票的提前量参差不齐。池级 `poolViewer`
  取全池最早能看见的那一级（常态是 `insider`），公允价值推力按它走——这就是"股价先动"的来源。
- **L2（情报玩家）落在券商上**：招伤天赋 `vipMs 3000`，按声誉星级 1/4 递进（1★ 1400ms → 4★ 3000ms）。
  未满 4★ 时提前拿到的消息**遮蔽方向**（`masked`，文案变成"【某股】出现未公开信息，方向待确认"）——
  §8.1 的"4★ 给满额提前量但不给强度、5★ 才给标的方向"就落在 `newsVipVisible`。
- **泄露期抽样只统计连续竞价段**：异动提示（`irregularHint`，默认**开**）给公众一条模糊提示，
  但不点方向/原因/是谁；`irregularHintMinMs > 0` 时可以只在泄露期尾部提示。
- **可观测性**：`news.noteLeakDrift` 在每条消息公开时记一次"泄露期内的价格漂移"并**只落日志不落盘**
  （§7.2 的 MVP 验收口径：让"消息公开前 N 秒价格已开始漂移"可被验证，而不是靠感觉）。
- **v3 未做**：合规层（罚没/降级/扣星）、假消息、内幕购买渠道。配置键已备好，`compliance.enabled` 默认 `false`。

### 13.3 两处口径澄清（复核后补记）

方案 §5 的改动清单里有两行写得比实际「多」了，落地时并未按字面执行，这里把真实口径定死：

1. **`persist.js` 那一行是空操作——消息磁带从来不落盘。**
   `persist.js` 存的是成交流水 tape、行情快照、账户与订单，**消息系统不在其中**：每次启动 `game.js` 都 `new NewsSystem(this.stocks)` 重建，`tape` / `active` 从空开始。
   所以「news 存档带上新字段」既无字段可带、也无必要；反过来 **`publicAt` / `lead` 永远不会从存档里读出来**，不必为它们预留升级路径。
   连带影响：§13.1 #3 那条「老档无 `publicAt` → 视为立即可见」的兼容口，**实际服务对象不是老存档**（不存在这种存档），而是**测试里直接往 `news.active` 塞的裸消息**（如 `game.test.js` 的既有写法）。这条兼容本身仍有价值——它是「引入本机制之前的行为」的等价表达式，也是 `visibleFor` 对畸形输入不炸的兜底——但别把它理解成"老库升级需要"。
2. **`npc.js` 传给读消息口的 tier 是两处，不是三处。**
   `updateBias` 里的 `sentimentByScope(now, stockId, n.newsViewer)` 与 `sentiment(scope, now, stockId, n.newsViewer)` 确实各带自己的 tier，公允价值侧走池级 `poolViewer`；
   但 `updateForce` 里读散户盘情绪那处（力场投票用）**刻意不传 viewer**——机构要判断的是「跟风盘在追什么」，而跟风盘看到的就是公众视角的情绪，给它 L1 的提前量反而是错的。
   所以 §5 那句「传自己的 tier」应理解为「**判断自己怎么交易**时传 tier」，而不是「所有读消息的地方都传」。
